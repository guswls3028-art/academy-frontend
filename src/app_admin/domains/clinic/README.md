# 관리자 클리닉 일정

관리자가 `/workspace/clinic`에서 클리닉 세션을 생성·복사·수정하고 학생 예약을
운영하는 도메인입니다. 같은 날짜의 여러 시간대 예약 가능 여부는 서버의 세션별
정책을 그대로 편집하며, 프론트가 tenant나 학생별 예외를 추정하지 않습니다.

전체 미통과 작업대와 운영 콘솔 학생 작업대의 수동 통과는 공통
`useResolveClinicLink`를 사용하며 `/progress/clinic-links/:id/resolve/` 성공
응답에 포함된 해결 시각·유형·근거를 해당 링크의 화면 캐시에 즉시 반영한다.
전체 대상/예약 목록 재조회를 기다리느라 통과 완료 안내와 다음 작업을 막지 않으며,
목록은 백그라운드에서 다시 읽는다. 저장 실패는 기존 항목을 유지하고 오류를
표시한다. 서버 응답 전에는 통과로 추정하지 않으며 점수·최종 판정을 새로 계산하지
않는다. 새로고침의 정본은 계속 서버 목록이며 테넌트·역할 권한은 기존 API가 소유한다.
운영 콘솔은 저장 완료 후 남은 다음 항목을 바로 처리할 수 있다. 백그라운드 조회가
실패하면 목록 조회 오류·재시도를 표시하며 이미 완료한 저장을 실패로 안내하지 않는다.
성공·저장 실패 알림은 공통 mutation이 한 번만 소유한다. 작업대의 항목 전환 영역은
390px의 여러 행에서도 높이가 압축되지 않아 아래 처리 영역과 겹치지 않는다.
`clinic-remediation-missing.mock.spec.ts`는 PC/390px에서 실제 항목 클릭, 저장 실패와
재시도, 지연·실패한 목록 조회, 다음 항목 처리 가능 상태와 reload를 검증한다.
오류·성공 알림은 열린 작업대 위의 실제 노출을 아홉 지점 hit-test로 확인하고,
2초 안내가 사라지기 전 즉시 캡처한다. DOM 표시 여부만으로 알림 노출을 판정하지 않는다.
전체 미통과의 **해결 완료 포함**은 URL에 보존되어 새로고침 후에도 완료 항목을
다시 찾을 수 있다. 직접 수동 통과한 항목은 학생 작업대·점수 일괄입력에서
**수동 통과 취소**로 학생과 항목을 확인한 뒤 미해소로 되돌린다. 시험·과제 자동 합격,
면제·이월, 교사 오답 확인으로 완료한 항목에는 이 동작을 제공하지 않는다.
`POST /progress/clinic-links/:id/unresolve/`에 화면에서 확인한 `resolved_at`을
`expected_resolved_at`으로 그대로 전달한다. 서버가 교직원·tenant 권한과 잠금 안의
수동 처리 시각·유형을 확인한다. 다른 처리로 바뀐 409는 목록을 다시 읽고 재확인을
안내하며, 일시 오류는 확인창과 선택 항목을 유지해 재시도할 수 있다. 저장 중에는
중복 요청·창 닫기를 막으며, 성공 응답으로 화면을 갱신하고 목록을 다시 읽는다.
원래 점수와 이전 처리 근거·이력은 보존한다. backend 정책은
`backend/docs/domain/clinic-booking.md`의 학생별 통과·면제와 진도 갱신을 따른다.

공식 격리 개발 검사에 포함된 `student-clinic-required-cancel-realuse.spec.ts`는
기존 qa-* 실패 항목과 실제 staff 계정으로 전체 미통과·운영 콘솔 수동 통과,
완료 목록의 UI 되돌리기, 학생 시험 결과의 클리닉 예약 안내 노출·해소를
PC/390px와 reload로 검사한다. qa-ymath는 오답 확인 표시 정책을 따르므로 별도 교사
오답 확인 상태는 미완료로 유지한다. 통과와 되돌리기 모두 원래 시험 점수 20점을
보존하고 기존 예약·취소 검증을 계속한다. route-mock은 503 재시도, 409 재확인,
저장 중 중복 클릭 방지, 자동 합격·교사 확인의 취소 미노출, 성공 후 reload를
PC/390px에서 검사한다. 이 명세는 실제 격리 실행의 통과 영수증을 대신하지 않는다.

## 새 일정의 개설 방식 선택

새 일정 만들기는 상세 폼보다 먼저 두 카드만 보여 줍니다.

- **한 타임 예약 · 시간지정 클리닉**: 17:00–18:00처럼 정해진 타임 전체를
  예약하는 기존 방식입니다.
- **등원·하원 선택 · 자유지정 클리닉**: 15:00–22:00 운영 범위를 열고 학생이
  그 안에서 16:00–19:00처럼 실제 시간을 고르는 독서실형 방식입니다.

`GET /clinic/settings/`의 tenant 기본은 **학원 기본** 배지로 추천할 뿐이고,
사용자가 카드를 직접 골라야 다음 입력으로 이동합니다. 선택 뒤에는 현재 방식을
짧게 요약하고 **방식 다시 선택**을 제공하므로 실수로 세부 일정을 작성하기 전에
돌아갈 수 있습니다. 수정·복사는 저장된 방식 snapshot을 그대로 열고 이 단계를
건너뜁니다. 자유지정은 긴 세션 하나를 예약하므로 여러 고정 시간대 허용과 학생
희망 시간 옵션을 자동으로 끄고 숨깁니다.

## 같은 날 여러 시간대 예약

- 새 세션은 `GET /clinic/settings/`의 `multi_slot_booking_default`를 체크박스
  초기값으로 사용합니다.
- 생성·수정 요청은 `allow_multi_slot_booking`을 명시해 서버에 저장합니다.
- 확인 화면은 **여러 시간대 허용** 또는 **한 타임만 허용**을 일정·정원·공개
  대상과 함께 보여 줍니다.
- 기존 세션 복사와 이전 주 불러오기는 원본 세션의 정책을 그대로 복사합니다.
- ON에서 OFF로 바꿔도 기존 예약은 화면에서 제거하지 않습니다. 서버가 이후 같은
  날짜의 충돌하는 새 예약만 `409`로 거부합니다.

## 시간 범위 정원 표시

`time_range` 수업은 누적 예약 인원과 동시 정원을 구분해 `예약 N명`·`동시 정원 M명`으로
표시한다. 하루 총 예약을 동시 정원으로 나눈 비율이나 예약률 막대는 표시하지 않는다.
월간 달력·운영 날짜 선택은 서버의 `is_full`을 사용하며 열린 구간이 하나라도 있으면
전체 마감으로 표시하지 않는다. 구체적인 잔여 정원은 선택 구간의 availability가 소유한다.
`fixed_slot` 수업의 기존 인원/정원 표시는 유지한다.

회귀 검증: `e2e/admin/clinic-weekly-multisession.mock.spec.ts`의 시간 범위 정원 사례.

## 빈 세션 운영

운영 화면의 `session` 선택은 참가자 목록이 아니라 세션 tree를 기준으로 유지합니다.
따라서 아직 참가자가 0명인 유효한 세션도 desktop과 390px에서 세션 제목·수정·삭제·
`학생 추가` 동선을 그대로 보여 주며, 첫 학생을 추가하기 전에 일간 합계 화면으로
자동 복귀하지 않습니다. 선택한 세션이 tree에서 실제로 사라졌을 때만 선택을 해제합니다.

## 달력에서 학생 관리

`오늘 출석·진행`에서 달력 날짜를 고르면 선택일 전체 운영 화면을 유지하면서 상단
`배정 학생 관리`에 그날의 세션별 활성 배정 인원을 표시합니다. 각 `학생 관리`는 새
배정 로직을 만들지 않고 정확한 세션을 선택해 기존 `ClinicTargetSelectModal`과
`POST /clinic/participants/bulk-create/` 흐름으로 들어갑니다. 취소·거절 이력은 활성
배정 수에서 제외하되 서버 기록은 보존합니다.

배포 카나리는 desktop의 좌측 달력과 390px의 `일정` overlay에서 실제 날짜를 선택해
추가·reload GET·`cancelled`·reload를 확인합니다. 같은 학원 다른 학생과 별도 qa tenant의
접근은 실제 개발 API가 거부해야 하며, 두 disposable tenant의 tenant/user 숫자 0 정리가
확인되지 않으면 성공으로 판정하지 않습니다.

## 학생 추가 실패와 재시도

운영 화면의 **학생 추가**는 전체 학생 선택이면 `student_ids`, 미통과 대상자
선택이면 정확한 `enrollment_ids`를 `POST /clinic/participants/bulk-create/`에
보냅니다. 서버가 선택 전체를 원자적으로 저장하므로 일부만 추가한 뒤
`0명 추가, 1명 실패`처럼 원인을 잃는 상태를 만들지 않습니다.

기존 예약, 같은 날 시간대 정책, 정원 등으로 실패하면 서버의 구체적인 사유를
표시하고 모달과 체크 선택을 그대로 유지합니다. 사용자는 선택을 조정하거나 같은
자리에서 다시 시도할 수 있습니다. 성공한 뒤에는 참가자와 세션 tree를 다시 읽은
후 모달을 닫아 저장된 명단을 즉시 보여 줍니다. 세션 생성 뒤 초기 학생 추가만
실패한 경우에도 이미 만들어진 세션을 다시 만들도록 유도하지 않고, 실패 사유와
운영 화면의 **학생 추가** 복구 경로를 안내합니다.

`time_range` 세션에서는 대상자 확정 뒤 학생 앱과 같은 실제 시간 선택기를 한 단계
더 보여 줍니다. 세션의 운영 시작·종료는 바꾸지 않고 availability 안의 연속 구간만
`booking_start_time`·`booking_end_time`으로 보냅니다. 여러 명을 한 번에 고르면 모두
같은 구간을 사용하며 다른 구간은 추가 작업을 나눠야 합니다. 저장된 실제 구간은
운영 명단에 표시되고 새로고침 뒤에도 서버 응답으로 복원됩니다.
새 자유지정 클리닉을 만들면서 대상자를 즉시 배정할 때도 생성 폼 안에서 같은
선택기를 사용합니다. 실제 시작·종료를 모두 고르기 전에는 배정 포함 만들기를
제출할 수 없고, 최종 확인에서 대상자와 공통 구간을 함께 보여 준 뒤 세션 생성에
성공한 경우에만 그 구간을 bulk 참가자 요청으로 보냅니다. 저장 후 운영 명단을
다시 읽어 실제 구간이 보이는 것까지가 성공입니다.
`time_range`는 24시간 미만의 운영 창으로 `23:00–01:00`도 입력할 수 있습니다.
같은 시작·종료 시각은 모호하므로 설명과 함께 거부합니다. 서버의 overnight 쓰기
활성화 전에는 서버 오류를 그대로 안내하며 입력을 보존합니다. 활성화·날짜 정책의
소유자는 backend `docs/domain/clinic-booking.md`입니다.
운영일과 `onsite_date`는 시작일을 유지합니다. 관리 운영 화면과 교사 목록의
**전날 시작·진행 중** 버튼은 아직 종료되지 않은 전날 세션의 운영일로 이동합니다.
월 경계에서도 전날 월을 조회합니다. 전날 목록 확인 실패는 빈 목록과 구분해
실패·재시도를 표시하고, 30초마다 현재 시각을 갱신해 종료된 일정 표식을 내립니다. 실제 예약 선택·명단은 API의 `start_date` /
`end_date`, `booking_start_date` / `booking_end_date`를 이용해 다음 날 실제 날짜를
표시하며, 구버전 응답에서는 시작 시각보다 이른 시간을 **익일**로 표시합니다.
운영 창 전체의 기존 availability·정원·최대 체류 정책을 따르고, 경과한 구간을
클라이언트가 임의로 제거하지 않습니다. 실패 시 선택을 유지하고 재시도할 수 있습니다.
PC/390px의 전날 일정 발견 → 직접 등록 → 충돌 안내/재시도 → 실제 날짜 → reload는
`e2e/admin/clinic-weekly-multisession.mock.spec.ts`에서 검증합니다.
