# 관리자 클리닉 일정

관리자가 `/workspace/clinic`에서 클리닉 세션을 생성·복사·수정하고 학생 예약을
운영하는 도메인입니다. 같은 날짜의 여러 시간대 예약 가능 여부는 서버의 세션별
정책을 그대로 편집하며, 프론트가 tenant나 학생별 예외를 추정하지 않습니다.

## 같은 날 여러 시간대 예약

- 새 세션은 `GET /clinic/settings/`의 `multi_slot_booking_default`를 체크박스
  초기값으로 사용합니다.
- 생성·수정 요청은 `allow_multi_slot_booking`을 명시해 서버에 저장합니다.
- 확인 화면은 **여러 시간대 허용** 또는 **한 타임만 허용**을 일정·정원·공개
  대상과 함께 보여 줍니다.
- 기존 세션 복사와 이전 주 불러오기는 원본 세션의 정책을 그대로 복사합니다.
- ON에서 OFF로 바꿔도 기존 예약은 화면에서 제거하지 않습니다. 서버가 이후 같은
  날짜의 충돌하는 새 예약만 `409`로 거부합니다.

## 이전 주 불러오기

- 기준은 벽시계의 이번 주가 아니라 일정 화면에서 현재 선택한 주의 월요일~일요일입니다.
  원본은 정확히 7일 전 월요일~일요일이고, 각 원본 날짜에 7일을 더해 같은 요일로
  만듭니다. 월말·월초와 연말·연초를 건너도 같은 규칙을 사용합니다.
- 원본 주와 대상 주를 각각 `date_from`+`date_to`로 조회합니다. 두 조회가 모두
  성공하고 원본 범위의 실제 세션이 0건일 때만 **이전 주에 클리닉이 없습니다.**를
  표시합니다. 조회 실패는 재시도 가능한 오류 상태이며 빈 상태로 바꾸지 않습니다.
- 사용자는 원본을 개별 선택하거나 전체 선택할 수 있습니다. 제목·요일·시간·장소·정원,
  대상 학년/학교유형/강의/반, 희망시간 접수, 다중 시간대, 예약 방식·간격·최대 체류를
  복사합니다. 학생 명단, 예약/출결 상태와 수치, 알림 이력은 복사하지 않습니다.
- 대상 주에 같은 날짜·시각·장소의 일정이 이미 있으면 **이미 있음**으로 표시하고
  생성에서 건너뜁니다. 생성된 새 세션에 학생을 배정하지 않으므로 불러오기 자체는
  예약 알림을 요청하지 않습니다.
- desktop과 390px 모두 날짜 그룹, 개별/전체 선택, 목적지 날짜와 하단 동작이
  화면 안에 유지되어야 합니다.

## 시간 범위 정원 표시

`time_range` 수업은 누적 예약 인원과 동시 정원을 구분해 `예약 N명`·`동시 정원 M명`으로
표시한다. 하루 총 예약을 동시 정원으로 나눈 비율이나 예약률 막대는 표시하지 않는다.
월간 달력·운영 날짜 선택은 서버의 `is_full`을 사용하며 열린 구간이 하나라도 있으면
전체 마감으로 표시하지 않는다. 구체적인 잔여 정원은 선택 구간의 availability가 소유한다.
`fixed_slot` 수업의 기존 인원/정원 표시는 유지한다.

회귀 검증: `e2e/admin/clinic-weekly-multisession.mock.spec.ts`의 시간 범위 정원 사례.

## 빈 세션 운영

운영 화면의 `session` 선택은 참가자 목록이 아니라 세션 tree를 기준으로 유지합니다.
따라서 아직 참가자가 0명인 유효한 세션도 desktop과 390px에서 세션 제목·수정·삭제·
`학생 추가` 동선을 그대로 보여 주며, 첫 학생을 추가하기 전에 일간 합계 화면으로
자동 복귀하지 않습니다. 선택한 세션이 tree에서 실제로 사라졌을 때만 선택을 해제합니다.

## 학생 추가 실패 복구

운영 화면에서 여러 학생을 추가할 때 각 요청의 결과를 학생별로 유지합니다. 일부만
실패해도 숫자 합계로 축약하지 않고 선택 당시 학생 이름, 서버가 반환한 실제 사유,
다음 해결 행동을 닫기 가능한 안내창에 표시합니다. 같은 날짜 한 타임 제한이면 기존
예약을 취소하거나 여러 시간대 예약이 허용된 일정으로 변경하도록 안내하고, 정원 마감·
중복 등록·지난 일정은 각각 정원/명단/날짜를 확인하도록 안내합니다. 실패한 학생 이름과
사유는 브라우저 로그에 추가하지 않습니다.

학생 추가 실패가 발생해도 성공한 다른 학생은 그대로 유지하며 참가자와 일정 tree를
다시 조회합니다. 교사 앱의 여러 시간대 일괄 추가는 서버의 원자적 bulk 계약을 그대로
사용하므로, 그 요청이 실패하면 선택 학생 모두가 미등록 상태로 남습니다.

관리자 mock E2E는 월 경계 조회·복사 직후 표시·reload 지속과 학생별 충돌 복구를
같은 운영 화면에서 검증합니다. `e2e/student/clinic-multi-slot-realuse.spec.ts`는
격리된 development tenant에서 생성→학생 다중 예약→교직원 추가→일정 변경→새 연결
재조회→학생 취소→세션/참가자 정리를 검증하며, 외부 tenant의 데이터는 사용하지 않습니다.
