# 공통 디자인 시스템

## 공통 조작 규격

물리적 치수는 `foundation.css`가 소유한다. 버튼의 중요도는 `intent`, 크기는
사용 맥락으로 정한다. 문구 길이에 따라 너비가 달라지는 것은 허용하지만 같은
작업줄에서 높이·글자·아이콘·좌우 여백을 제각각 고르지 않는다.

| 용도 | 크기 | 데스크톱 높이 | 좁은 화면·터치 포인터 |
|---|---|---|---|
| 표 안 보조 조작·작은 선택 | sm | 32px | 44px |
| 일반 필드·독립 조작 | md | 40px | 44px |
| 목록 툴바·헤더·모달 실행 | lg | 44px | 44px |
| 로그인·큰 진입 실행 | xl | 48px | 48px |

`--control-*`는 공통 `--ds-control-*`의 호환 연결이다. 모바일 규칙에서 다시
고정 높이를 선언하지 않는다. 기본 본문 14px, 보조 정보 12–13px, 이름 15px,
제목은 기존 공통 글자 위계를 사용한다. 필드는 좁은 화면·터치 포인터에서 16px로
입력 가독성을 확보한다. 기본 조작 간격은 8px, 관련 폼 간격은 12–16px이며
기존 4px 간격 체계와 역할별 호환 연결을 사용한다. 강의 생성처럼 카드 장식을 제거한
폼은 라벨과 필드 사이 8px를 한 곳에서 소유하여 카드 gap과 중복하지 않는다.
컨트롤 크기를 유지하면서 본문과 고정 하단 동작의 가시성을 확보한다.
학생 읽기 화면의 본문·상단·하단은
1120px 상한으로 정렬하고 교사 업무 화면은 기존 1320px 상한을 공통 토큰으로
소비한다. 작은 화면은 가용 폭을 사용하며 영상 전용 상한과 표의 가로 스크롤은 유지한다.

`ActionBar`, `DomainListToolbar`, `ModalFooter`, 교사 `BottomSheet` 하단은
`ControlSizeContext`로 같은 묶음의 공용 `Button` 크기를 결정한다. 툴바·모달은
lg이며 래퍼 안에 있는 버튼도 동일 규격을 따른다. 아이콘은 공용 좌우 슬롯을
사용하고 실제 그룹 크기에 맞춰 표시한다. 입력·선택창은 `data-control-size`를
소비한다. 새 폼은 `ds-input`, `ds-select`, `ds-textarea`를 사용하고 테마·상태는
정본에서 관리한다. 한 줄 라벨이 잘리면 버튼을 축소하지 말고 그룹 줄바꿈이나
명시적 스크롤로 배치를 해결한다. 단일 실행 문구 자체가 화면보다 긴 모바일 모달은
단어 단위 줄바꿈과 행 높이 확장을 허용하여 내용을 숨기지 않는다.

학생 버튼·입력·선택·아이콘 조작은 학생 역할 토큰을 통해 같은 기준을 소비한다.
일반 학생 조작은 44px, 큰 조작은 48px이며 테넌트 색·라이트/다크·영상 전용
표면을 유지한다. 교사 팝업은 포털에 있어도 본문과 같은 규격을 사용한다.
학생 앱의 새 화면에서 조작의 용도가 명시되면 `stu-btn`의 `data-size`로 공통
크기를 선택한다. 기존 크기 클래스는 44/48px 호환값을 사용한다.
로그인 입력·실행은 48px, 가입 필드·하단 실행은 44px다. AntD 호환 컨트롤도
같은 치수를 소비하며 affix 입력은 바깥 상자만 높이를 소유한다.

배지는 조작과 구분하는 읽기 전용 상태다. 글자와 안쪽 여백은
`foundation.css`의 `--ds-badge-*`가 소유한다. 표·기록·프로필 메타는 기본
`sm`(11px), 독립 카드의 중요한 상태는 `md`(12px), 매트릭스 셀은 `xs`(10px),
요약의 강조 지표는 `lg`(13px)로 표시한다. 관리자·교사는 공용 `Badge`를
사용한다. 기본은 옅은 배경이고, 같은 기록 목록에서 결과를 빠르게 비교해야
할 때 진한 배경을 쓴다. 브랜드색은 주요 실행·선택, 초록은 완료·활성, 경고색은
대기·확인 필요, 위험색은 실패·삭제, 중립색은 분류·종료에 쓴다. 상태는 문구로도
표시하며 배경·글자는 각 역할과 테넌트의 의미 토큰을 함께 소비한다.

기록 카드의 기본 규격은 14px 모서리, 16px 안쪽 여백, 관련 항목 사이 12px다.
같은 대상을 요약하는 정보와 이동은 한 카드의 행과 구분선으로 배치한다.
관리자 학생·직원 상세의 기록 탐색은 `ds-record-tabs`의 44px 한 줄 탭을 사용한다.
좁은 화면에서는 탭 줄 안에서 가로로 이동하고 선택한 기록만 본문에 표시한다.

표·목록의 글자/여백은 기존 공통 토큰을 사용한다. 체크박스·라디오의 표시점,
영상 슬라이더·캔버스·내용 카드처럼 별도 의미를 가진 요소에 일반 버튼 크기를
일괄 강제하지 않는다. 이 경우 클릭 가능한 바깥 영역과 키보드 초점은 해당
컴포넌트 계약으로 검증한다. 선택·포커스·오류·로딩·비활성 상태와 입력 보존,
저장·재시도·권한·테넌트 분리는 기존 동작을 유지한다.

규격 검증은 `e2e/visual/theme-control-states.spec.ts`의 모든 테마·1366/1100/390px
실측, `student/design-system-isolation.mock.spec.ts`의 역할·다크 분리 및 조작,
`teacher/lecture-navigation-recovery.mock.spec.ts`의 모달 크기·저장·실패 복구를
사용한다. 공통 컨트롤 변화는 기존 전체 PR gate와 동일 산출물 development-canary,
cleanup0, 운영 정확한 revision/자산/영향 흐름 검증을 함께 통과해야 한다.
이 절은 검증 계약이며 아직 실행하지 않은 검사를 통과 기록으로 간주하지 않는다.

## 범위와 정본

학생·학부모·교사·관리자는 공통 기초 값을 사용한다. 메뉴 이름·위치·URL, 역할별
업무 순서, API·권한·테넌트 경계는 유지한다. 여백·글자 위계·표면·조작 피드백을
정리하며 화면별 업무 배치는 해당 CSS 모듈이 소유한다.

| 계층 | 정본 | 책임 |
|---|---|---|
| 기초 값 | `src/styles/design-system/foundation.css` | 간격·반경·글자 크기·중립색·모션·그림자 |
| 공통 의미 | `colors/scale/`, `colors/role/`, `density/`, `typography/`, `surface/` | 기초 값의 역할 연결과 기존 토큰 호환 |
| 관리자·교사 스타일 | `colors/themes/index.css` | 클린·노트·포커스의 표면, 모서리, 대비, 사이드바 |
| 강조색 | `src/shared/theme/accent.ts` | 사용자 색의 검증과 읽을 수 있는 상태별 색 파생 |
| 표시 취향 | `src/shared/theme/themes.ts`, `themeRuntime.ts`, `src/shared/contexts/ThemeContext.tsx` | 목록, 이관, DOM 적용, 저장·실패 상태 |
| 설정 화면 | `src/shared/theme/AppearanceSettings.tsx`, `ThemeGrid.tsx` | 관리자·교사 공통 선택, 실제 토큰 미리보기, 색상 입력·복구 |
| 교사 연결 | `src/app_teacher/shared/ui/tokens.css` | 기존 `--tc-*`를 공통 의미·기초 값에 연결 |
| 학생 연결 | [학생 테마 정본](../src/app_student/shared/ui/theme/README.md) | `--stu-*`, 테넌트 브랜드, 라이트·다크·영상 경계 |

표의 축약 CSS 경로는 `src/styles/design-system/` 기준이다.
진입점은 `src/index.css` → `design-system/index.css`다. 기초 값 → 의미 연결 →
스타일 → 컨트롤 순서로 로드한다. 학생의 테넌트 색·다크 모드는 별도 역할 연결이며
교사의 개인 테마를 상속하지 않는다. 로그인 브랜드는 [테넌트 브랜딩](TENANT-BRANDING.md)을
따른다. 공용 React 컨트롤은 `src/shared/ui/ds/index.ts`를 사용한다.

기존 `--space-*`, `--tc-*`, `--stu-*` 이름은 호환 연결이다. 학생 간격은 역사적으로
2px 단위, 교사는 4px 단위였으므로 같은 숫자를 같은 값으로 치환하지 않는다.
사용 중인 간격 의미를 유지하면서 기초 값에 연결한다. 새 독립 팔레트·복제 토큰을
화면에 추가하지 않는다. 학생의 미사용 `palette.css`, 중복 다크·시스템 그림자 정의,
관리자 전용 테마 카드·미리보기 복제는 이 통합으로 제거했다.

## 화면 스타일과 강조색

`/workspace/settings/appearance`, 시스템 설정, 교사의
`/workspace/mobile/settings/appearance`는 같은 설정을 소비한다. 기존 ‘테마’ 메뉴와
뒤로가기·선택·키보드 조작은 유지한다.

- **클린**: 중립 바탕과 흰 표면, 가벼운 테두리, 절제된 둥근 모서리.
- **노트**: 종이 바탕, 작은 모서리, 선과 얕은 겹침으로 구획을 구분.
- **포커스**: 어두운 바탕과 밝기가 다른 표면, 저눈부심 글자·상태색.

색만 다른 12개 프리셋은 세 스타일과 별도 강조색으로 대체한다. 스타일마다 화면
구조를 바꾸지 않으며, 강조색 변경은 버튼·선택·링크에만 반영한다. 학원 로고,
테넌트 브랜드, 성공·주의·오류의 의미색은 개인 강조색으로 대체하지 않는다.
색상 선택기는 즉시 적용하고, 여섯 자리 HEX 입력은 Enter/‘색상 적용’으로 확정한다.
잘못된 값은 입력을 보존하고 오류를 표시하며 적용된 색은 유지한다.

`accent.ts`는 선택한 원본 색을 보존하면서 실제 표면·바탕 위 강조 글자 및 강조 면의
글자 대비를 확보하도록 표시 밝기를 조정한다. 공용·교직원 컨트롤의 흰 글자 고정값은
`--color-brand-primary-contrast`와 역할별 연결을 소비한다. 미리보기 역시 같은 함수를 사용하고
`.theme-preview`에서 실제 의미 토큰을 다시 계산하므로 상위 테마에 영향받지 않는다.
`colors/preview-theme.css`는 미리보기 별칭만 소유한다. 초기 부팅용
`colors/scale/brand.css` 이후의 활성 강조색은 런타임 파생 값이 정본이다.

선택은 `aria-pressed`로 전달하고 Enter/Space로 적용한다. 모바일에서는 설명이
잘리지 않도록 세로 목록으로 배치한다. 현재 적용과 키보드 포커스는 구분한다.
색상 입력·선택은 44px 조작 영역을 유지하며 reduced-motion을 존중한다.

## 저장·이관·실패 복구

`hakwonplus:appearance`의 `{ version: 1, theme, accent }`가 브라우저 표시 취향의
정본이다. 유효한 새 객체가 있으면 우선하고, 없거나 손상됐으면 기존
`hakwonplus:theme`을 이관한다. 밝은 프리셋은 클린, 모카·모노는 노트, 어두운
프리셋은 포커스로 옮기며 기존 강조색을 보존한다.
`ivory-office`, `youtube-studio`, `terminal-neon`도 지원한다.
알 수 없는 키·손상된 JSON은 기본 클린으로 안전하게 진입한다.

이전 배포로 돌아가도 읽을 수 있도록 기존 키에는 클린=`modern-white`,
노트=`minimal-mono`, 포커스=`modern-dark`를 기록한다. 구버전은 사용자 지정 색을
지원하지 않지만 새 객체는 보존되어 새 버전에서 복원된다. 사용자 데이터나
테넌트 설정의 삭제·서버 쓰기는 없다. 상위 계약은 [브라우저 저장](BROWSER-PERSISTENCE.md)이다.

저장 후 읽기 확인에 실패하면 현재 화면에는 적용하되 저장 실패를 명확히 알리고
‘저장 다시 시도’를 제공한다. 기본값 복구도 같은 저장 경로를 사용한다. 저장소가
차단된 상태에서 재방문 복원을 성공으로 안내하지 않는다.

## 공용 표면과 컨트롤

바탕은 `--color-bg-canvas`, 읽는 면은 `--color-bg-surface`, 눌림·호버는 별도
상태 토큰을 쓴다. 일반 패널은 테두리와 여백으로 구분하며 겹친 광택·그림자를
제거한다. 모달 배경은 테마 이름 목록을 JS/CSS에서 각각 판단하지 않고
`--color-modal-bg` 하나를 소비한다.
날짜·시간 선택기의 body 포털도 `--color-bg-surface`를 사용하며 테마 이름 목록이나
별도 팔레트를 갖지 않는다. 선택한 날짜와 시간 적용 버튼은 같은 강조색 대비를 따른다.
AntD reset과 전역 native control 초기화는 Tailwind의 `base` 계층과 낮은 선택자 우선순위를 사용한다.
역할 컨테이너의 상속 규칙이나 계층 밖 초기화로 컴포넌트·유틸리티가 지정한
글자색·글꼴·강조 배경을 덮지 않는다.
PPT 비율·배치 선택지는 이름과 설명을 세로로 분리하며, 배경색 견본과 이름은 가로 정렬을 유지한다.

상태 글자·아이콘의 의미색과 채워진 버튼·배지의 `--color-*-solid`는 분리한다.
특히 다크 스타일의 밝은 오류·성공색 위에 흰 글자를 직접 얹지 않는다. 채워진 면은
`--color-semantic-contrast`와 함께 소비하며 교사의 `--tc-*-solid`도 같은 정본에 연결한다.
교사 상태 글자와 출결 상태는 `--color-*-text`를 연결해 밝은 표면에서도 읽을 수 있게 한다.
매치업 보고서의 포함·제외 버튼과 선택·완료 배지도 같은 역할 토큰을 사용한다.
자동저장·후보 검색·재시도 안내는 상태별 `--color-*-text`와 `--color-*-bg`를 짝지어 쓴다.
자동저장 상태는 재시도 불가 상태에서도 읽을 수 있는 불투명도로 표시한다.
보고서 이미지 확대 버튼과 묶음 안내의 표면·글자도 테마 토큰을 사용하며 문서 이미지 자체는 유지한다.
`matchup-mobile-touch-parity.mock.spec.ts`에서 밝은 강조색의 버튼·선택·변경됨 상태 대비와
PC/390px 선택·저장·재열기·다운로드를 함께 검증한다.

주요 작업은 `Button`, 상태 선택은 `SelectionButton`, 읽기 전용 상태는 `Badge`가
맡는다. 로딩·빈 결과·오류·재시도·저장 중·선택·비활성은 서로 구별하며, 색만으로
의미를 전달하지 않는다. 긴 한국어 라벨은 읽을 수 있도록 그룹을 줄바꿈하거나
소유 화면의 스크롤로 해결한다. 스타일 정리는 기능 숨김·권한 변경·입력 소실로
해결하지 않는다. 영상·성적 그리드·모달의 도메인 전용 배치는 각각의 정본을 유지한다.
학생 화면은 360px 이하에서 바깥 좌우 여백을 12px로 줄여 달력의 7열과 터치 영역을
보존한다. `clinic-booking-ux.mock.spec.ts`에서 390px·PC와 125% 확대에 해당하는
312px 너비의 날짜 선택, 키보드 이동, 가로 넘침을 검증한다.

## 모달 최소화와 복원

관리자 공용 `AdminModal`의 최소화는 입력 상태를 유지한 채 하단 작업 표시줄에
창을 남긴다. 표시줄에서 같은 창과 입력을 복원하고, 실제 닫기 또는 화면 이탈로
창이 해제될 때만 표시줄 항목을 정리한다. 다른 창의 최소화나 부모 재렌더는
닫기가 아니다. 복원은 저장 요청을 보내지 않으며, 저장 중 이탈 제한과 미저장
확인은 각 화면의 계약을 유지한다. 합산 설정의 PC/390px 회귀는
`assessment-feedback.mock.spec.ts`와 [합산 구성](ASSESSMENT-TOTALS.md)이 소유한다.

공용 모달은 열람·입력·확인 모두 확대 대신 짧은 페이드로 나타나고 사라진다.
이미지나 목록이 준비되는 순간에도 버튼 위치를 고정해, 늦게 시작된 확대 효과가
클릭 도중 선택·닫기 버튼을 이동시키는 문제를 방지한다. 닫은 뒤 호출 화면으로 돌아가며,
숙제 미리보기 회귀는 실제 이미지 로드 → 닫기 한 번 → 대화상자 사라짐 → 검수
저장·새로고침과 호출 버튼으로의 포커스 복원을 검증한다. 모션 감소 설정에서는
모든 공용 모달 효과를 즉시 끝낸다. 생성·확인 및 최소화·복원의 동작 계약은 유지한다.
`clinic-weekly-multisession.mock.spec.ts`는 PC/390px에서 일정 선택을 한 번 누른 뒤
선택 상태 → 불러오기 → 저장 응답 유실 복구 → 새로고침 시 중복 없는 결과를 검증한다.

## 대화상자의 배치와 키보드

교사 `BottomSheet`는 모바일에서 기존 하단 시트를 유지하고, 768px 이상에서는
최대 640px의 대화상자로 표시한다. 본문만 스크롤하고 강의·학생 등록의 저장 영역은
하단에 고정한다. 390px 및 높이 560px에서도 저장·취소를 찾을 수 있어야 한다.
배경은 전체 화면을 가리고 닫기 버튼은 44px 터치 영역을 제공한다.

`shared/ui/overlays/useDialogSurface`는 교사 시트, 학생 커뮤니티 이미지 확대,
공용 날짜·시간 선택창, 학생·교사의 모바일 메뉴의 초기 포커스·Tab 순환·Escape·호출 위치 복원을 소유한다.
마우스로 누른 버튼에 자동 포커스를 주지 않는 Safari에서도 최근 호출 버튼을
보존해 같은 위치로 복원하며, 키보드 호출은 기존 활성 요소를 기준으로 한다.
열린 창 스택의 최상단만 키보드에 반응한다. 날짜·시간 팝업이 열린 동안
`AdminModal`은 단축키를 넘겨서 팝업만 닫히고 부모 폼의 입력은 유지되게 한다.
Ant Design 선택·날짜·메뉴 팝업에도 같은 우선순위를 적용한다. 팝업이 열려 있는
동안 Enter는 항목 선택, Escape는 팝업 닫기를 처리하며 부모 폼을 제출하거나
닫지 않는다. 팝업을 닫은 뒤에는 기존 모달 단축키로 돌아온다. 클리닉 생성에서
예약 간격 선택을 취소해도 제목·장소·시간 입력은 남고 다시 선택해 생성할 수 있다.
표시·닫힘 애니메이션, 권한과 저장 API는 유지하며 기존 데이터 이관은 없다.
클리닉 폼의 시간 조절 버튼은 시간 입력 아래에 배치해 좁은 창에서도 전체 시간과
익일 표시를 읽을 수 있게 한다. 390px에서 세로로 쌓이는 정원·체류 시간 필드는
가로 배치용 고정 너비를 높이로 적용하지 않아 불필요한 빈 공간을 만들지 않는다.
공용 문구·서식 편집기는 `delegateEditorEscape`로 대화상자 안의 Escape만 부모에게
넘긴다. ProseMirror 기본 처리에 막혀 미저장 닫기 확인이 사라지지 않으며,
줄바꿈·실행 취소와 한글 조합은 편집기가 계속 소유한다.
`bodyScrollLock`은 이 창들과 `ConfirmDialog`의 스크롤 잠금을 소유자별로 관리한다.
겹친 창 하나를 닫아도 나머지 창의 잠금을 해제하지 않는다. Ant Design 모달의
자체 수명주기와 최소화 계약은 유지한다.

교사 출결 상태 선택도 공용 `BottomSheet`를 사용한다. 개별 배경·스크롤 잠금·
애니메이션 구현을 제거하며 출석 카드는 Enter·Space로 열 수 있다. 학생 메뉴의
로그아웃 확인은 `ConfirmDialog`로 통일해 취소 시 메뉴와 로그인 상태를 보존하고,
확인 시에만 기존 로그아웃을 실행한다. 교사 데스크톱의 고정 메뉴는 모달로 취급하지 않는다.

`ConfirmDialog`의 위험 동작은 취소에 초기 포커스를 둔다. 버튼·링크의 Enter는
그 컨트롤의 기본 동작에 맡기므로 취소를 확인으로 바꾸지 않는다. 관리자 모달의
Enter 자동 실행은 해당 모달 footer의 명시적 primary 버튼만 대상으로 하고,
비활성 등록 대신 취소·삭제를 실행하지 않는다. 한글 조합 중 Enter는 가로채지 않는다.

`useConfirmBeforeClose`는 수정한 강의·학생 등록 폼의 닫기 경로를 통일한다.
닫기 버튼·배경·Escape 모두 작성 유지 또는 명시적 폐기를 선택하며 처리 중에는
닫기와 중복 제출을 막는다. 닫기 확인은 서버 쓰기를 실행하지 않는다. 기존 URL,
메뉴, 권한, 저장 API와 데이터에는 마이그레이션이 없다.

## 첫 진입과 상세 화면의 위계

첫 진입은 주요 업무와 짧은 분류를 제시하고, 분류를 선택하면 별도 URL의 업무
목록으로 이동한다. 주요 탐색을 펼침 메뉴로 누적하지 않는다. 상세 화면에서는
필요한 설명과 조작을 제공한다. 오류·저장 상태·복구는 기본 화면에서 계속 보인다.
구체 역할별 진입은 [업무 탐색](WORKSPACE-NAVIGATION.md)과
[학생·학부모 계약](STUDENT-PARENT-APP-CONTRACT.md)이 소유한다.

`DomainLayout`은 작은 상위 경로 → 현재 객체의 h1 제목 → 해당 객체의 탭 → 본문
순서다. 경로를 제목 대신 크게 표시하지 않으며 현재 제목은 경로 끝에서 중복하지
않는다. 헤더 장식과 탭의 중첩 테두리를 제거하고 선택 상태는 밑줄·색으로 표시한다.
390px에서도 탭은 한 줄로 이동하며 본문을 밀어내는 2~3줄 배열을 만들지 않는다.
`PageTrail`은 실제 링크를 사용하고 학생 상세에도 같은 복귀 구조를 제공한다.

같은 과제·시험 헤더의 제목 수정, 템플릿 저장, 주요 작업은 `Button size="lg"`로
높이(44px)·패딩·아이콘을 맞추고 `intent`로 우선순위를 표현한다. 너비는 문구에
맞춘다. 목록·표의 작은 동작은 기존 `sm`을 유지한다. 관리자 모바일 밀도 규칙은
`lg`/`xl`을 40px로 축소하지 않으며 화면별 높이 재정의 대신 DS size를 소비한다.

출결의 메모 열은 `StudentLectureMemo compact`로 강의·학생 공통 메모를
가로 배치하고 한 줄 미리보기를 제공한다. 가로 화면 밖의 메모 때문에 모든 행이
늘어나지 않는다. 전체 내용·편집·미저장 복원·동시 수정 충돌은 기존 메모 창이
유지하며 데이터나 접근 권한을 바꾸지 않는다.

검증 정본: `session-attendance-bulk-safety.mock.spec.ts`(탭·집계·390px 행 높이),
`student-lecture-memo.mock.spec.ts`(저장·reload·강의 분리·충돌),
`assessment-operations-workspace.mock.spec.ts`, `lecture-session-scopes.mock.spec.ts`
(1366/1100/390px 버튼 실측·기존 저장/복구). 캡처만으로 저장 성공을 판정하지 않는다.

전체 업무의 차시 출결표는 모든 폭에서 학생마다 11개 상태 버튼을 펼쳐 놓는다. 색상, 반응형 배치와 저장·실패 복구 계약은 [출결 명단 안전](ATTENDANCE-ROSTER-SAFETY.md#ui와-접근성)을 따른다.

명단의 기본 도구줄에는 일상 작업을 우선한다. 출결의 부가 업무는 별도 URL이 있는 도구 화면으로 이동하며, 학생을 선택했을 때에만 선택 문맥 요약과 대상 작업 진입을 제공한다. 일괄 결과·오류·되돌리기는 계속 눈에 보이는 위치에 둔다.
