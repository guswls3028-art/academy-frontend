# 가입 신청과 클리닉 예약 승인

교직원이 현재 승인 방식을 이해하고, 대기 신청을 확인한 뒤 처리 결과까지 확인하는
화면 계약이다. 가입은 `/workspace/students/requests`, 클리닉은
`/workspace/clinic/home`에서 진입한다. 기존 역할·학원 접근 권한과 승인 규칙은
서버가 결정한다. 비밀번호·학부모 계정·삭제 이력 복구 정책은
[학생 정본](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/student-core.md)과
[학부모 계정](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/parent-account.md)을 따른다.

## 승인 방식

두 화면은 공용 `ApprovalPolicyPanel`로 서버에 저장된 자동/직접 승인 상태를 표시한다.
전환은 기존 가입 `registration_requests/settings/` 또는 클리닉 `clinic/settings/`
API의 해당 boolean 하나만 수정한다. 새로 접수되는 신청부터 적용되며 기존 대기
신청은 이 설정 변경만으로 승인하지 않는다. 저장 중에는 추가 전환을 막고,
성공 응답으로 캐시를 갱신한다. 실패 시 마지막 저장값과 오류를 유지하고
`저장 다시 시도`로 같은 변경을 다시 요청한다. 조회 실패는 직접 승인 상태로
추정하지 않고 설정 재조회를 제공한다. 가입 비밀번호 설정 검증도 서버에 유지한다.

## 가입 신청 처리

대기 목록은 50건씩 추가 조회한다. 전체 건수와 불러온 건수를 구분하며 전체 선택은
현재 불러온 신청에만 적용한다. 다음 페이지 실패에도 기존 신청과 선택을 유지한다.
학생 이름·학교·연락처·신청 날짜를 확인하고 `신청 상세` 버튼으로 상세 대화상자를
연다. 승인·거절은 이름 있는 버튼과 최종 확인을 거친다. 확인 중 연속 실행과
저장 중 상충 처리를 방지한다. 상세 저장 오류는 대화상자 안에도 표시한다.

승인은 학생·학부모가 이미 선택한 비밀번호를 유지한다. 기존 삭제 이력 충돌은
명시적 계정 선택·복구 과정을 유지한다. 일괄 승인 일부 실패는 성공 건수와
실패 학생·이유를 화면에 남기고 실패 신청의 선택을 유지한다. 전체 요청 실패도
선택을 지우지 않는다. 승인 후 학생 목록·알림 건수·대기 목록을 갱신한다.
신청과 계정 데이터는 기존 API에 보존되며 저장 형식·마이그레이션 변경은 없다.

## 교사 학생 직접 등록

`/workspace/mobile/students`의 학생 추가는 기존 계정·초기 비밀번호 정책을 유지한다.
등록 버튼은 스크롤 본문 밖의 고정 영역에 두고, 수정 후 닫기·배경·Escape에는
작성 유지/폐기 확인을 제공한다. 초기 비밀번호 확인 및 실제 등록 요청 중에는
부모 입력창 이탈과 중복 제출을 막는다. 비밀번호 확인 취소는 입력을 지우거나
학생을 생성하지 않는다. 성공 후 계정 준비 상태·로그인 ID·학생 화면 검수 진입을
유지하며 기존 서버 권한과 tenant 경계에는 변경이 없다.
390/1366px, 높이 560px에서 작성 보존 → 비밀번호 선택 → 등록 결과를 검증한다.

## 클리닉 예약 처리

자동승인 설정과 별도 영역에서 날짜와 무관한 승인 대기를 보여 준다. 첫 3건은
이름·날짜·시간·장소를 미리 보여 주고 `대기 신청 보기`는 기존 운영 화면의
승인 대기 영역으로 연결한다. 개별 시간·요청사항·승인·거절 기능은 그 화면에 유지한다.
일괄 승인은 현재 확인한 건수를 최종 확인한 뒤 기존 참가자 상태 API로 `booked`를
저장한다. 확인 취소는 쓰기를 실행하지 않는다. 동시 요청은 최대 4개로 제한한다.
부분 실패는 이름과 이유를 남기고, 다시 조회된 대기 목록에서 재시도한다.
참가자·세션 트리·알림 건수를 갱신하며 학생 예약 화면에서도 확정 상태를 확인한다.
대기 조회 실패를 0건으로 표시하지 않으며 오류 중에는 목록 재조회를 제공한다.

## 표현과 검증

기존 테마 토큰과 공용 버튼·상태 배지를 사용한다. 데스크톱은 정보와 처리 버튼을
가로로 정렬하고 390px은 정보 아래에 44px 승인·거절 버튼을 둔다. 상세 진입과
선택은 독립된 키보드 조작 대상이며 피드백 전환은 동작 줄이기를 따른다.

`e2e/admin/approval-workflows.mock.spec.ts`는 1366/390px 설정 저장 실패·재시도·reload,
기존 대기 불변, 가입/예약 일괄 처리의 부분 실패·재시도, 추가 페이지 오류와 선택
보존, 키보드 상세 진입을 검증한다. `student-create-readback.mock.spec.ts`의 비밀번호
선택 보존 검사를 함께 유지한다. 격리 실사용의 학생·학부모 가입 검사에서는 화면의
설정 전환→서버 readback→신규 수동/자동 가입→계정 로그인까지 검증한다.
클리닉 실사용은 1366/390px 설정 전환·reload·서버 readback 후 학생 예약이
실제로 확정되는지와 학부모 조회를 확인하고 원래 설정을 복원한다.
출시에는 동일 artifact 개발 실사용·cleanup zero와 운영 읽기 전용 검증이 필요하다.
