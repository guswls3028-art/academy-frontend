# 출결 QR 화면 계약

## 교직원

강의의 차시 출결 탭과 클리닉 화면의 `출결 QR 출력`에서 표지를 발급한다.
강의 표지는 그 강의의 당일 등록 차시에 재사용하며 클리닉 표지는 입력한 정확한
장소 이름의 확정 예약에 재사용한다. 장소를 비우면 학원의 모든 장소를 대상으로 한다.
목록 로딩/오류/재시도를 구분하고 발급 이름·장소는 실패해도 유지한다.
표지 선택 → SVG 미리보기 → `QR 인쇄·PDF 저장` → 브라우저 인쇄로 A4 표지를 출력한다.
표지에는 개인 정보 없이 로그인·스캔 안내를 넣고 QR 주위 흰 여백을 유지한다.
새 QR 교체와 사용 중지는 영향 확인 후 실행하며 기존 출결은 삭제하지 않는다.

## 학생

홈·출결 현황·클리닉의 `QR 출석`으로 `/student/attendance/scan`에 진입한다.
카메라는 학생이 버튼을 눌러 켠다. 후면 카메라를 선호하고 디코더를 지연 로딩한다.
앱을 떠나거나 백그라운드로 보내면 촬영을 중지하고, 다시 버튼을 눌러 시작한다.
촬영 프레임은 기기 안에서 해독하고 서버에는 표지 토큰만 보낸다.

- 수업 대상 하나: QR 인식 → 서버 자격 조회 → 출석 자동 저장 → 저장 시각 표시.
- 수업 대상 여러 개: 본인의 당일 차시를 확인하고 출석할 차시를 선택한다.
- 클리닉: 예약과 현재 기록을 표시하고 `등원하기`/`하원하기`를 명시적으로 선택한다.
  하원은 학습 완료를 의미하지 않는다. 연속 촬영으로 하원으로 바뀌지 않는다.
- 성공 뒤 학생 쿼리를 무효화하고 출결/클리닉 기록 링크를 제공한다. 새로고침 후
  서버 기록을 다시 읽는다. 저장 응답 실패는 같은 동작 재시도로 결과를 확인한다.
- 본인 학생만 입력 가능하며 학부모에게 QR 입력 버튼을 보여주지 않는다. 직접 URL
  접근도 읽기 안내로 종료하고 서버에서 권한을 다시 검증한다.

발급 링크는 현재 origin의 고정 scan 경로와 fragment 토큰만 포함한다. 다른 origin,
다른 경로·쿼리와 잘못된 토큰은 API 요청 전에 거절한다. 로그인 전 휴대폰 기본
카메라로 링크를 열면 기존 로그인 복귀 경로를 통해 스캔 화면으로 돌아온다.

## 실패·접근성·모바일

권한 거절/카메라 미지원은 구체적 안내와 QR 사진 촬영·선택, 링크 입력으로 복구한다.
사진은 20MB 이하이며 해독 후 이미지를 업로드하지 않는다. 잘못된 QR, 다른 학원,
중지/교체된 QR, 가능한 차시/예약 없음, 수동 출결 보호, 저장 실패를 구분한다.
입력·촬영 중 중복 요청을 막고 로딩은 status, 오류는 alert로 안내한다.
390px에서는 버튼을 쌓고 가로 넘침을 막는다. 완료 전환의 짧은 움직임은 reduced-motion을
존중한다. 배포 Permissions-Policy는 camera=(self)만 허용하고 마이크·위치는 계속 차단한다.

## 서버 소유와 검증

API·상태·한국 날짜·예약 시간·잠금과 보존 정책은
[backend QR 계약](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/attendance-qr.md)을 따른다.
`qr-scanner@1.4.2`는 실시간/사진 해독을 담당하고, 기존 antd QRCode는 표지 SVG를 만든다.
공식 사용 계약: [qr-scanner](https://github.com/nimiq/qr-scanner/blob/master/README.md).
고정 표지는 공유될 수 있으므로 현장 존재를 기술적으로 증명하지 않는다.

타입/린트/빌드와 QR route mock에서 390/1366px 발급·학생 저장·중복·조회·복구를 검사한다.
실제 데이터 저장·양 역할 소비·정리는 같은 artifact의 격리 development에서 확인한다.
기존 `student-parent-clinic-realuse.spec.ts`는 전용 qa-* 학생으로 선생님 QR 발급,
실제 이미지 해독, 수업 출석·클리닉 등원·하원, 조회·재시도와 정확한 fixture 정리를 검사한다.
이때 발급한 QR은 중지하고 수업·클리닉 fixture를 삭제하며, 격리 tenant 최종 정리는
기존 development runner의 cleanup-zero 게이트가 확인한다.
실물 인쇄물과 iOS/Android 카메라 검증은 mock 결과와 분리해 기록한다.
