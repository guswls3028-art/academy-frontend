# 학생 공통 메모와 강의 메모

## 목적과 소유권

학생 공통 메모는 학생 자체의 특이사항이며 기존 `Student.memo`와 학생 정보 편집
흐름을 유지한다. 학생별 강의 메모는 한 학생이 한 강의에서 받는 안내·조교 인수인계
사항이다. 예를 들어 같은 학생도 영어 A에서는 영상 수강, 영어 B에서는 현장 수강일
수 있다. 강의 메모는 수강등록 `Enrollment.lecture_memo` 한 곳에만 저장하며 해당
강의의 모든 정규·보강 차시가 같은 값을 읽는다. 별도의 차시 메모를 만들거나 기존
학생 메모·보강 준비 메모(`Attendance.memo`)를 복사/변환하지 않는다.

API, 권한, tenant 격리 및 수강등록 삭제·복구 정책은
[backend 학생 도메인 계약](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/student-core.md)이 소유한다.

## 직원의 진입과 표시

- 관리자 **강의 → 차시 → 출결** 명단에서 학생 행 아래에 강의 메모와 학생 공통
  메모를 구분하여 표시한다. 비어 있는 강의 메모에는 `메모 추가`가 표시된다.
- 조교용 **강의 → 차시 → 학생/출석**, **출석 체크** 화면도 같은 공용 컴포넌트를
  사용한다. 스와이프 출결 동작과 메모 편집 영역은 분리한다.
- 메모 내용은 명단에서 두 줄까지 바로 읽고, 누르면 전체 내용을 확인한다.
  강의 메모 편집창은 현재 학생·강의와 “모든 차시에서 공유, 다른 강의에는 표시되지
  않음” 범위를 안내한다. 학생 공통 메모는 이 창에서 읽을 수 있고 학생 정보에서
  수정한다. 학생 정보의 기존 `메모` 제목은 `학생 공통 메모`로 명확히 한다.
  기존처럼 포커스를 벗어나면 저장하고, 저장 후 차시 명단의 공통 메모도 다시 조회한다.
- 새 강의 메모는 활성 직원(owner/admin/staff/teacher) 전용이다. 학생·학부모 화면에
  새 메모를 추가하지 않는다. 기존 학생 공통 메모의 기존 공개 범위는 변경하지 않는다.

## 저장·충돌·실패 복구

1. 편집창 진입 시 `GET /enrollments/{id}/`로 최신 내용과
   `lecture_memo_updated_at`을 읽는다. 실패 시 `다시 불러오기`를 제공한다.
2. 최대 2,000자, 줄바꿈·공백을 그대로 유지하며 명시적으로 `저장`한다. 빈 문자열을
   저장하면 해당 강의 메모만 비워진다.
3. `PATCH /enrollments/{id}/lecture-memo/`에 `{lecture_memo}`와
   `X-Expected-Updated-At`을 보낸다. 일반 수강등록 수정의 수납·알림 흐름을 호출하지 않는다.
4. 저장 중 중복 제출과 닫기를 막고, 실패하면 작성 내용을 그대로 유지하며 재시도한다.
   성공 응답으로 해당 수강등록의 캐시된 명단을 먼저 갱신하고 재조회하여, 재조회 실패가
   확인된 저장값을 이전 값으로 되돌리지 않는다. 다음 차시도 최신 값을 읽는다.
5. `409 stale_resource`이면 내 초안을 보존한 채 최신 서버 메모를 별도로 보여 준다.
   직원이 `최신 메모 확인 · 계속 편집`을 누른 후 내용을 합쳐 다시 저장한다.
   자동 덮어쓰기는 하지 않으며 최신 내용 조회 실패도 재시도할 수 있다.
6. 저장하지 않은 변경이 있는 상태에서 닫으면 폐기 여부를 확인하고 새로고침·창 닫기는
   브라우저 경고를 표시한다. 앱 내부 이동 후 곧바로 돌아왔을 때는 tenant+직원+수강등록
   범위의 메모리 캐시에서 초안과 원래 수정 시각을 복원한다. 명시적 폐기·저장 시 제거하며,
   새로고침을 수락하거나 로그아웃·인증 만료로 캐시가 초기화되면 복구되지 않는다. 브라우저 저장소에 학생
   메모를 복제하지 않는다.

## 반응형과 검증

가로 열을 더하지 않고 명단 하단 보조 행을 사용한다. 1366/1100px 및 390px에서
미리보기 폭을 화면 안으로 제한하고 긴 한국어·공백 없는 문자열·줄바꿈을 처리한다.
공용 모달, 버튼, 포커스 표시를 사용하며 배경 전환은 reduced-motion 설정을 따른다.

`e2e/admin/student-lecture-memo.mock.spec.ts`가 저장→새로고침→다음 차시, 다른 강의
독립성, 학생 공통 메모 보존, 조회/저장 실패 후 재시도, 빈 값 저장, 동시 수정 충돌,
staff 역할 모바일 명단·출석 체크 화면을 검증한다. 실제 tenant/역할 접근 제어는
백엔드 테스트와 격리된 개발 환경의 실사용 검증으로 확인한다. route mock은 실서버
권한 검증의 대체 근거가 아니다.

배포는 백엔드 additive migration/API 제공 후 프론트엔드를 반영한다. 구버전
프론트엔드는 새 필드를 사용하지 않으므로 기존 학생 메모와 출결 동작을 유지한다.
