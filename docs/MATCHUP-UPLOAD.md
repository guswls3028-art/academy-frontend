# 매치업 자료 업로드

관리자·교직원은 `/workspace/storage/matchup`에서 참고 자료 또는 학생 시험지를
선택해 업로드한다. 빈 목록에서도 같은 업로드 창을 사용한다. 여러 파일의 별도
업로드는 순차 처리하며 각 파일의 진행·완료·실패를 표시한다.

시험 회차는 1학기 중간·기말, 2학기 중간·기말, 모의고사, 기타와 미지정으로 구분한다.
회차와 연도를 업로드 요청에 함께 보내 검증·저장한다. 별도 메타 요청의 실패를 무시한 채
완료로 표시하지 않는다. 저장 실패 시 입력·파일을 보존하고 기존 재시도 흐름을 사용한다.
학교별 적중보고서 목록은 학교명, 연도 내림차순, 1학기 중간·기말, 2학기 중간·기말 순이다.
기존 중간·기말 자료는 값을 보존하며 `학기 미지정`으로 표시한다. 학기를 자동 배정하지 않는다.
새 회차를 저장하고 같은 `/matchup/documents/{id}/pages/` 경로의 POST로
`page_index`의 선택 페이지를 준비하는 백엔드가 먼저 반영되어야 한다.

업로드와 분석 완료에 따른 문서 목록의 갱신은 열려 있는 업로드 창을 다시 만들거나
닫지 않는다. 제목·분류·선택 파일·진행 상태를 유지하고, 전체 업로드가 완료됐을
때 기존 동작대로 창을 닫는다. 부분 실패는 창에 남아 실패한 파일을 확인할 수 있다.
선택 문서와 다른 편집 창도 목록의 일시적인 조회 오류 때문에 초기화하지 않는다.

처음 목록 조회가 실패하면 빈 저장소로 표시하지 않고 재시도 안내를 보여준다.
기존 목록이 있는 상태에서 갱신이 실패하면 마지막 목록과 작업을 유지하고 실패 및
재시도 버튼을 표시한다. 업로드 실패는 해당 파일에 표시하며 서버에 저장된 자료는
삭제하지 않는다. 이번 변경은 이전에 사라진 브라우저 작업을 복원하지 않는다.

분석 진행률은 최근 처리 중 문서 최대 8개를 병렬 조회하고, 응답이 끝난 뒤
3초 후 다시 조회한다. 느린 요청 위에 다음 요청을 겹쳐 쌓지 않는다. 작업박스의
매치업·공개용 정리·분석 준비 조회도 작업별로 한 요청만 진행한다. 화면 이탈 시
진행 요청을 취소하고, 학원·로그인 세션이 바뀐 뒤 도착한 응답은 진행률·완료 알림·
목록에 반영하지 않는다. 실패·입력 거부·검수 필요 등 종료 상태에서는 저장된
문서 목록을 갱신해 기존 직접 자르기·재시도 경로를 사용할 수 있게 한다.
조회 실패는 자동으로 원본을 다시 제출하거나 수동·승인 문항을 변경하지 않는다.
작업박스는 `403/404`나 DB 조회까지 끝난 뒤의 `UNKNOWN`을 계속 진행 중으로 표시하지
않는다. 작업 없음·권한 확인 안내와 함께 조회를 종료하고 원본 화면에서 상태 확인 또는
목록 제거를 허용한다. 일시적인 통신·서버 장애와 요청 제한은 다음 간격에 재시도하며,
학원·계정 전환 전 요청의 늦은 실패는 새 범위의 작업 상태를 바꾸지 않는다.
문서 화면도 같은 영구 오류에서 해당 작업의 자동 조회를 멈추고 문서 목록을 한 번 갱신한다.
이전 진행률 대신 `상태 확인 불가`를 표시하며, 이미 저장된 문항은 계속 보여준다.
`상태 다시 확인`은 목록과 진행률을 새로 읽는 동작이며 분석을 재제출하거나 문서의
서버 상태·수동 문항을 변경하지 않는다. 다른 정상 작업과 일시 장애의 조회는 계속된다.
지연·취소·계정 전환·종료 상태 회귀는 `scripts/tests/ai-job-lifecycle.test.mjs`가 검증한다.

격리 개발 실사용에서는 Setup이 확인한 일회용 QA tenant의 PNG 페이지·문항 크롭만
짧은 서명 URL로 읽는다. 개발 bucket·정해진 경로·최대 1시간 서명·이미지 GET을
검증하며 인증 헤더·쿠키·redirect·다른 tenant·운영 bucket은 허용하지 않는다.
실제 PNG 응답을 검증해 그대로 전달하고 원본 PDF나 다른 외부 요청을 허용하지 않는다.
이 검증 전송 경계는 `e2e/helpers/releaseApiBoundary.ts`와
`scripts/tests/release-omr-image-boundary.test.mjs`가 소유하며 제품의 접근 권한은 바꾸지 않는다.

API·자료 저장·접근 권한과 tenant 경계는
[백엔드 매치업 정책](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/matchup.md)을 따른다.
새 저장 방식이나 권한 변경은 없다. 창의 너비·스크롤과 기존 상호작용을 유지한다.
보고서의 학원 전체 목록·게시 관리와 AI 자동분리 검수 진입점은 현재 `tenantRole`이
`owner/admin`일 때만 제공한다. 전역 `is_superuser` 표시가 남은 강사도 본인 보고서
목록과 기존 자료 편집 흐름을 사용하며, 서버에서 거부될 관리자 검수 버튼을 표시하지
않는다. 분리 검수 탭·직접 주소도 같은 역할을 적용한다. 일반 직원은 자료 저장소의
파일 탭으로 진입하며 매치업·적중 보고서·분리 검수 탭을 표시하지 않는다. 이전
즐겨찾기도 해당 역할이 사용하는 기본 탭으로 이동한다. 서버 권한이 정본이며 이
화면 교정은 보고서·공개 자료를 변경하지 않는다.
`e2e/admin/matchup-role-boundaries.mock.spec.ts`는 1366/390px에서 역할별 목록·탭 전환·
reload, 관리자 검수 진입/닫기와 강사 본인 보고서 접근을 검증한다.
390px에서는 문서 목록이 본문에 밀려 높이 0으로 축소되지 않도록 하여 업로드
버튼을 실제로 누를 수 있게 유지한다.

직접 자르기는 AI 분석의 성공 여부와 관계없이 선택한 원본 페이지만 준비한다.
페이지 준비·캐시 저장은 명시적 POST로 실행하고, 뒤따르는 GET은 저장된 캐시와
임시 URL만 조회한다. 미준비 페이지의 GET은 `409 pages_not_prepared`를 반환한다.
전체 페이지가 필요한 검수·페이지 상태 화면도 같은 helper의 POST 준비→GET 조회를
사용하며 기존 전체 페이지 응답을 유지한다. 새 백엔드를 먼저 적용한 전환 단계에서
기존 프론트의 이미 준비된 캐시는 GET으로 조회할 수 있지만, 새 프론트까지 반영되기
전의 cold-cache 자르기 성공은 보장하지 않는다. 혼합 버전은 별도 배포 검증 대상이다.
첫 페이지를 열기 위해 다른 페이지의 렌더링·업로드를 기다리지 않는다. 페이지 번호를
누르면 해당 페이지를 요청하고 준비된 이미지를 재사용한다. 실패 시 로딩을 멈추고
`페이지 다시 불러오기`를 제공하며 닫기·붙여넣기·기존 저장 문항을 유지한다.
요청 취소는 닫기·페이지 이동에 연동된다. 데스크톱 3열과 390px의 페이지→영역→번호→저장
순서를 유지하며 준비가 끝난 뒤 조회가 취소돼도 이후 다시 열기는 저장된 캐시를 재사용한다.
닫힌 창에는 늦은 응답을 반영하지 않는다. 준비·조회 실패 모두 같은 가시적 재시도로
복구하며 자르기 저장 전에는 문항이 생성되지 않는다.
자르기 저장 후 재조회·새로고침에서도 문항과 문항 번호를 유지해야 한다.

`e2e/admin/matchup-upload-retention.mock.spec.ts`는 1366px와 390px에서 빈 목록의
첫 파일 등록, 반복 갱신, 조회 실패 중 입력·파일·진행 상태 보존, 전체 완료 후 닫힘,
재조회 시 저장 자료 표시를 검증한다. 이 회귀 검증은 로컬 API mock이며 실제 저장소
연결 검증과 운영 배포 게이트는 [배포 계약](DEPLOYMENT-OPERATIONS.md)을 따른다.

추가 격리 실사용 스펙 `e2e/admin/matchup-isolated-realuse.spec.ts`는 합성 2문항
참고자료·시험지를 UI에서 등록하고 실제 분석, 수동 자르기, 보고서 후보 선택·자동저장,
새로고침 복구와 PDF 다운로드를 확인한다. 1366/390px 화면과 각 단계의 처리시간도
기록한다. 운영 조회·mock suite에는 포함하지 않으며, 고정 QA Setup에서 받은 정확한
tenant와 API release/digest, 프론트 후보 SHA, 합성 PDF hash에 묶인 일회용 dispatch plan이
있어야 실행된다. 분석 등록 2회와 수동 자르기 1회를 전송 전에 각각 예약하므로 응답을
잃은 작업을 같은 계획으로 재전송하지 않는다. 생성 문서·AI job·보고서 ID는 테스트
artifact에 남기고, 실행 소유자가 고정 Cleanup→독립 Inspect의 잔여 0을 확인한다.
이 스펙의 준비·발견 성공은 실제 개발환경 통과 증거를 대신하지 않는다.

적중 보고서 편집기는 900px 이하에서 문항 목록→시험·자료 비교와 코멘트→후보 선택을
세로로 배치한다. 제목과 저장·다운로드·게시·닫기 동작은 줄바꿈하여 유지하고, 보고서
요약은 하단에 유지한다. 넓은 화면은 기존 3열 비교를 사용한다. 모바일에서도 코멘트와
선택 자료를 저장하고 새로고침 후 복구하며 PDF를 다운로드할 수 있어야 한다.
`matchup-mobile-touch-parity.mock.spec.ts`가 390/1366px의 실제 코멘트 입력 폭,
후보 선택, 자동저장, 재열기, 다운로드와 닫기를 검증한다. 진입 모션은 버튼 위치를
움직이지 않는 160ms 페이드이며 reduced-motion 설정을 존중한다. 반응형 배치는 보고서
권한·게시 정책·저장 데이터 형식을 바꾸지 않는다.
