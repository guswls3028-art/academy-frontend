# 알림톡 문구·발송·기록 화면

## 자동발송 설정 저장과 복구

관리자 메시지 → 자동발송과 클리닉·커뮤니티 등의 자동발송 설정 패널은 같은
테넌트·로그인 사용자 범위의 편집 상태를 공유한다. 토글과 발송 시점 변경은
`PATCH /messaging/auto-send/`에 저장하며, 숫자 입력은 마지막 편집 뒤 600ms에
저장한다. 화면을 떠나도 대기 중인 저장은 이어지고, 돌아오면 미저장 변경값을
서버 조회 결과 위에 표시한다. 한 번에 하나의 저장 요청만 보내며, 요청 중에
추가한 변경은 앞선 응답 후에 저장한다. 저장 중 시작된 조회는 PATCH 성공 후
취소하고 서버가 반환한 저장 결과를 캐시에 반영한 뒤 미저장 편집을 해제한다.
늦게 도착한 이전 조회가 저장된 값을 덮어쓰지 않는다.

저장 실패 시 변경값을 유지하고 화면에 오류와 **다시 저장**을 표시한다. 다시
저장에 성공하면 새로고침 후에도 서버 값이 보인다. 조회 갱신이나 실패 응답은
미저장 입력을 되돌리지 않는다. 로그아웃·세션 만료·다른 탭에서의 계정 전환은
대기 중인 편집을 폐기하고 브라우저 요청을 취소하며, 이후 응답을 적용하지
않는다. 이미 서버가 완료한 저장까지 되돌리지는 않는다. 다른 테넌트나
사용자에게 편집 내용을 보여주지 않는다. 설정 저장은 공급자 발송 요청을
만들지 않는다.
권한과 설정값의 최종 검증은 서버가 담당한다. 데스크톱과 좁은 화면에서 오류
안내와 재시도 버튼을 설정 위에 표시한다.

검증은 자동발송 브라우저 회귀에서 편집 → 이동 → 저장 실패 → 복귀 → 재시도
→ 새로고침, 요청 중 추가 편집의 직렬 저장을 확인한다. 별도 저장 계약 회귀는
PATCH 중 시작한 오래된 GET의 늦은 응답과 로그아웃·테넌트 전환 시 미발송
편집 폐기를 확인한다.

## 문구 관리와 편집

관리자·교직원의 메시지 → 문구 편집(`/workspace/message/templates`)은 테넌트가
저장한 `GET /messaging/templates/` 문구를 관리한다. 목록은 내 문구를 먼저 보여주고,
`is_user_default`는 **발송 기본**, 자동발송 설정의 `template` 참조는 **자동발송
설정에 연결**로 구분한다. 연결 표시는 해당 자동발송의 활성화나 과거 발송 이력을
뜻하지 않는다. 연결되지 않은 시스템 제공 문구는 접힌 참고 영역에 보존한다.
이전 기본 문구와 직접 작성한 문구를 삭제하거나 일괄 덮어쓰지 않는다.
카테고리 안에서 이름·본문을 검색할 수 있고 연결 상태 조회 실패는 재시도를 제공한다.
카드의 수정·보기는 텍스트 버튼으로 표시하고, 제공 문구 복원은 사용 안내 안에 둔다.

발송 모달과 문구 수정 모달은 동일한 안내문 편집기를 사용한다. 이름·강의·성적 등의
변수는 글자처럼 부분 편집되지 않는 블록으로 넣는다. 선택·삭제·복사·붙여넣기,
Ctrl/⌘+Z, Ctrl/⌘+Shift+Z, Ctrl+Y와 실행 취소·다시 실행 버튼을 지원한다.
줄바꿈과 한글 일반 텍스트를 유지하고 외부 서식은 붙여넣지 않는다. 저장 API와 기존
문구 데이터는 `#{변수}` 형식을 유지하므로 기존 양식과 발송 변수 계약은 호환된다.
시스템 제공 양식은 기존 읽기 전용/복제 정책을 유지한다. 권한과 테넌트 범위는 서버가
판정하며 승인 알림톡 본체나 채널을 편집기로 변경하지 않는다.

발송 시 저장한 내 문구를 먼저 선택하고 **이 문구로 작성하기**로 편집에 들어간다.
**변경 내용 저장**은 선택한 사용자 문구를 업데이트하고 **새 문구로 저장**은 새 행을
만든다. 저장 실패 시 입력을 유지하며 저장 성공 후 목록 캐시를 갱신한다. 수신자별
사전 검증과 최종 확인 절차는 유지하며 저장만으로 메시지를 발송하지 않는다.
작성 화면의 **발송 가능 상태**는 수신자·문구·예약 시각의 자동 검사 결과다.
작성 중 **현재 발송 문구**는 같은 입력으로 호출한
`POST /messaging/send/preflight/`의 첫 발송 가능 학생 `full_message_body`만 보여준다.
본문·대상·예약 시각이 바뀌면 이전 결과를 숨기고 다시 확인한다. 조회 실패는 오류와
**다시 확인**을 제공한다. 편집 화면이나 문구 선택 팝업에서 보이는 이름·날짜 등의
배치는 예시이며, 수신자별 실제 문구로 표시하지 않는다.
하단 발송 버튼을 누르면 **보내기 전 마지막 확인**에서 받는 사람과 실제 문구를
다시 보여주며, 그 화면의 **발송하기**를 눌러야 발송 요청을 접수한다.
**돌아가기**로 작성 화면에 돌아오면 발송되지 않고 편집 내용은 유지된다.

## 선생님 앱의 문구 수정과 단계별 발송

교직원은 **자료·메시지 → 알림톡 문구 관리**
(`/workspace/mobile/message-templates`)에서 테넌트의 저장 문구를 만들고 수정한다.
시스템 제공 문구와 카카오 승인 봉투는 읽기 전용이다. 학생 목록에서 학생을 선택해
**알림톡**을 누르면 저장한 사용자 문구를 불러오거나 새 안내문을 직접 작성할 수 있다.
저장 문구를 불러온 뒤 수정한 내용은 이번 발송에만 적용되고 원본 저장 문구는 바뀌지
않는다. **저장 문구 만들기·수정하기**는 관리 화면으로 이동한다. 내부
`#{선생님메모}` 토큰은 편집 문구에서 숨기되, 이름 등의 사용자 변수는 유지한다.

발송 흐름은 **수신자·종류·시점·안내문 작성 → 실제 문구 확인 → 발송 확정**이다.
종류는 승인된 출석·클리닉 안내 봉투를 고르고, 자유롭게 쓴 안내문은 그 봉투의
선생님 메모에 들어간다. 학생별 성적 본문이 필수인 성적 봉투와 변경 전후 일정이
필수인 클리닉 변경 봉투는 이 일괄 발송창에서 선택하지 않는다. 기존 저장 문구는
그대로 보존하고 전용 성적·클리닉 업무에서 사용한다. 특히 성적 안내는 관리자 성적
발송에서 학생별 결과를 구성한 뒤 진행한다. 작성 화면은 채널 선택을 요구하지 않는다. 교직원이
`GET /messaging/templates/`로 문구를 읽고, 같은 스냅샷 입력을
`POST /messaging/send/preflight/`와 `POST /messaging/send/`에 전달한다.
사전 확인에서 `preview_recipients`가 수신자 수와 맞고 발송 대상의
`full_message_body`가 있어야 마지막 확인으로 넘어간다. 학생을 바꾸면 서버가
조립한 해당 학생의 전체 문구·마스킹 번호를 확인할 수 있다. 연락처가 없어 제외된
대상과 중복 번호 건수도 표시한다. **문구 수정**은 입력을 보존하며 발송하지 않는다.

저장 문구 조회 실패는 직접 작성과 재시도를 허용한다. 사전 확인 실패·차단·미리보기
누락은 발송을 막고 이유를 보여준다. 발송 요청 결과를 확인하지 못하면 자동 재시도하지
않고 발송 내역 확인 경로를 제공한다. 본문·개인정보와 전송 가능 여부는 서버가 최종
판정하며 화면은 다른 채널로 대체하지 않는다. 데스크톱과 390px 바텀시트에서
작성·학생 선택·전체 문구·확정 버튼에 가로 넘침 없이 접근할 수 있어야 한다.
검증은 `e2e/teacher/alimtalk-compose-preview.mock.spec.ts`의 저장 문구 선택,
이번 발송 수정, 사전 확인 실패 복구, 학생별 문구, 최종 요청 동선을 따른다.

## 성적 안내와 실제 데이터 미리보기

양식 선택 팝업의 배치 예시는 현재 학원명과 첫 선택 학생의 이름·강의·차시·성적을
사용할 수 있다. 본문을 바꾸거나 다른 양식을 선택하면 학생별 치환 함수로 다시 계산하지만
서버에서 확정한 발송 문구는 아니다. 작성 화면과 최종 확인은 서버 응답을 사용한다.
학원명은 사이트 브랜드명이 아니라 `/core/subscription/`의 `tenant_name`을 사용해
실제 발송의 `Tenant.name`과 맞춘다. 테넌트 코드별 캐시를 사용하고 조회 실패 시
다시 확인할 수 있으며, 다른 학원이나 브랜드명으로 대체하지 않는다.
학원플러스·홍길동 같은 예시값을 발송 문구로 표시하지 않는다. 학생을 아직
고르지 않은 문구 관리에서는 정보 이름/자동 입력 블록을 보여준다. 최종 발송 내용과
발송 가능 여부는 기존 서버 preflight 응답으로 수신자별 확인한다.

`숙제완성도`와 `전체요약`의 과제 완료 수는 서버 `correction_status`가 `COMPLETED`
또는 `NOT_REQUIRED`인 과제만 센다. `PENDING` 또는 확인되지 않은 상태는 완료로
세지 않으며 점수 입력, 합격 여부만으로 완료를 추정하지 않는다. 예를 들어 80/70/80점인
세 과제가 모두 교사 미완료라면 **0/3 완료**다. 기존에 발송된 메시지/로그는 변경하지
않고 새로 계산하는 미리보기와 발송 본문부터 적용한다.

데스크톱에서는 편집과 미리보기를 나란히, 좁은 화면에서는 편집을 먼저 배치한다.
사용하지 않는 제목 영역은 공간을 차지하지 않는다. 목록·요약 블록을 먼저 보여주고
시험·과제 번호별 블록은 **시험·과제별 정보 더 보기**에서 펼친다. 자동으로 채워지는
정보는 삽입 버튼과 구분되는 읽기 전용 이름·값 목록으로 표시한다.
성적 발송창도 390px에서는 수신자·발송 시점을 고른 뒤 작성하고 긴 미리보기를 확인한다.
변수 목록은 별도 스크롤 영역에 가두지 않고 모달 본문과 함께 스크롤한다.
본문 편집과 수신자 확인, 저장·발송 버튼에 접근할 수 있어야 한다.
검증은 `message-template-editor.mock.spec.ts`의 블록·단축키·clipboard·저장/재조회,
`score-alimtalk-personalization.mock.spec.ts`의 학생별 미리보기/발송·실패 복구,
`score-alimtalk-payload-vars.spec.ts`의 완료 판정과 실제 치환 본문을 사용한다.
발송 정책은 [백엔드 메시징 SSOT](https://github.com/guswls3028-art/academy-backend/blob/main/docs/ssot/messaging-policy.md)를 따른다.

## 목적과 진입점

관리자 앱의 `/workspace/message/log`는 현재 테넌트의 알림톡 처리 이력을 읽는
운영 화면이다. 발송·재시도·재큐잉·공급자 선택 기능은 제공하지 않는다.
제품 메시지는 알림톡만 사용하며 SMS/LMS 또는 대체 발송을 화면에 노출하지
않는다.

소유 화면은
`src/app_admin/domains/messages/pages/MessageLogPage.tsx`이고 API 투영 계약은
`backend/docs/domain/messaging-delivery-log.md`에 있다.

## 정보 구조와 상태 표시

대시보드의 알림톡 상태 카드는 카카오 채널 표식, 현재 준비 상태, 발송 내역과
메시지 설정 진입점을 한 카드에 제공한다. `정상`, `설정 필요`, `확인 중`,
`불러오기 실패` 문구를 항상 함께 표시해 노란색만으로 상태를 판단하지 않는다.
정상 상태는 공용 알림톡 채널과 직접 발송 봉투가 준비됐다는 뜻이다. 자동
안내별 활성화·승인 양식 상태는 메시지 설정에서 따로 확인하며, 정상 카드가
모든 자동 안내의 준비나 개별 메시지의 수신·열람을 보장하지 않는다.

상단 운영 요약은 접수 완료, 진행 중, 확인 필요, 종료 실패를 구분한다. 필터는
전체, 접수 완료, 진행 중, 확인 필요, 실패를 제공하며 `processing`, `sending`,
`retryable_failed`, `failed`, `ambiguous`를 하나의 실패로 합치지 않는다.

- `접수 완료`: 공급자가 알림톡 요청을 접수했다는 뜻이며 수신자의 카카오톡
  열람 완료를 뜻하지 않는다.
- `진행 중`: 발송 준비, 공급자 접수 확인, 자동 재시도 대기 상태를 포함한다.
- `결과 확인 필요`: 결과가 모호하여 중복 방지를 위해 자동 재발송하지 않는
  상태다.
- `발송 실패`: 종료된 실패만 나타낸다.

목록의 `기록 시각`은 모델의 `sent_at`, 즉 로그 행 생성 시각이다. 상세의
`작업자 처리 시작`은 `claimed_at`이다. 공급자 처리 완료 시각은 현재 계약에
없으므로 화면에서 추정하지 않는다.

## 상세와 개인정보

목록은 본문 없이 빠르게 조회한다. 행을 열 때만 상세 API를 호출하고, 서버가
반환한 표시 범위를 그대로 따른다. 상세의 왼쪽은 카카오톡 대화창과 유사한
시각적 미리보기이고, 오른쪽은 상태·처리 시각·공급자 증거를 분리한 운영
기록이다. 미리보기는 저장된 로그를 읽기 쉽게 투영할 뿐 실제 카카오톡 화면,
수신 확인 또는 재발송 기능이 아니다.

- `available`: owner/admin에게 저장된 개인정보 제거 본문 표시
- `sensitive_redacted`: 자격증명·인증 유형이므로 원문이 저장되지 않았다는
  보안 안내 표시
- `restricted`: staff/teacher에게 본문 권한 제한 안내 표시
- `not_recorded`: 저장된 본문이 없음을 표시하며 내용을 추정하지 않음

공급자 증거는 서버가 owner/admin에게 정확한 메시지 ID를 반환하면 운영 대사용
근거로 표시하고, 그 외 역할은 마스킹 참조와 확인 여부만 표시한다. 실패 사유는
서버의 안전한 요약만 사용하고 공급자 원문을 렌더링하지 않는다.

## 반응형·접근성 계약

- 넓은 화면은 운영 레저 테이블, 680px 이하 화면은 카드 목록으로 전환한다.
- 390px에서 문서·목록·상세 모달에 가로 스크롤이 생기지 않아야 한다.
- 상태는 색상만으로 전달하지 않고 텍스트와 아이콘을 함께 사용한다.
- 필터와 행은 키보드 포커스가 보이고, 상세는 제목이 연결된 dialog로 연다.
- 로딩·빈 목록·조회 실패·상세 실패 상태를 분리하고 실패 시 다시 시도할 수
  있어야 한다.

overflow를 고정한다.
