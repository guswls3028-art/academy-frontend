# 선생님 업무 화면 운영 계약

## 목적과 진입점

선생님 업무 화면은 원장·관리자·강사·직원이 오늘 해야 할 일을 먼저 확인하고
수업, 출결, 학생 소통으로 이어가는 역할별 작업 공간이다. 기본 진입점은
`/workspace/mobile`이며 데스크톱에서는 같은 라우트를 고정 사이드바와 넓은 업무
캔버스로 표시한다.

## 영상 상세 미리보기

- `/workspace/mobile/videos/:videoId`는 영상 상세 응답의 선생님용 재생 주소를 화면
  상단 16:9 미리보기로 표시한다. `source_type=youtube`이면
  `youtube_video_id`를 임베드하고, 그 외 READY 영상은 signed `hls_url`을 네이티브
  HLS 또는 Hls.js로 재생한다.
- 이 미리보기는 업로드 결과를 확인하는 선생님 전용 읽기 흐름이다. 학생 재생
  bootstrap, playback session, 진도 저장 API를 호출하지 않으며 재생해도 학생 시청
  시간·진도·완료 상태를 변경하지 않는다.
- READY인데 재생 주소가 없거나 영상이 처리 중·실패 상태이면 다른 주소를 추정하지
  않고 현재 상태와 다음 행동을 표시한다. HLS 로드 실패는 재시도할 수 있고 YouTube와
  HLS 모두 자동 재생하지 않는다.
- 재생 영역은 390px와 데스크톱에서 가로 넘침 없이 컨테이너 폭을 사용하고,
  `playsInline`, 기본 재생 컨트롤, 전체 화면을 지원한다.

## 오늘 업무의 단일 기준

- 상단 상태 배지, `오늘 업무` KPI, 처리 대기함은 같은 합계를 사용한다.
- 합계는 운영 알림 건수와 오늘 수업의 출결 미입력 학생 수를 더한다.
- 출결 미입력은 처리 대기함에 별도 행으로 표시하며 강의 화면으로 이동한다.
- 합계가 0일 때만 `정리됨`과 빈 대기함을 표시한다. 일부 업무가 남아 있는데
  완료 상태를 표시하지 않는다.
- 운영 알림 집계가 로딩 중이면 `업무 집계 중`, 일부 소스가 실패하면 `업무 확인
  필요`와 재시도를 표시한다. 이 상태에서 임시 0, `정리됨`, 빈 알림센터를 만들지
  않으며, 처리 대기함의 합계·빈 카드도 확정하지 않는다. 성공한 일부 항목이 있으면
  Today·알림센터에서 해당 행을 유지하고, 헤더·상단바·하단탭·메뉴의 전체 배지는
  숫자 합계 대신 `일부` 또는 확인 필요 상태를 표시한다.
- 오늘 수업 조회가 실패하면 수업 0건, 출결 0%, 일정 없음으로 계산하지 않고
  수업 영역에 오류와 재시도를 표시한다. 차시 상세의 수강생·출결·시험·과제·영상·
  클리닉 탭도 해당 탭의 필수 조회가 성공한 뒤에만 빈 상태를 표시한다.
- 우선 행동은 답변 대기 질문, 다른 운영 알림, 출결 미입력, 다음 수업 순으로
  결정한다. `오늘 업무` KPI를 누르면 현재 우선 행동으로 바로 이동한다.
- 사용자 이름이 이미 `님`으로 끝나면 존칭을 중복해 붙이지 않는다. 이름이
  없으면 원장님·관리자님·선생님을 역할에 맞게 표시한다.

운영 알림은 각 백엔드 업무 API가 소유한다. 학원장 상담함은 원장 전용이므로
일반 관리자·강사·직원 세션에서는 해당 API를 호출하지 않으며, 역할별 쿼리 캐시도
분리한다. 출결 진행률은 오늘 차시 응답의 `attendance_filled`와
`attendance_total`을 사용하고 클라이언트가 다른 출결 상태를 추정하지 않는다.

학생 자가 가입이 비활성인 테넌트에서 가입 신청 pending API가
`self_registration_disabled`를 반환하면 해당 소스만 의도적인 0건으로 제외한다.
과거 요청은 서버 감사 이력으로 남지만 Today·알림 뱃지·처리 대기함·CTA에 나타나지
않는다. `/workspace/mobile/comms?tab=requests`나 관리자 가입신청 화면을 직접 열면
정책 변경 전 요청이 보존된다는 안내만 표시하고 승인·거절 동작을 렌더하지 않는다.
자가 가입 사용 테넌트의 가입 신청 CTA는 학생 목록이 아니라 같은 소통 탭으로
이동하며 기존 상세·승인·거절 흐름을 유지한다. 그 밖의 가입 신청 목록 오류는
0건으로 바꾸지 않고 오류·재시도를 표시하며, 성공 응답 전에는 자동 승인 설정과
승인·거절 표면을 열지 않는다. 목록이 성공해도 자동 승인 설정 조회가 로딩 또는
실패 상태이면 기존 값을 `false`로 추정하지 않고 설정 토글을 숨긴 채 별도 재시도를
제공한다. 설정 GET이 성공하기 전에는 설정 PATCH를 보내지 않는다.

## 역할과 결제 경계

- 결제·구독 조회와 등록 카드 조회는 학원장만 사용할 수 있다.
- 관리자·강사·직원에게는 사이드바, 드로어, 빠른 이동에서 결제 메뉴를 노출하지
  않는다. 직접 URL로 진입해도 역할 가드가 화면을 차단하며 카드 API를 호출하지
  않는다.
- 수납과 직원 관리 등 별도 기능의 기존 원장·관리자 권한은 결제 권한과 섞지
  않는다.

구독 정보와 카드 정보는 서로 다른 비동기 상태를 가진다. 카드 요청 중에는 로딩,
성공한 빈 목록에는 `등록된 카드가 없습니다`, 실패에는 오류와 `다시 시도`를
표시한다. 401·403·네트워크 실패를 빈 카드 목록으로 바꾸지 않는다.
학원 정보 조회가 실패하면 빈 학원명을 편집값으로 열지 않으며, 구독 또는 카드 중
하나라도 실패하면 등록·삭제를 잠근다.

## 출결 상태와 반응형 계약

차시 상세는 백엔드 출결 상태 `UNSET`을 내부 코드 대신 `미입력`으로 표시한다.
알 수 없는 새 상태는 데이터 손실 없이 원문을 보이는 기존 호환 경계를 유지한다.

- 1024px 이상 출결 명단은 학생별 `미입력·현장·영상·보강·지각·조퇴·결석·출튀·자료·부재·퇴원`을 한 줄의 빠른 선택 레일로 펼친다. 현재 상태만 의미색으로 채우고 나머지는 회색으로 낮추며, 부재는 보색 윤곽·퇴원은 위험 윤곽으로 놓치지 않게 한다. 선택은 `aria-pressed`로도 구분하고 다른 상태를 한 번 누르면 즉시 저장한다. 상태 변경 전후 학생 행은 같은 정렬 위치를 유지하며, 퇴원은 기존 확인·이력 보존 절차를 유지한다.
- 1023px 이하에서는 학생 한 명당 한 개의 현재 상태 버튼과 가로 선택 팝오버를 사용해 이름·전화번호 공간과 최소 44px 터치 영역을 보존한다.

- 1023px 이하에서는 업무 콘텐츠의 버튼과 `role=button` 조작 영역이 최소 44px다.
- 아이콘 이름만 가진 버튼은 너비도 최소 44px로 유지한다.
- 1024px 이상에서는 고정 사이드바를 사용하고 업무 캔버스는 최대 1320px까지
  확장한다. 1366px에서는 가로 넘침 없이 가용 폭을 채우고 더 넓은 화면에서는
  목록과 오늘 업무 두 열이 불필요하게 좁아지지 않는다.
- 상태 전환 모션은 짧은 색·그림자·이동 피드백만 사용하고
  `prefers-reduced-motion`에서는 제거한다.

## 클리닉 운영 콘솔

- 상단 클리닉 탭은 **오늘 요약 / 일정·배정 / 오늘 출석·진행 / 전체 미통과**로
  역할을 이름에 드러낸다. `/workspace/clinic/operations`는 별도 날짜·세션 링크가 없으면
  **오늘 전체** 예약·배정 학생으로 시작하고, **현장**을 누르면 등원 후 아직 하원하지
  않은 학생만 좁혀 본다. `/workspace/clinic/bookings`는 날짜와 무관한 전체 누적 정리다.
- `/workspace/clinic/bookings`의 **전체 미통과** 기본 화면은 `학생 작업대`다. 서버가 반환한
  tenant-scoped 대상을 stable `student_id`로 묶고 ID가 없을 때만 `enrollment_id`를
  fallback key로 사용해 학생 한 명을 한 행에
  표시하고, 그 학생의 시험·과제 카드를 높이가 늘어나지 않는 한 줄 가로 레일에 모두
  펼친다. 항목이 많아도 다음 학생 행을 밀어내지 않으며 모바일에서도 카드 레일만
  가로로 이동한다. 미해결 항목을 먼저,
  같은 상태에서는 `created_at` 최신순으로 놓으며 학생 행은 미해결 개수 내림차순 뒤
  이름순이다. `점수 일괄입력`은 명시적으로 전환했을 때만 기존 표를 연다.
- 항목 카드는 원본 제목, 시험/과제 유형, 차시, 사유, 점수·기준 또는 미응시/미제출을
  표시한다. `판정 대기`, 시험/과제/수동 통과, 면제, 다음 차수 이월, 원본 항목 삭제를
  서로 다른 상태명으로 유지하며 link 없는 항목이나 조회 오류를 해결 완료·0건으로
  바꾸지 않는다.
- 카드를 누르면 URL과 학생 목록을 유지한 같은 행의 처리 패널에서 원점수와 시도 이력,
  재시험 점수 저장, 통과, 제출 확인·완료, 면제, 다음 차수 이월을 실행한다. 항목 선택은
  `target`, 검색·사유·차시·해결 포함·보기 상태는 각각 query parameter로 보존하므로
  딥링크와 새로고침에서 복원되고 브라우저 뒤로가기는 선택 패널만 닫는다. 닫기나 Esc
  뒤에는 방금 누른 카드에 포커스를 돌린다. mutation 중에는 전체 처리 동작을 잠가
  중복 요청을 막고, 성공 뒤 대상 목록을 다시 읽으며 실패는 재시도 가능한 오류로 남긴다.
- 390px에서는 학생 신원과 처리 패널을 한 열로 재배치하고 항목 카드는 한 줄 가로
  레일로 유지해 문서 가로 넘침을 만들지 않는다. 키보드 포커스와
  `prefers-reduced-motion`도 같은 계약을 따른다.
- 처리 패널의 **예약·운영 연결**은 서버가 `SessionParticipantPlanItem`으로 직접
  연결한 `linked_bookings`만 표시한다. 이름·날짜·제목으로 참가자를 추정하지 않으며,
  각 연결의 날짜·시작/종료·장소·참가 상태·희망 시간·학생 작성 요청·교직원 메모와
  exact plan provenance를 함께 보여준다. 작성 출처가 불명확한 legacy participant
  `memo`는 표시하지 않는다. ClinicLink의 현재 해소 근거와 append-only 처리 이력도
  같은 패널에서 원시험·시도 이력과 분리해 확인한다. 연결이 없으면 “직접 연결된
  예약 없음”으로 표시해 missing link와 empty-success를 혼동하지 않는다.
- tenant 누락/권한 거부를 포함한 대상 조회 403은 진행중 0건이나 모두 통과로 바꾸지
  않는다. KPI를 `—`로 유지하고 명시적 오류와 `다시 시도`를 제공하며, 성공 응답을
  받은 뒤에만 진짜 빈 상태를 표시한다.

- `/workspace/clinic/operations`의 기본 범위는 **오늘 전체**다. 당일 예약·배정·미등원·
  결석 학생까지 먼저 한 처리 큐에서 본다. **현장**을 누르면 16시·17시·18시처럼 여러
  클리닉이 동시에 진행돼도 시간대별 화면을 오가지 않고 현재 등원중인 학생만 좁힌다.
  `전체 시간 / 16:00 / 17:00 / 18:00`은 두 범위 안의 보조 필터다.
- `/workspace/clinic/schedule`은 월간 달력을 기본 탐색으로 항상 표시한다. 이전 달·이번 달·
  다음 달 이동은 이 툴바 하나만 사용하고 중복 주간 이동과 7일 날짜 레일은 두지 않는다.
  날짜를 고르면 아래에는 그날의 시간대 카드만 표시한다. 로딩·실패·빈 날짜를 `0개`로
  반복 표시하지 않고 한 번의 상태 또는 빈 안내로 구분하며, 390px에서도 문서와 카드가
  가로로 넘치지 않는다.
- 단일 세션에서 예약된 학생은 같은 행과 모바일 작업대에서 **일정 변경**과
  **명단에서 빼기**를 실행한다. 일정 변경은 기존 예약을 취소 이력으로 보존하면서 새
  세션 예약을 만들고, 명단에서 빼기는 학생·날짜·시간·장소·보호자 취소 알림을 확인한
  뒤 `cancelled`로 전환한다. 두 동작은 참가자를 hard delete하지 않고 알림톡 요청
  성공·실패를 상태 저장과 분리해 피드백한다. 세션 전체 **삭제**와는 별도 계약이다.
- **현재 등원중**은 서버의 tenant-scoped `onsite_date` 조회가 반환한 당일 참가자 중
  `status=attended`, `checked_in_at` 존재, `checked_out_at` 없음이 모두 성립한 경우만
  표시한다. pagination 응답은 현장과 오늘 전체 모두 `next`를 반드시 포함하며
  `next: null`에서만 종료한다. 다른 날짜·상태, 체크인 누락, 하원 완료, 중복 ID,
  `next` 누락 또는 pagination loop가 섞이면 일부 명단이나 0명을 표시하지 않고 전체
  조회를 실패 처리한다.
  `is_late`는 현장 포함 여부를 바꾸지 않고 `completed_at`도 하원을 대신하지 않는다.
- 열린 예약 승인·출석 진행 화면은 화면이 보이는 동안 참가자·대상·월별 세션 트리를
  10초 간격으로 bounded refetch한다. 백그라운드 탭에서는 주기 요청을 멈추고 로컬
  참가 상태 변경은 참가자와 세션 트리 cache를 즉시 무효화한다. 따라서 다른 기기에서
  생긴 학생 예약도 날짜 토글이나 수동 새로고침 없이 반영된다. **오늘 전체**는 계속
  `session_date_from=오늘&session_date_to=오늘`, **현장**은 `onsite_date=오늘`을 보내므로
  미래 예약은 오늘 수에 섞이지 않는다. pending/booked/cancelled/rejected/no_show는
  서버 참가 상태 그대로 유지하며 클라이언트가 하나의 “예약” 상태로 합치지 않는다.
- 현장/전체 시간 큐의 각 학생 행과 작업대에는 해당 참가자의 실제 세션 시간·장소를
  표시한다. 일정 수정·삭제, 학생 추가, 전체 출석, 변경 알림처럼 한 세션을 전제로 한
  동작은 통합 현장 범위에서 숨기고 단일 세션 범위에서만 허용한다.
- `오늘 출석·진행`은 목록과 작업대를 분리한다. 목록은 학생별 자동 높이 행에 이름,
  현장 상태, `오늘 n / 미완료 n`, 최근순 시험·과제를 같은 크기의 카드 블록으로
  표시한다. 긴 제목과 점수·기준은 행 높이를 늘려 잘리지 않으며 내부 가로 스크롤을
  만들지 않는다. 항목이 4개를 넘으면 최신 4개와 `+n 전체 보기`를 표시하고, 이 버튼은
  첫 숨은 항목을 선택한 전체 작업대를 연다. 항목을 누르면 현재 URL과 목록 위치를
  유지한 채 그 항목 하나만 처리하는 작업대가 열린다.
- 같은 tenant-scoped `student_id`가 여러 클리닉 participant에 있어도 목록은 학생 한
  줄만 표시한다. 이름 문자열로는 절대 합치지 않는다. 각 시간·장소 칩은 실제
  participant를 가리킨다. 당일 기록 중 `pending/booked/no_show/attended` 상태가 정확히
  하나면 같은 날의 취소·거절 기록이 함께 있어도 그 유효 participant로 행의 승인·출결·
  하원 동작을 연결한다. 유효 participant가 둘 이상이면 `처리할 시간대를 선택하세요`를
  표시하고 시간대를 명시 선택하기 전까지 참가자 단위 동작을 잠근다. 취소·거절 기록만
  있으면 진행 rail과 동작을 숨기고 처리할 수 없는 이유를 행에 표시한다.
- 달력과 수업 목록은 상단 **일정** 버튼의 오버레이로 연다. 오버레이가 학생 큐를
  밀거나 목록 위치를 바꾸지 않으며 Esc로 닫으면 일정 버튼에 포커스를 돌린다.
- 작업대에서 `오늘은 이 항목 처리`를 켜거나 끄면 해당 참가자의 유효한
  `planned_clinic_link_ids` 전체를 한 번에 교체한다. 저장 성공 응답으로만 화면을
  갱신하고, 실패하면 기존 선택을 보존한 채 오류를 알리고 서버 상태를 다시 읽는다.
  오늘 할 범위는 해당 클리닉 일정에만 속하며 등원·하원·세션 완료와 별개다. 같은
  학생·수강에 참가자가 둘 이상이면 planned owner 또는 유일한 참가자 문맥이 없을 때
  첫 참가자를 추정하지 않는다. 사용자가 시간대를 고른 뒤 exact participant ID로만
  저장하고 참가자 목록을 다시 읽는다. 유효한 항목 DOM 식별자는 stable
  `clinic_link_id`를 쓰고, 링크가 아직 없는 `NOT_SUBMITTED` 시험은
  차시·수강·source type·시험 ID 조합으로만 구분하며 오늘 할 범위에는 넣지 않는다.
- 작업대는 미완료 항목 전환, 현재 항목 점수 입력, 수동 통과·면제·다음 차수 이월,
  현장 상태, 세션 처리 완료를 한 화면에서 제공한다. 항목 전환은 선택 항목 하나의
  입력만 바꾸며 강의·시험 화면으로 이동하지 않는다.
- 미제출 과제를 학생이 온라인·문자 사진·현장에서 별도로 제출한 경우에는 출석을
  먼저 바꾸지 않고도 해당 과제의 **온라인·문자 제출 확인·완료**를 실행할 수 있다.
  카드와 확인 폼은 원본 과제명을 첫 정보로, 강의·차시를 보조 문맥으로 표시하며
  확인 경로를 2자 이상 기록한다. 기존 과제 ClinicLink 완료 API 뒤 대상 목록을
  다시 읽어 해당 항목이 실제로 해소된 경우에만 성공으로 알린다. 이 동작은 출결,
  하원, 세션 완료를 변경하지 않는다. 점수가 아직 없는 과제도 이 경로를 사용하고,
  실제 점수가 저장된 score target만 일반 수동 통과를 유지한다. `NOT_SUBMITTED`
  시험은 같은 수동 완료를 제공하지 않고 면제로만 해소한다. `clinic_link_id`가 없어도
  exact 차시·수강·시험 식별자가 모두 유효할 때는 사유 2자 이상을 받아 전용 면제 API를
  사용하며, 재시험·이월·일반 통과는 양수 link ID가 없으면 fail-closed한다.
- 시험·과제 대상 조회 중이나 오류일 때는 참가자 사유를 미완료 합성 항목이나
  자율 학습으로 바꾸지 않는다. 개수는 `—`로 두고 로딩 또는 오류·재시도를 표시한다.
- 클리닉 참가자의 현장 상태는 `미등원 → 등원/지각 등원 → 하원` 순서다. 정상 하원은
  실제 `checked_in_at`을 보존해 `arrival_recorded`로 기록한다. 등원 처리를 놓친 확정
  예약 학생은 **미등원 하원**에서 현재 학생·일정을 다시 확인한 뒤 하원 시각만
  `arrival_not_recorded`로 기록한다. 이 예외는 `status`나 `checked_in_at`을 만들지 않으며,
  반복 실행은 기존 하원 시각을 다시 쓰지 않는다.
- 결석으로 먼저 처리한 학생이 늦게 도착하면 `지각 등원`으로 정정한다. 결석 확인
  팝업은 Enter로 실행하고 Esc로 닫을 수 있다.
- 등원·결석은 학생/학부모/둘 다 중 알림톡 수신자를 선택한다. 하원은 exact 승인
  봉투가 없어 수신자 선택과 알림 요청을 노출하지 않는다. 승인된 exact
  템플릿이 없으면 SMS/LMS나 다른 trigger로 대체하지 않는다. 상태 저장 성공과 알림톡
  요청 성공은 별도 결과다. 응답의 `notification.failed`가 1건 이상이면 저장된 상태를
  다시 읽되 `발송 완료`로 표시하지 않고 요청·실패 건수를 경고한다. 재촉의 503 상세는
  확인창을 유지한 채 표시하고, 일부 제외가 있는 200 응답도 완전 성공으로 숨기지 않는다.
- 재촉은 1회 또는 사용자 지정 간격 반복이며 반복 종료는 같은 날 22:00 이하다.
  등원·결석·하원 처리 뒤에는 해당 참가자의 아직 실행되지 않은 수동 재촉을 취소한다.
- 결석 처리 뒤에는 같은 조회 기간의 다른 클리닉으로 옮기거나 새 클리닉을 만든다.
  결석 원본 기록은 유지한다.
- 하원(`checked_out_at`)과 자율학습 완료(`completed_at`)는 별도 버튼과 이벤트다.
  하원이 학습 완료를 만들거나 지우지 않는다.
- `/workspace/clinic/msg-settings`의 기록은 클리닉 trigger만 조회해 예약·대기·전송 중·
  공급사 접수·최종 전달·실패·취소·발송 안 함을 구분한다. 저장된 공급사 접수 ID는
  전달 완료가 아니며 사용자가 **최종 상태 확인**을 눌렀을 때만 read-only 확인한다.
  승인 봉투의 고정 문구와 자동 변수는 읽기 전용이고, 공급사가 허용한 안내 영역만
  수정한다. SMS/LMS fallback과 미지원 하원 설정은 표시하지 않는다.
- 390px에서는 `현장 / 오늘 전체`와 시간대 필터를 각각 한 줄 가로 레일로 유지하고,
  **일정** 오버레이를 전체 높이로 연 뒤 월 달력을 이전/다음 날짜 전환기로 줄인다.
  클리닉 상단 탭도 줄바꿈하지 않으며 선택 탭을 자동으로
  보이게 한다. 상태 필터는 필요한 만큼 줄바꿈하고, 시험·과제는 학생 행 안에서 2열로
  자동 확장하며 `학생 작업대 열기`를 명시적으로 제공한다. 문서와 학생 행, 항목 카드,
  작업대 전환 목록에는 가로 넘침이나 제목 잘림이 없어야 한다. 작업대의 등원·재촉·
  결석·하원·일정·명단 동작은 2열로 배치해 각 버튼을 44px 이상으로 유지하고, 한국어
  라벨을 글자 단위 세로줄로 쪼개지 않는다.
- 일반 성공·경고 message toast는 정보만 전달하고 아래 모달·작업대의 pointer input을
  가로막지 않는다. CTA가 있는 notification만 자체 버튼 입력을 유지한다.
- 작업대는 모달 포커스를 가두고 Esc로 닫은 뒤 방금 누른 항목에 포커스를 돌린다.
  `prefers-reduced-motion`에서는 드로어·항목 피드백 모션을 제거한다.
