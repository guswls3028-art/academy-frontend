# PC·모바일 공통 업무 계약

## 진입과 화면

원장·관리자·강사·직원이 `/` 또는 `/workspace`로 접속하면 화면 폭, 운영체제,
standalone 여부, 이전 PC 화면 선호값과 관계없이 `/workspace` 공통 업무로 진입한다.
같은 계정은 PC와 휴대폰에서 같은 라우트·컴포넌트·API·권한 메뉴를 사용한다.
1023px 이하에서는 사이드바가 드로어·하단 메뉴로 바뀌며 업무 내용과 동작은 유지한다.
PC 헤더의 근무 중인 직원·근무시간·본인 출퇴근 조작도 모바일 메뉴의 근무 현황에서
같은 컴포넌트로 제공하며 클릭·터치로 직원 상세 시간을 확인한다. 모바일 헤더의
간편 출퇴근 버튼도 유지한다. 학생 검색은 양쪽 모두 이름·아이디·전화번호·학교 범위를 안내한다.
폭 변경만으로 현재 경로·편집 상태를 다른 앱으로 옮기지 않는다.

학생·학부모는 기존 공통 `/student` 라우트를 사용한다. 역할이나 테넌트의 권한,
기능 플래그를 화면 크기로 확대하거나 우회하지 않는다. 메뉴 정본은
[WORKSPACE-NAVIGATION.md](WORKSPACE-NAVIGATION.md), 경로 호환은 [ROUTING.md](ROUTING.md)다.

교직원 설치 manifest는 기존 `/teacher` 앱 ID와 학원 브랜드를 유지하고 시작 경로와
scope를 `/workspace`로 사용한다. 공통 업무 화면도 같은 manifest와 설치 메타데이터를
주입한다. 기존 `/workspace/mobile` 주소·북마크·간편 입력 동선은 호환 유지한다.
이 화면은 사용자가 명시적으로 여는 간편 업무이며 기기 폭에 따른 기본 화면이 아니다.
전체 업무/간편 업무 간 복귀 정보는 기존 계정·테넌트 분리와 만료·검증 규칙을 유지한다.
기존 service worker의 `/workspace/mobile` 범위와 API 캐시 정책은 확대하지 않는다.
열린 앱의 입력·재생을 강제 새로고침하거나 사용자 데이터를 이관하지 않는다.

## 상태와 선택지의 정본

| 영역 | 정본 | 소비 화면 |
|---|---|---|
| 출결 | `src/shared/ui/badges/attendanceStatus.ts` | 전체 업무 출결·성적, 간편 출결·차시·현황표, 학생/학부모 출결 |
| 영상 처리 | `src/shared/api/contracts/videos.ts` | 전체 업무 영상, 간편 영상 목록·필터·차시 영상 |
| 제출 처리 | `src/shared/product/submissions/status.ts` | 전체·간편 제출함 |
| 수납 상태·비목·결제 수단 | `src/shared/product/fees/feesStatus.ts` | 전체 업무 수납·청구·비목 설정, 간편 수납·청구 |

출결의 `PRESENT/ONLINE/RUNAWAY/MATERIAL/INACTIVE`는 각각 현장/영상/출튀/자료/부재다.
간편 출결도 PC와 동일한 11개 상태와 순서를 제공한다. 한 글자 표시는 공통 약칭을
사용하고 현황표는 전체 이름을 접근성 라벨로 제공한다. 기존 enum과 저장값은 바꾸지
않으며 학생·학부모 화면의 합산 출석 수는 서버 집계를 그대로 사용한다.

퇴원은 PC와 동일한 범위 선택창에서 차시/강의 전체와 영향을 확인한 후에만 요청한다.
취소하면 쓰지 않는다. 강의 전체 퇴원은 다른 차시·수강·성적 캐시도 갱신하며 단일
출결 상태 되돌리기를 전체 강의 복구로 제시하지 않는다. 이전 퇴원 상태로 되돌리는
작업도 명시적인 범위를 확인한다. 기존 성적·출결·시청 이력 보존은 서버 계약을 따른다.
저장 실패에는 오류가 보이고 기존 값·재시도 동선이 유지된다. 현황표 조회 실패는
빈 목록으로 표시하지 않고 재시도한다. 단축 선택은 390px에서 줄바꿈·스크롤로 모두
접근 가능하며 터치 영역과 감소된 모션 설정을 유지한다.

영상 필터는 업로드 대기·인코딩 대기를 포함한 전체 처리 상태를 제공한다.
제출함은 대체됨과 구버전 처리 상태까지 PC와 같은 이름·톤을 사용한다.
수납 비목은 교재비/판서·프린트/재료비 등 PC 정의를 사용하고 결제 수단의 이름·순서와
기본값(현금)을 공유한다. 금액·청구·결제 API와 멱등성·권한 경계는 변경하지 않는다.

## 검증

- `e2e/root-routing-contract.spec.ts`, `e2e/pwa-branding-contract.spec.ts`: 공통 시작 경로,
  역할·기존 링크·설치 앱 ID와 학원 브랜드.
- `e2e/teacher/full-workspace-parity.mock.spec.ts`: 네 직원 역할의 PC/390px 기본 진입,
  같은 메뉴·목적지, 새로고침·학생 화면 이동·가로 넘침.
- `e2e/teacher/attendance-device-parity.mock.spec.ts`: 390/1366px 전체 상태 선택·저장·reload,
  퇴원 취소·강의 범위 요청, 현황표의 11개 상태와 조회 실패·재시도.
- 기존 출결 save/undo·학생/학부모 이력, 수납·제출·영상 및 업무 복귀 회귀 검증을 유지한다.
- 배포는 동일 산출물 development-canary·cleanup zero와 운영 revision/조회 검증을 따른다.
  합성 route-mock 결과를 운영 쓰기나 실제 API 저장 검증으로 보고하지 않는다.
