# 테넌트 브랜딩 UI 계약

신규 테넌트의 로그인 화면과 로그인 후 공용 헤더를 같은 브랜드로 완성하기 위한
프런트엔드 정본이다. 도메인·운영 DB·대표 계정까지 포함한 전체 절차는 백엔드
`docs/operations/tenants/custom-domain.md`가 소유한다.

## 완료의 정의

로고 파일을 등록하고 로그인 화면에 표시하는 것만으로 완료 처리하지 않는다.

- 로그인: 데스크톱·모바일에서 로고 배경이 페이지나 브랜드 스테이지와 이어진다.
- 내부 화면: 관리자·선생·학생·학부모 상단바에서 같은 브랜드 계약을 사용한다.
- 테마: 라이트·다크에서 로고가 흰색 또는 검은색 헤더 위에 네모 사진처럼 뜨지 않는다.
- 반응형: 1366px와 390px에서 가로 넘침이 없고, 좁은 화면에서는 제목보다 로고를
  우선해 안전하게 축약한다.
- 기능: 홈 이동, 메뉴, 알림, 프로필과 키보드 포커스 동작을 유지한다.

## 학원플러스 브랜드와 로그인

테넌트 1의 기본 로고는 파란 H+ 심벌과 한글 이름을 가로로 조합한다.
`public/tenants/hakwonplus/`의 `logo.png`는 로그인, 관리자 데스크톱 상단바, 프로모션의 머리글·메뉴·바닥글에,
`icon.png`는 역할별 상단바, 개발자 콘솔과 학원플러스 알림톡 미리보기에 사용한다.
상단바는 밝은 브랜드 표면에 심벌을 놓아 라이트·다크 테마에서 모두 식별할 수 있게 한다.
파비콘, Apple 홈 화면, 192·512px 앱 아이콘과 1200×630 공유 이미지는 각각의 표시 비율에 맞춘다.
기존 주소에도 새 이미지를 제공하며 프런트엔드에서 참조하는 주소에는 자산 버전을 붙인다.
기본 브라우저 주소 `/favicon.ico`와 Apple 터치 아이콘 주소는 학원플러스 도메인에서
같은 버전의 아이콘으로 연결한다. 학원플러스 기본 도메인과 www의 첫 HTML에는 브라우저 탭용
32px 파비콘과 검색·홈 화면용 180px Apple 아이콘이 함께 들어간다. 테넌트 API가
지정한 아이콘을 우선하고, API를 사용할 수 없으면 학원플러스 기본 아이콘을 제공한다.
학생·학부모 및 업무 화면은 처음 받은 HTML의 Apple 아이콘을 유지한다. 업로드된
이미지의 크기는 추정하지 않으며, 기본 아이콘에만 실제 크기인 180×180을 표시한다.
홈페이지와 `/promo`의 구조화 데이터는 512px 조직 로고를, 링크 공유 카드는 1200×630 이미지를 사용한다.

홍보 페이지에서는 헤더·메뉴·바닥글과 제품 스크린샷 안의 학원플러스 심벌까지 확인한다.
가이드 사진이나 영상의 심벌이 바뀌면 새 버전의 묶음을 발행하고 가이드 목록에서
사진·영상·포스터·자막을 함께 전환한다. 예시 화면에 표시된 다른 학원의 로고는 그 학원의
브랜드를 따른다.

`hakwonplus.com`과 `www.hakwonplus.com`에서는 Cloudflare에 캐시된 구판 응답이
Pages의 리디렉션보다 먼저 제공될 수 있다. Cache Rule
`hakwonplus_legacy_brand_guide_navigation`은 이전판 11개 경로의 `Range` 없는 요청 중
JPG 또는 브라우저가 직접 여는 MP4·VTT(`Sec-Fetch-Mode: navigate`)를 캐시 조회에서
제외해 최신판으로 `307` 연결한다. 플레이어의 구판 영상·자막 요청과
`Range` 요청은 원래 파일에서 이어져 재생 위치를 보존한다. 운영 검증은 구판 영상이
캐시에 있는 상태에서 직접 연 구판 JPG·MP4의 `307`과, 새 영상 및 구판 이어받기의
`206`을 각각 확인한다.

`/login`의 데스크톱 화면에는 브랜드 영역과 입력 폼을 나란히 둔다. 좁은 화면은
가로 로고, 아이디 또는 학부모 휴대폰 번호, 비밀번호, 로그인 순서로 읽힌다.
입력 중에도 필드 이름이 보인다. 기존 인증·역할별 이동, 가입 및 계정 찾기, 만료·인증
오류 표시와 재시도는 공용 로그인 흐름을 사용한다. 운영자가 지정한 로그인 로고와
다른 학원의 테넌트별 브랜딩 우선순위는 기존 계약을 따른다.

검수 시 1366px와 390px에서 브랜드 로고 로딩, 키보드 포커스, 인증 실패 후 재입력,
계정 찾기와 로그인 후 역할별 상단바를 확인한다. 설치 아이콘은 역할별 매니페스트,
공유 이미지는 서버가 반환한 OG 메타데이터에서도 확인한다.

## 1. 입력과 로고 분류

원본을 실제 크기로 열어 아래 중 하나로 분류한다.

| 유형 | 헤더 처리 |
|---|---|
| 투명 배경 아이콘 | `headerLogoUrl`만 등록하고 공용 헤더 표면을 유지 |
| 단색 불투명 배경 | 이미지 모서리색을 `headerPalette.surface`로 등록 |
| 사진·그라데이션 불투명 배경 | 네 모서리의 대표색을 `surface`, 이미지에서 헤더로 이어질 중간색을 `surfaceSoft`로 등록 |

`logoUrl`은 로그인·큰 브랜드 면용이고 `headerLogoUrl`은 상단바용 1:1 크롭이다.
불투명 원본을 그대로 축소한 파일을 두 필드에 중복 등록하지 않는다. 헤더 파일은
32px 표시에서도 핵심 심벌이 식별되도록 별도로 확인한다.

비밀번호나 계정 ID는 에셋명·코드·문서·스크린샷 파일명에 넣지 않는다.

## 2. 레지스트리 SSOT

테넌트 정의는 `src/shared/tenant/tenants/<code>.ts`에 둔다. 불투명 헤더 에셋은
다음 팔레트를 함께 등록한다.

```ts
branding: {
  logoUrl: "/tenants/<code>/logo.png",
  headerLogoUrl: "/tenants/<code>/icon.png",
  headerPalette: {
    surface: "#이미지-모서리-배경색",
    surfaceSoft: "#헤더로-이어질-중간색",
    foreground: "#표면-위-제목색",
    accent: "#포커스와-브랜드-강조색",
  },
}
```

`getTenantHeaderCssVars()`가 팔레트를 공용 CSS 변수로 변환한다. 역할별 헤더에서
테넌트 코드를 다시 하드코딩하지 않는다.

## 3. 소비 경계

| 화면 | 소유 파일 | 계약 |
|---|---|---|
| 관리자 | `src/app_admin/layout/Header.tsx` | 팔레트 테넌트는 `headerLogoUrl`을 Program 원본보다 우선 |
| 선생 | `src/app_teacher/layout/TeacherTopBar.tsx` | 팔레트와 헤더 전용 에셋을 공용 리본에 적용 |
| 학생 | `src/app_student/layout/StudentTopBar.tsx` | 학생 테마와 무관하게 브랜드 리본 유지 |
| 학부모 | 학생 레이아웃 공유 | 학생과 동일한 계약, 좁은 화면에서는 아이콘 우선 |

세 헤더는 `data-tenant-header-brand`와 아래 CSS 변수를 공통으로 사용한다.

```text
--tenant-header-surface
--tenant-header-surface-soft
--tenant-header-foreground
--tenant-header-accent
```

리본은 `surface`에서 시작해 `surfaceSoft`를 거쳐 투명해진다. 전체 상단바 배경을
테넌트색으로 덮지 않으므로 다른 조작의 라이트·다크 대비는 그대로 유지된다.

## 4. 로컬 저장 경계

공개 랜딩의 공지 팝업은 "24시간 동안 보지 않기"를 브라우저에 저장하되,
tenant 코드와 공지 내용 fingerprint를 모두 키에 포함한다. 따라서 같은
브라우저에서 한 학원의 공지를 닫아도 다른 학원 공지는 가려지지 않고,
학원장이 제목·본문·링크·만료 시각을 바꾼 새 공지도 즉시 다시 노출된다.
tenant를 확정할 수 없는 preview에서는 숨김 값을 저장하거나 복원하지 않는다.
저장소 접근이 차단된 브라우저에서도 팝업 자체는 정상 동작해야 한다.

강의 생성의 저장 과목과 클리닉 생성의 저장 장소도 tenant 범위 로컬 키를
사용한다. 운영자가 같은 브라우저로 다른 학원에 접속해도 이전 학원의 과목명과
장소명이 제안 목록에 섞여서는 안 된다.

## 5. 신규 테넌트 작업 순서

1. `public/tenants/<code>/`에 로그인 로고와 1:1 헤더 에셋을 준비한다.
2. `src/shared/tenant/tenants/<code>.ts`에 호스트·브랜드·헤더 팔레트를 등록한다.
3. `src/auth/themes/<code>.css`에서 로그인 장면을 구성한다.
4. 학생앱 색은 `src/app_student/shared/ui/theme/tenants/<code>.css`에 **토큰만** 정의하고
   `STUDENT_THEME_BY_TENANT`에 등록한다. 공통 규칙은 `tenants/brand.css`가 소유하며,
   흰 글자용 그라데이션·아이콘·상태 글자의 대비 기준은
   [학생앱 디자인 시스템](../src/app_student/shared/ui/theme/README.md)을 따른다.
5. `index.html`의 초기 메타데이터 레지스트리와 OG·PWA·성적표 등 백엔드
   커스텀 도메인 매뉴얼의 나머지 경계를 반영한다. Pages 함수가 응답 HTML을
   올바르게 바꿔도 초기 스크립트에 호스트가 없으면 브라우저가 fallback 값으로
   다시 덮으므로 두 레지스트리를 함께 검증한다.
6. 역할·테마·폭 검증을 통과한 뒤 정식 품질 게이트로 배포한다.

## 6. 검증표

최소 조합은 다음과 같다.

| 역할 | 1366px | 390px | 라이트 | 다크 |
|---|---:|---:|---:|---:|
| 관리자 | 필수 | 필수 | 필수 | 필수 |
| 선생 | 필수 | 필수 | 필수 | 필수 |
| 학생 | 필수 | 필수 | 필수 | 필수 |
| 학부모 | 필수 | 필수 | 필수 | 필수 |

각 조합에서 확인한다.

- `headerLogoUrl`이 선택되고 큰 `logoUrl` 원본이 상단바에 노출되지 않음
- 이미지 표시 크기 32×32px
- 로고 모서리와 리본 시작면 사이에 눈에 띄는 색 경계가 없음
- 제목색이 `foreground`이고 배경 대비가 유지됨
- 문구·아이콘 겹침과 가로 스크롤이 없음
- 390px에서 공간이 부족하면 제목이 말줄임 또는 생략되고 로고는 유지됨
- 홈 이동, 메뉴, 알림, 프로필, 포커스 링이 정상

기본 정적 검증:

```powershell
cd C:\academy\frontend
pnpm typecheck
pnpm exec eslint <변경한 ts/tsx 파일>
pnpm build
git diff --check
```

운영 배포는 `.github/workflows/quality-gate.yml`을 통과해야 한다. 배포 후 실제
테넌트 계정으로 역할별 상단바와 tenant isolation을 다시 확인한다.

## 7. 활성 브랜드 — godmin

`godmin.kr` / `www.godmin.kr`은 ID `11`, code `godmin`, 표시명 `신과함께`로
등록한다.

- 원본은 투명 PNG 워드마크이며 `public/tenants/godmin/logo.png`가 로그인 큰
  브랜드 면을 소유한다.
- 헤더는 원본 첫 글자 `m`을 정사각형으로 파생한 `icon.png`를 사용한다. Program의
  넓은 `logo_url`보다 이 파일을 우선하기 위해 레지스트리에 헤더 팔레트를 함께
  등록한다.
- 공용 로그인·관리자·선생 브랜딩은 차콜 `#383838`, 코어 민트 `#35c7a0`, 딥
  민트 `#147a62`, 옅은 민트 `#e4f7ef`를 유지한다. 로그인은 워드마크 윤곽을
  닮은 두 개의 원형 궤도만 대표 장면으로 쓴다.
- 학생·학부모 앱의 라이트 테마는 학습 정보를 빠르게 읽는 데 초점을 두고
  쿨그레이 배경 `#eef2f7`, 흰 카드 `#ffffff`, 잉크 텍스트 `#162233`, 클린
  블루 포인트 `#2f6fe4`를 사용한다. 헤더·하단 탭·주요 패널은 큰 유색 면이나
  장식 그라데이션 없이 흰색을 유지하고, 블루는 현재 위치·주요 동작·포커스에만
  쓴다. 성공·경고·오류 색은 의미 구분을 위해 기존 의미색을 유지한다.
- OG는 1200×630, PWA는 192×192·512×512, Apple touch icon은 180×180 PNG로
  파생한다. 제목·manifest·sitemap은 `functions/[[path]].ts`에서 두 호스트를 모두
  fail-closed 레지스트리에 포함하고, `index.html` 초기 메타데이터 레지스트리에도
  같은 제목·설명·아이콘·민트 테마색을 등록해 런타임 fallback 덮어쓰기를 막는다.
- 네이버 Search Advisor 인증값은 발급 전까지 만들지 않는다.

focused 검증은 `e2e/pwa-branding-contract.spec.ts`에서 hostname→code, 교사·학생
manifest, theme/background 색, 정적 에셋 존재를 함께 확인한다. 로그인은 1366px와
390×844에서 DOM·가로 overflow·폼/푸터 겹침을 확인하고, 내부 헤더는 관리자·선생·
학생·학부모의 라이트·다크 조합을 따른다.

## 8. 정성원영어

`정성원영어.com`과 `www.정성원영어.com`의 Punycode 호스트는 ID `12`,
코드 `jeongseongwon-lab`으로 같은 로그인을 제공한다. 학원명은 **정성원영어**이고 공유 설명은 “정성원영어의 수업 일정, 과제와 성적을 확인하는 학습 공간입니다.”다. API가 제공하는 운영 메타와 브라우저 초기 HTML·Pages 폴백을 일치시킨다. 역할별 설치 앱 이름은 이 학원명에 ‘학생’ 또는 ‘모바일 업무’를 붙인다. 로그인 하단의 **사용 가이드**는 학생 가이드로 열리며 관리자·직원 안내로 전환할 수 있다. 로그인 화면은 네이비
면에 고객이 제공한 흰색 워드마크를 표시한다. 넓은 화면에서는 로고와 폼을 좌우에,
700px 이하에서는 상하로 배치한다. 로고는 진입 시 한 번만 나타나며 동작 줄이기
설정을 따른다. 입력 중에도 필드 이름을 표시하고 오류 후 재시도와 계정 찾기를 제공한다.

관리자·학생 헤더와 앱 아이콘에는 네이비 바탕에 흰색 심벌을 사용한다. 헤더의 흰색 학원명은
마지막 글자까지 네이비 배경을 유지한다. 전용 도메인에서
처음 여는 관리자 콘솔과 테마 초기화는 네이비 강조색을 사용한다. 사용자가 선택한
테마·강조색은 다음 접속에도 유지한다. 성적표와
학생앱 탭·버튼도 네이비 계열을 쓰며 어두운 화면에서는 선택 상태를 밝은 색으로
표시한다. 원장·학생·학부모의 계정, 접근 권한, 채점과 알림은 공통 흐름을 따른다.

집중 기능 검증 및 체험 기간은 백엔드의
`docs/operations/tenants/jeongseongwon-lab.md`에서 관리한다.

## 공통 공개 랜딩 상단의 긴 학원명

`src/landing/templates/shared.tsx`의 `LandingNavBar`를 사용하는 공개 페이지와
학원 커뮤니티 상세는 1366px·390px에서 긴 학원명과 역할별 이동 버튼을 함께 표시한다.
브랜드 그룹은 최대 320px 안에서 줄어들며 이름만 말줄임한다. 메뉴 버튼과 로고는
축소하지 않고 로고는 높이 30px·최대 너비 48px 안에서 비율을 유지한다. 전체 이름은
브랜드 링크의 접근 가능한 이름·title과 전체 메뉴의 줄바꿈 제목으로 확인한다.
전체 메뉴의 닫기 버튼과 관리자·학생·학부모 이동 버튼은 화면 안에서 조작할 수 있어야 한다.

이 변경은 서버 이름·로고 설정, 인증·테넌트 판정, 역할별 목적지와 저장 데이터를
수정하지 않는다. 기존 메뉴 열림/닫힘·hover·키보드 동작과 복구 경로를 유지한다.
`e2e/landing-header-width.mock.spec.ts`가 세 역할의 desktop/390px 상세 진입→reload→
전체 메뉴→공개 게시판 이동, 버튼 경계와 전체 이름 접근을 검증한다. 실제 격리 검증은
`e2e/admin/board-attachments-realuse.spec.ts`의 화면별 JSON/PNG를 함께 확인한다.
