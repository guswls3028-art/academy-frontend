# 관리자 QnA 답변 작업 영역

관리자 커뮤니티 `/workspace/community/qna`에서 접근 가능한 직원은 학생 질문을 선택해
문제 사진을 보면서 답변을 작성한다. 서버가 제공한 질문·첨부·기존 답변만 보여 주며,
테넌트와 역할별 접근 권한은 기존 커뮤니티 API가 판정한다. 답변 등록과 알림 발송
정책은 백엔드가 소유한다.

데스크톱 기본 화면은 질문 목록과 질문 자료·답변 2열이다. 이미지 첨부가 있으면
**크게 보며 답변**이 질문 목록과 앱 메뉴를 가리는 화면을 연다. 왼쪽 사진과 오른쪽
답변 편집기는 같은 컴포넌트를 유지하므로 화면 전환 중 회전·확대와 미등록 답변이
사라지지 않는다. **화면 줄이기** 또는 Esc로 돌아오며, 다른 질문 선택이나 목록
복귀도 확대 상태를 끝낸다. **원본**은 별도 탭에서 이미지를 열어야 할 때 사용한다.
이미지 없는 질문은 텍스트 질문으로 표시하고 확대 버튼을 제공하지 않는다.

교직원은 답변 편집기의 **이미지 삽입**으로 사진을 선택하거나 편집기에
Ctrl+V로 캡처 이미지를 붙여넣을 수 있다. 모바일 교직원 커뮤니티 QnA의
**답변 작성**에도 같은 기능이 있다. 미리보기에서 사진을 뺄 수 있고, 글 없이 사진만
등록할 수도 있다. JPG·PNG·GIF·WebP를 장당 5MB, 답변당 10장까지 첨부할 수 있다.

답변 사진은 등록할 때 질문의 원본 첨부와 별도로 저장한다. 학생과 학부모는 볼 수 있는
질문 상세의 선생님 답변에서 사진을 열 수 있다. 표시가 실패하면 **사진 다시 불러오기**로
새 표시 URL을 요청한다. 사진과 텍스트의 저장·권한은
[커뮤니티 QnA 백엔드 계약](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/community.md#qna-답변-사진)을 따른다.
등록 성공 여부가 불명확할 때는 같은 사진과 글을 유지한 채 **다시 등록**할 수 있다.
파일 검증 오류에는 표시된 사진을 제거하거나 다른 파일로 교체할 수 있다.

질문·답변 조회 실패에는 해당 영역의 재시도 버튼을 표시한다. 답변 등록 실패 시
편집 내용을 보존하고 오류를 알리며 다시 등록할 수 있다. 등록 성공 후 질문 상태와
미답변 수를 갱신하고, 새로고침 후에도 서버의 답변이 표시되어야 한다. 모바일
390px에서는 질문 자료·답변 작성 탭으로 전환하며 편집 중인 내용을 유지한다.

구현: `src/app_admin/domains/community/pages/QnaInboxPage.tsx`,
`src/app_admin/domains/community/qna-inbox.css`, `PostThreadView.tsx`.
회귀 검증: `e2e/admin/community-workspace-polish.mock.spec.ts`의 데스크톱
사진 확대·회전·등록과 390px 전환 시나리오. 실사용 검증은 격리 개발 환경의
파일 선택과 실제 Ctrl+V → 등록 → 새로고침 → 학생·학부모 화면 반영 및 소유 QA 데이터 정리를 따른다.
390px 등록 재시도와 이미지 표시의 브라우저 회귀도 검증한다.
실사용 브라우저 경계는 인증된 QnA 상세·목록과 해당 첨부 다운로드 응답에서
받은 개발 R2 URL과 인증된 답변 목록의 사진 URL 중 같은 QA 테넌트·게시글의
서명된 이미지 GET만 전달한다. 다른 R2 객체,
운영 버킷, 자격 증명이 붙은 요청과 잘못된 이미지 응답은 차단한다.
