# 학생·학부모 앱 제품 계약

## 목적과 화면 원칙

`/student/*`는 학생과 학부모가 함께 사용하는 모바일 우선 화면이다. 학부모는
선택한 자녀의 학습 현황을 확인하고, 학생은 학습·제출 작업을 수행한다. 두 역할
모두 같은 테넌트 로고와 색상 토큰을 사용한다. 현재의 상단 브랜드 리본, 해야 할
일 우선 카드, 하단 핵심 탐색 구조는 유지한다.

기준 뷰포트는 390px이며 320px에서도 문서 전체의 가로 스크롤이나 카드 잘림이
없어야 한다. 긴 한글 제목, 공백 없는 URL, 표와 코드 블록은 화면 또는 콘텐츠
영역 안에서 줄바꿈하거나 해당 콘텐츠만 가로 스크롤한다. 로딩·빈 결과·오류에는
각각 스켈레톤, 다음 행동을 설명하는 빈 상태, 재시도 동작을 제공한다.

## 콘텐츠 표시 경계

- 제목, 요약, 메모, 검토 사유처럼 일반 문장인 필드는
  `richHtmlToPlainText` 또는 `richHtmlToPreviewText`로 정규화한다. 예전 데이터에
  HTML 또는 여러 번 이스케이프된 엔티티가 있어도 태그 문자열을 사용자에게
  노출하지 않는다.
- 이 규칙은 화면 본문뿐 아니라 버튼·카드, 썸네일 `alt`, `aria-label`, `title`,
  `placeholder`에도 동일하게 적용한다. 영상 영역은 `video.api.ts`에서 강의명,
  차시명, 영상명과 재생 응답을 먼저 정규화하므로 홈 카드, 차시 목록, 플레이어,
  재생목록이 서로 다른 문자열을 노출하지 않는다.
- 공통 `Program`·인증 사용자 표시명과 학생 프로필, 성적 사용자 지정 라벨,
  커뮤니티 활동 배지도 API 응답 경계에서 평문으로 정규화한다. 로그인 헤더나
  합격 배지처럼 여러 화면에서 재사용되는 값은 개별 컴포넌트에서 중복 처리하지
  않는다.
- 공지·질문·상담 본문처럼 서식이 의미 있는 필드는 `RichHtmlContent`로만
  렌더링한다. 이 컴포넌트는 허용 가능한 HTML을 정화하고, 편집기에서 붙은
  `style`, 고정 `width`·`height`, 외부 `class`·`id`, 글꼴 속성을 제거한다.
- 본문의 링크와 의미 있는 제목·목록·표 구조는 유지한다. 표와 `pre`는 자신의
  영역에서만 스크롤하며 앱 전체 폭을 늘리지 않는다.
- 리치 콘텐츠가 아닌 텍스트는 DOM 주입 없이 일반 텍스트와 줄바꿈으로 표시한다.

소유 구현은 `src/shared/utils/richHtml.ts`,
`src/shared/ui/content/RichHtmlContent.tsx`, 학생 공용
`StudentPageShell`과 `base.css`다. 새 사용자 입력 또는 API 문자열을 추가할 때는
화면의 의미에 따라 일반 텍스트와 리치 본문 중 하나를 명시적으로 선택한다.

## 역할과 데이터 계약

- 학생은 시험·과제·성적표 제출, 보관함 업로드와 프로필 수정을 수행할 수 있다.
- 학부모는 자녀의 대시보드·일정·성적·공지·보관함·프로필을 읽을 수 있으나,
  시험·과제·성적표 제출, 자녀 파일 변경, 자녀 프로필 변경, 질문·상담 작성은
  읽기 전용으로 막는다. 학부모 자신의 비밀번호 변경은 허용하며,
  자녀 프로필 `PATCH /student/me/`가 아닌 전 역할 계정 전용
  `POST /core/change-password/`로 처리한다. 성공 시 기존 토큰을 폐기하고
  새 비밀번호로 다시 로그인한다. 현재 비밀번호 불일치는 입력 오류로,
  비밀번호 변경 알림톡 전송 실패는 저장 롤백과 재시도 가능 오류로 표시한다.
- 학부모가 고른 자녀 ID는 학생 API의 `X-Student-Id`에 전달한다. 선택하지 않은
  자녀, 연결되지 않은 자녀 또는 다른 테넌트 자녀를 임의로 추정하지 않으며 API가
  실패하면 오류 상태로 닫는다.
- 알림 읽음 상태는 서버의 학습 데이터가 아니라 30일 보존 로컬 UX 상태다.
  저장 키는 `{tenant}:{student profile}`로 분리한다. 학부모는 선택 자녀 ID,
  학생은 본인 프로필 ID를 사용하므로 같은 기기·같은 시험 ID여도 다른 학생의
  읽음 배지를 숨기지 않는다. 자녀 전환 시 쿼리 캐시도 새 선택 범위로 갱신한다.

서버의 학생·학부모 권한과 자녀 연결 계약은 academy-backend의
`docs/domain/student-core.md`, `docs/domain/parent-account.md`가 소유한다.
프론트엔드는 그 계약을 완화하거나 기본 자녀를 추정하지 않는다.

## 질문·상담 작성 초안

- 학생 Q&A와 상담 신청은 현재 tenant, 로그인 user, 작성 종류가 모두 일치할 때만
  이 브라우저의 초안을 복구한다. Q&A와 상담은 서로 다른 키를 사용하며, 학부모
  읽기 전용 경계와 서버의 게시 권한을 완화하지 않는다.
- 입력은 변경 800ms 뒤 저장하되 연속 입력 중에도 5초 안에는 저장하고, 페이지 숨김·
  브라우저 이탈·학생 앱 내부 화면 이동 전에 flush한다. 저장 중·저장 완료·복구·저장
  실패와 **다시 저장** 동작을 폼 안에서 보여 주며, 저장소 실패가 질문 또는 상담
  제출 자체를 막지는 않는다. version이 맞는 초안은 30일까지 복구하고 version 없는
  raw legacy 값이나 30일 초과·손상 값은 가져오지 않는다.
- 같은 계정의 다른 탭에서 다른 최신 초안이 생기면 예약된 자동 저장을 멈추고 현재
  내용을 자동 덮어쓰지 않는다. 사용자가 새 초안을 불러오거나 현재 내용을 유지하도록
  명시적으로 선택한 뒤에만 저장을 재개한다.
- 첨부는 안전한 파일명·크기·MIME type 메타데이터만 제한적으로 보관한다. 파일 bytes,
  Blob/data URL, 로컬 경로, token·프로필 정보는 저장하지 않는다. 복구하면 이전 파일명을
  보여 주고 파일을 다시 선택하라고 안내한다. 서버 게시글 등록이 성공한 뒤에만 해당
  초안을 제거하므로 API 실패에는 입력과 초안을 유지하고, 게시글 등록 뒤 첨부 업로드만
  실패한 경우에는 게시 중복을 막기 위해 초안을 제거한다.
- 제품 소유 구현은 `src/shared/hooks/useDurableDraft.ts`와
  `src/app_student/domains/community/pages/CommunityPage.tsx`다. 정적·브라우저
  회귀는 `e2e/student/community-draft-autosave.mock.spec.ts`가 검증한다.

## 교직원 학생 화면 대리보기와 활동 증거

관리자 학생 상세와 선생님 모바일 학생 상세의 **학생 화면 보기**는 430px 폭의
별도 팝업에서 실제 `/student/*` 앱을 연다. 팝업은 학생 이름과
`교직원 대리보기` 리본을 항상 표시하고, 종료 버튼과 15분 만료 경계를 제공한다.
대리보기 중 화면 탐색과 조작은 학생 앱의 기존 API·권한·오류 상태를 그대로
사용한다.

관리자 영상 상세의 **학생 시청 현황**도 학생별 행에서 같은 **학생 화면** 팝업을
연다. 행 전체를 의미 없는 선택 버튼으로 만들지 않고, 학생 이름·학교/학년,
출결·시청 권한, 진도와 명시적 화면 보기 버튼을 분리한다. 이 진입점은 영상 통계가
반환한 tenant-scoped `student_id`만 사용하며 이름이나 수강 ID로 학생을 추정하지
않는다. desktop과 390px 모두 버튼·상태·진도가 잘리지 않아야 하고, 영상 통계에
학생 ID가 없으면 버튼을 비활성화하고 행 안에 이유를 항상 표시한다.
학생 계정에 최초 비밀번호 변경 또는 첫 이용 안내가 남아 있어도 대리보기에서는
그 개인용 절차를 띄우지 않고 학생 화면을 바로 보여 준다. 해당 플래그 자체는
변경하지 않으므로 학생이 직접 로그인할 때는 기존 절차가 그대로 적용된다.

보안 경계는 다음과 같다.

- 버튼 클릭과 동시에 빈 팝업을 먼저 만들어 브라우저 팝업 차단을 피하고, 서버가
  15분 access-only 세션을 발급한 뒤 앱으로 이동한다.
- 토큰은 URL, 쿼리, history, 일반 `localStorage`에 넣지 않는다. 최초 전달에는
  팝업 전용 `window.name`을 사용하고 앱 bootstrap 즉시 지운 뒤 그 팝업의
  `sessionStorage`에만 둔다.
- refresh token을 만들거나 교직원 창의 로그인 저장소를 읽지 않는다. 팝업 종료,
  만료, 401에서는 전용 세션만 지우고 교직원 원래 세션은 유지한다.
- 상단 리본은 서버 만료 시각에서 계산한 남은 시간을 `mm:ss`로 표시한다. 종료
  버튼은 서버 세션을 먼저 폐기한 뒤 창을 닫고, 교직원 원창도 팝업 닫힘을 감지해
  같은 세션 종료 API를 호출한다. 네트워크가 끊겨 종료 신호가 도달하지 않아도
  access token과 서버 세션은 발급 후 15분을 넘겨 사용할 수 없다.
- 대리보기는 학생 로그인 기록을 만들지 않는다. 학생 앱 화면 증거는
  `actor_mode=support`로 별도 기록하며 기본 활동 목록에서 제외한다.

교직원 학생 상세의 **활동** 탭은 실제 학생 로그인과 허용된 학생 화면의 서버
수신 기록을 최신순으로 보여 준다. 7일·30일·90일, 로그인·과제·영상·시험·결과
등의 분류를 선택할 수 있다. `교직원 대리보기 포함`을 켠 경우에만 지원 세션
활동도 함께 표시한다. 화면 열람 기록은 제출 완료나 영상 완주의 증거가 아니므로
각 도메인의 정본 상태와 함께 확인한다.
활동 검색은 시험·과제·화면 제목과 교직원을 서버에서 조회한다. 결과 상단은 조건
전체 건수와 최신 100건 제한 여부를 구분하고, 각 행의 **증거 상세**는 서버 수신
시각·사용 주체·검증된 대상·증거 번호를 제공한다. 내부 route ID나 토큰은 사용자
화면에 표시하지 않는다.

계정정보 재전송은 저장되어 있지 않은 현재 비밀번호를 노출하지 않는다. 선생님
모바일 학생 상세의 버튼은 기존 학생/학부모 비밀번호 재설정 시트를 열고, 대상
계정의 임시 비밀번호를 만든 뒤 승인된 알림톡 경로로 발송한다. 신규 계정의 최초
안내 시점은 backend `docs/ssot/messaging-policy.md`를 따른다.

## 강의 공지 발견 계약

- 학생·학부모의 `/student/video` 강의 탭은 수강 강의 카드 앞에 **강의 공지**
  진입점을 둔다. 공지가 있으면 현재 수강 강의에 연결된 `COURSE` 범위 공지 수와
  우선 공지 제목을 보여주고, 로딩·빈 결과·조회 실패 상태에서도 공지 목록으로
  이동할 수 있어야 한다.
- `/student/video/courses/:lectureId`의 **이 강의 공지**는
  `/student/notices?tab=lecture&lecture=:lectureId`로 이동한다. 공지 화면은 API가
  반환한 `mappings[].node_detail.lecture`와 `level=COURSE`를 함께 확인해 선택한
  강의 공지만 표시하며, **전체 강의**로 범위를 해제할 수 있다. URL의 강의 ID는
  표시 필터일 뿐 권한을 넓히지 않으며 서버의 학생·선택 자녀 범위 응답을 그대로
  따른다.
- 공지 목록 데이터는 기존 `GET /api/v1/community/posts/notices/`가 소유한다.
  프론트엔드는 강의 제목이나 공지 본문을 별도로 복제하지 않는다. 공개 강의에는
  수강 강의 공지 진입점을 노출하지 않는다.
- 390px에서는 공지 요약을 한 줄로 줄이고 아이콘·건수·진입 동작을 유지한다.
  키보드 포커스와 `prefers-reduced-motion`을 지원하며 문서 전체 가로 스크롤을
  만들지 않는다.

## 현재 강의와 종료 강의 계약

- 현재 학습 화면, 대시보드 진행 시험·미통과 건수, 차시, 시험 응시, 과제 제출,
  영상 목록·재생은 `Enrollment.status=ACTIVE`와 `Lecture.is_active=true`를 모두
  만족할 때만 열린다. 클라이언트 필터는 표시 보조이며 서버 접근 차단이 정본이다.
- 종료 강의의 성적과 영상 진도는 삭제하지 않는다. 성적과 영상 화면은 진행 중
  강의를 먼저 표시하고, 종료 강의는 기본으로 접힌 읽기 전용 이력에서 강의별
  성적·영상 수·완료 수·진도 기준 시청 분량·활동 감사 도입 이후의 재생 횟수를 보여 준다. 종료 이력에는 차시 링크,
  제출 동작, 재생 URL을 만들지 않는다.
- 강의를 복원하면 기존 수강·성적·진도를 유지한 채 현재 학습 접근을 다시 계산한다.
- 열린 영상 플레이어는 최초 재생 응답을 캐시로 재사용하지 않고, 30초마다 그리고
  창으로 돌아올 때 `access_check=1`로 현재 학생·선택 자녀·수강·강의·영상 정책을
  재검증한다. 403이면 HLS/YouTube와 `FREE_REVIEW`/`PROCTORED_CLASS` 구분 없이
  플레이어를 즉시 unmount해 재생을 멈추고 서버의 거절 사유를 표시하며 반복
  polling도 멈춘다. 성공 응답의 서버 `access_mode` 또는 `policy_version`이 현재
  부트스트랩과 다르면 기존 플레이어를 먼저 unmount하고 전체 재생 권한을 다시
  발급받는다. 새 모드·버전이 일치하고 현재 토큰이 있으며, 감시 모드라면 감시 정책과
  세션까지 모두 발급된 경우에만 다시 연다. 따라서 열린 `FREE_REVIEW`가 서버에서
  `PROCTORED_CLASS`로 바뀌어도 감시 없는 플레이어가 남지 않는다. 일시적 네트워크
  오류는 강의 종료로 오인하지 않는다. 영상이나 선택 수강이 바뀌면 이전 거절 사유를
  지우고 정책 재발급 세대를 새로 시작한다. 이전 영상·수강의 지연된 재발급 성공이나
  실패는 새 영상의 거절 사유와 대기 상태를 변경하지 않는다. 다시 시도는 재생 정보와
  현재 접근을 모두 성공적으로 확인한 뒤에만 플레이어를 다시 연다. 수동 다시 시도도
  시작 당시의 영상·수강·세대에 묶이므로, 그 사이 다른 영상으로 이동하거나 새 403이
  발생하면 이전 성공이 현재 거절 상태를 지우거나 발급된 URL을 다시 mount하지 않는다.
  허용 상태에서는 30초 주기로 재검증하며, fatal 거절 뒤의 타이머·focus와 영상 화면
  이탈 뒤에는 추가 access-check 요청을 보내지 않는다.

## 영상 건너뛰기 계약

- 기본 `Video.allow_skip=false`와 `PROCTORED_CLASS` 재생은 임의 앞으로 탐색 대신
  10초 단위 건너뛰기를 제공한다. 교사가 `allow_skip=true`로 자유 탐색을 명시한
  복습 영상은 기존 자유 탐색을 유지하고, 학생별 `block_seek`는 완전 차단을 유지한다.
  영상별 한도는 인코딩 길이의 20%와 30분 중 작은 값이며, 마지막 승인은 남은
  시간만큼 10초보다 짧을 수 있다. 뒤로 10초와 이미 본 구간 재이동은 계속 허용한다.
- 남은 시간은 재생 컨트롤 안에서 즉시 보이고, 서버 응답이 올 때까지 앞으로 버튼을
  잠가 연타를 막는다. 승인 실패는 이동 성공처럼 보이지 않고 다시 시도할 수 있는
  문구를 표시한다. 영상 길이가 없거나 한도를 모두 쓰면 버튼을 비활성화하고 이유를
  설명한다.
- `POST /student/video/videos/{videoId}/forward-skip/` 응답이 승인한 초만 headless
  HLS/YouTube controller의 별도 승인 경로로 이동한다. 재생 막대 드래그, 개발자 도구,
  일반 `seek()` 호출은 승인 경로가 아니며 기존 탐색 guard와 감사 이벤트를 유지한다.
- 정본 누적값은 `VideoProgress.forward_skip_seconds_used`다. 브라우저 저장소나
  playback session을 한도로 사용하지 않으므로 새로고침·기기 변경·동시 탭으로
  복원되지 않는다. 학부모 화면은 선택 자녀 영상을 읽을 수 있지만 학생의 누적 한도를
  변경하지 않는다. `FREE_REVIEW`에서는 기존 교사 영상 정책을 그대로 따른다.
- 데스크톱과 390px 모두 `10초씩 · 남은 시간`을 영상 위 컨트롤에 표시하고 가로
  넘침을 만들지 않는다. 잔여량 막대의 짧은 전환은 `prefers-reduced-motion`에서
  제거한다.

## 과제 학습 현황 계약

- 성적 화면의 과제 탭은 관리자 학생 상세와 같은 정본 과제 이력을 읽으며,
  카드마다 강의·차시, 점수/만점, 완료 상태와 진행률을 보여 준다. 값이 없는
  점수는 `null/만점`이나 0점으로 출력하지 않고 `검사 전`으로 표시한다.
- 제출하지 않은 과제는 `미제출`, 제출했지만 아직 채점하지 않은 과제는
  `검사 전`, 기준을 충족한 과제는 `완료`, 미달은 `미완료`로 구분한다. 완료형은
  숫자 `0/1` 대신 완료 상태만 보여 준다.
- 기본 정렬은 최근 차시순이어서 1차시가 목록 아래에 온다. 학생·학부모는
  `정규·보강`, `미완료·검사 전/완료`, `최근 차시·1차시부터·최근 기록`으로
  범위를 좁힐 수 있다. 필터는 선택 자녀 또는 본인 학생 범위를 바꾸지 않는다.
- 390px에서는 필터가 두 행 안에 배치되고, 점수·상태·진행률이 제목을 가리거나
  문서 전체의 가로 스크롤을 만들지 않는다. 학부모는 동일 화면을 읽기 전용으로
  확인한다.

## 차시별 과제 제출 계약

- 차시 상세에서 `/student/submit/assignment?sessionId={sessionId}`로 들어오면 해당
  차시의 미완료 시험·과제만 표시한다. 강의명이 같아도 다른 차시 항목을 섞지 않으며,
  전체 미완료 목록으로 이동하는 명시적 링크를 제공한다.
- 과제 A에서 파일을 고른 뒤 과제 B로 대상을 바꾸면 아직 업로드하지 않은 선택
  묶음을 즉시 비운다. 한 과제에서는 사진·동영상을 함께 여러 개 고르고 각 파일의
  썸네일·이름·용량·순서와 업로드 진행률을 확인한다. 서버에 이미 제출된 파일은
  새로고침 뒤에도 별도 목록에 남는다.
- 업로드는 파일별 독립 요청이다. 일부가 실패해도 성공한 파일은 유지하고, 실패한
  카드에 원인을 보여 주며 그 파일만 같은 식별자로 다시 시도한다. 전부 성공한 뒤에만
  대상·선택 파일·브라우저 파일 입력을 함께 초기화한다. 요청 중에는 대상 이동과
  해당 파일 삭제를 잠가 요청 시작 시점의 대상을 보존한다.
- 클라이언트는 허용 확장자와 한 과제 최대 20개, 파일당 100MB, 전체 500MB를 선택
  전에 검사한다. 서버의 tenant·배정·MIME/signature·용량 검증이 정본이다. 현재 제출
  파일 목록 조회 실패를 0개로 바꾸지 않고 재조회 전까지 새 업로드를 잠근다. 학부모는
  이 화면에서도 읽기 전용이다. 검수가 끝난 파일 변경은 서버 오류를 그대로 안내한다.
- 집중 회귀는 `e2e/student/assignment-session-scope.mock.spec.ts`가 390px 범위 고정,
  대상 전환 초기화, 파일 형식 거부, 성공 후 초기화와 가로 넘침을 검증한다.
  `e2e/student/assignment-media-multiupload.mock.spec.ts`는 기존 단건 복원, 사진·동영상
  다건 선택, 느린 업로드, 부분 실패·파일별 재시도, reload 지속성과 390px 넘침을
  검증한다.

## 실패 동작과 검증

학생·학부모의 자료함과 영상 강의·차시·통계는 프로필/선택 자녀 범위와 본문 조회가
모두 성공한 뒤에만 빈 상태를 표시한다. 실패한 자료함에서는 업로드·삭제를 잠그고,
영상·시험 상태와 알림 개수는 실패를 0건이나 미응시로 바꾸지 않는다. 알림 집계는
프로필과 클리닉·QnA·상담·성적 하위 조회가 모두 성공한 뒤에만 확정하며, 하나라도
실패하면 cached partial 합계나 0건을 만들지 않는다. 조회 중에는 하단 알림 탭과
대시보드가 **확인 중**, 실패하면 **확인 실패/확인 필요**를 표시하고, 성공한 빈
응답 뒤에만 `0건`, `정리됨`, `급한 일이 없음`을 표시한다. 알림 센터 진입은 계속
허용한다.

공지의 인라인 이미지는 presign URL을 파일별로 병렬 조회한다. 특정 이미지의 URL 조회,
실제 이미지 응답 또는 디코딩이 실패해도 성공한 형제 이미지는 표시하고, 실패 행에는
파일명·오류·**다시 시도**를 남긴다. 재시도는 그 이미지 URL만 다시 요청하며, pending일
때만 `이미지 로딩 중`을 표시한다. 이 계약은 `/student/notices/:id`와 커뮤니티 공지
상세에 동일하게 적용한다.

리치 콘텐츠 정화가 실패해도 원본 HTML을 실행해서는 안 된다. 로컬 저장소가
비활성·가득 참·손상 상태이면 알림 읽음 처리는 저장하지 못한 것으로 취급하되
학습 데이터 조회와 화면 사용은 계속 가능해야 한다.
영상 이어보기 보조값과 현재 재생 항목은 tenant, 로그인 사용자, 선택 enrollment
범위가 모두 일치할 때만 복원한다. 다른 학생이나 학부모 계정의 같은 브라우저
기록을 이어받지 않으며, 서버 진도가 항상 정본이다. 공통 저장 규칙은
[BROWSER-PERSISTENCE.md](BROWSER-PERSISTENCE.md)를 따른다.

```powershell
pnpm typecheck
pnpm exec playwright test e2e/admin/student-support-preview.mock.spec.ts --project=chromium
pnpm exec playwright test e2e/student/student-content-resilience.mock.spec.ts --project=chromium
pnpm exec playwright test e2e/student/student-score-trend.spec.ts --project=chromium
pnpm exec playwright test e2e/visual/design-system-route-audit.spec.ts --grep "student (mobile|desktop) route surface" --project=chromium
```

첫 테스트 묶음은 다중 이스케이프 HTML, 영상 홈→차시→재생 흐름, 대시보드·출결·
클리닉·시험·성적·과제·커뮤니티·알림 제목, 붙여넣기 고정 폭, 긴 URL·표,
390/320px 레이아웃과 계정별 알림 격리를 검증한다. 주요 조회 API를 503으로
차단하는 상태 매트릭스는 대시보드·일정·출결·시험·성적·공지·커뮤니티·알림·
클리닉·수납·프로필·영상 재생목록이 빈 화면으로 무너지지 않고 사용 가능한
`다시 시도` 동작을 제공하는지 확인한다. 운영 정적 경로 감사는 학생
모바일과 1366px 데스크톱을 각각 순회하고, 모든 역할 화면에서 본문 및 접근성
속성의 태그/엔티티 문자열, 빈 화면, 오류 문구, 디자인 토큰·폰트 누락과 문서
전체의 가로 넘침을 실패로 처리한다.
