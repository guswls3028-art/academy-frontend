# 학원 설정의 권한과 저장 복구

설정 메뉴와 편집 권한은 로그인 사용자의 현재 `tenantRole`을 따른다.
전역 `is_superuser` 표시로 학원 내 역할을 높이지 않는다.

모바일 학원 목록은 학원명·전화번호를 수정/제거 버튼 아래 전체 너비로 줄바꿈하여
표시한다. 버튼 때문에 실제 연락처가 말줄임으로 사라지지 않아야 한다.

| 기능 | 현재 학원 역할 |
|---|---|
| 학원명·문의 전화·미리보기·합/불 라벨·사업자 프로필 편집 | owner |
| 결제 방식·청구 정보 관리 | owner |
| 홈페이지 편집·상담 수신함·상담 업무 알림 | owner/admin |
| 학생 성적표 구성 | owner/admin |
| 프로필·테마 | 로그인한 교직원 본인 |

설정 메뉴에서 허용된 기능만 표시한다. 결제 화면에 직접 접근한 일반 교직원은
구독 현황을 읽을 수 있지만 원장용 계좌이체 관리 API를 호출하거나 편집할 수 없다.
서버의 최종 권한 검증은 그대로 유지한다. backend의 `apps/core/permissions.py`,
`apps/core/views/tenant_info.py`, `apps/core/landing/_helpers.py`가 서버 경계를 소유한다.
플랫폼 운영 콘솔 권한은 이 학원 설정의 역할 판단과 별개다.

학원 정보 최초 조회 실패를 빈 학원 목록으로 취급하지 않는다. 기존 정보를
불러오는 재시도 동선을 표시하고 성공한 뒤 편집·추가한다. 사업자 프로필도 최초
조회 실패 시 빈 입력값으로 저장하지 않는다. 이 방식은 읽지 못한 기존 값을
빈 배열·빈 문자열로 덮어쓰는 문제를 방지한다.

저장 실패는 오류 메시지를 표시하고 입력 중인 이름·전화와 기존 분원 목록을
보존한다. 재시도 성공 시 서버 응답을 캐시에 반영하고 편집을 닫는다. 다른 설정
섹션을 저장하거나 조회가 갱신되어도 편집 중인 미리보기·합/불 라벨·사업자
프로필 초안을 덮지 않는다. 취소는 마지막 조회값으로 되돌린다.
동시 사용자 간 버전 충돌 해결을 추가한 변경은 아니며 기존 API와 저장 데이터는 유지한다.

홈페이지 상담 알림은 실제 상담 처리 권한과 같은 owner/admin에 제공한다.
teacher/staff는 해당 조회를 하지 않는다. 알림 표시·실패 복구의 공통 계약은
[TEACHER-WORKSPACE-OPERATIONS.md](TEACHER-WORKSPACE-OPERATIONS.md)를 따른다.

검증은 `e2e/admin/settings-role-recovery.mock.spec.ts`의 1366px/390px에서
owner(전역 관리자 아님), admin/teacher/staff(전역 관리자 표시 있음), 직접 접근,
최초 조회 오류→재조회→저장 오류→재저장→reload, 기존 분원 유지, 여러 섹션의
초안 보존을 확인한다. 결제·상담 업무는 기존 관련 회귀도 함께 실행한다.
