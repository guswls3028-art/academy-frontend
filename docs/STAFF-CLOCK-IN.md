# 조교 출퇴근·근무기록 화면 계약

조교가 시스템 로그인과 유급 근무 시작을 혼동하지 않고, 클리닉·현장 등
배정된 근무유형을 직접 선택해 출퇴근하며 같은 기록을 PC·모바일과 관리자
정산 화면에서 확인하는 현재 계약이다.

## 역할과 진입점

| 사용자·화면 | 진입점 | 가능한 작업 |
|---|---|---|
| 조교 `tenantRole=staff` | 새 로그인 직후 선택창 | 유형별 출근 또는 `출근하지 않고 로그인` |
| 조교 PC | 상단 근무 시계, `/workspace/profile/attendance` | 출퇴근·휴식, 본인 기록·공제 전후 급여/기본 공제 3.3%/환급 조회 |
| 조교 모바일 | 상단 타이머, `/workspace/mobile/my-records` | 출퇴근·휴식, 본인 기록·공제 전후 급여/기본 공제 3.3%/환급 조회 |
| 급여 관리자 | `/workspace/staff/*` | 직원별 기록·비용·월마감·정산 관리 |

새 자격증명 로그인 성공 시에만 세션 힌트를 만들며, 새로고침이나 기존 토큰으로
브라우저를 다시 연 것만으로 선택창을 반복하지 않는다. 이미 열린 근무가 있으면
새 기록을 만들지 않고 현재 근무 상태로 이어진다.

## 프런트 구조와 상태 소유권

직원 명부·근무·선결제 환급·근무유형/배정·월마감·급여 스냅샷과 직원 본인
근무기록은 `src/shared/staff/fetchStaffPages.ts`로 페이지당 최대 500건씩 끝까지
읽는다. 첫 500건을 전체 목록으로 간주하지 않으며, 첫 페이지의 대표 정보는
별도로 보존한다. 이름 검색·선택·직원 목록 엑셀은 모두 완성된 목록을 사용한다.
명부는 정렬·검색한 전체 결과를 화면에서 50명씩 나눠 그려 대량 명부의 모바일
입력 지연을 줄인다. 검색·정렬 변경은 첫 페이지로 돌아가며, 페이지를 넘어 선택한
직원과 엑셀 대상은 유지한다. `전체 선택`은 모든 페이지의 현재 검색 결과를 뜻한다.

전체 조회는 시작 시의 계정 세션과 학원에 고정한다. 서버가 보낸 `next` URL은
직접 따라가지 않고 같은 API·필터의 다음 페이지 번호만 요청한다. 중간 실패,
전체 건수 변경, 잘못된 응답·중복·누락은 전체 조회 실패로 표시한다. 오류 화면의
`다시 시도`로 처음부터 재조회하며 일부 행만 담은 엑셀이나 미완성 목록을 정상
결과로 제공하지 않는다. 급여·공제 계산과 마감 쓰기 권한은 기존 서버 계약을 따른다.

- `src/shared/staff/api.ts`가 `/staffs/me/` 직원 identity와 배정 근무유형 계약을
  소유한다. 관리자 화면과 조교·강사 상단 시계가 별도 타입이나 요청 함수를
  만들지 않는다.
- `src/features/staff-clock/`이 현재 근무 조회, 출근·휴게·퇴근 명령, 관련
  React Query 캐시 무효화와 경과시간 계산을 소유한다.
- PC `HeaderCenterStaffClock`, 모바일 `CompactStaffClockButton`, 로그인 선택창은
  모두 같은 `useStaffClock`을 사용한다. 화면별 타이머나 mutation을 복제하지
  않으며 진행 중 유형·시급은 현재 근무 API 응답만 표시한다.
- 공용 `src/shared/staff/queryKeys.ts`가 직원 identity, 현재 근무, 현재 근무자,
  근무기록·합계 캐시 루트를 소유한다. 관리자 정산과 본인 화면의 갱신은 문자열이
  우연히 같은 별도 키가 아니라 이 정본 키를 공유한다.
- 새 로그인 여부는 인증 화면의 세션 힌트일 뿐 근무 상태가 아니다. 인증 역할을
  읽은 뒤 `tenantRole=staff`일 때만 힌트를 만들며, 다른 역할로 로그인하면 남은
  힌트를 제거한다.

## 로그인 선택

- 로그인 자체는 시간을 계산하지 않는다.
- 선택창은 `00:00 · 아직 근무 시작 전`을 먼저 보여 준다.
- 서버가 `/staffs/me/`로 반환한 본인의 활성 `assigned_work_types`만 카드로
  표시한다. 카드에는 근무유형과 적용 시급을 함께 보여 준다.
- 근무유형 선택은 `POST /staffs/{staff_id}/work-records/start-work/`가 성공한
  뒤에만 창을 닫는다. 실패하면 오류를 알리고 선택창을 유지한다.
- `출근하지 않고 로그인`은 근무 API를 호출하지 않고 선택창만 닫는다. 이후에도
  상단 근무 상태에서 출근할 수 있다.
- 배정 유형이 없으면 출근 버튼을 만들지 않고 관리자에게 배정을 요청하도록
  안내한다. 비근무 로그인은 계속 허용한다.
- 조교가 아닌 owner·admin·teacher에는 로그인 선택창을 띄우지 않는다.
- 직원 역할은 과거 `must_change_password` 값이 남아 있어도 변경 권장 모달을
  표시하지 않고 출근 선택을 바로 연다. 실제 첫 로그인 계정 안내가 표시되는
  동안에만 출근 선택창을 렌더하지 않아 뒤 화면이 포커스를 가로채지 않는다.
- 로그인 선택창과 별개로 연결된 `Staff`와 배정 유형이 있는 강사·admin은 기존
  상단 근무 상태에서 본인 출퇴근을 계속 사용할 수 있다.

## 진행 중 근무와 퇴근

상단 근무 상태는 선택 유형, 출근 시점에 고정된 시급, 휴게를 제외한 실시간
경과시간을 표시한다. 휴식 중에는 타이머를 멈추고 `근무 다시 시작`을 제공한다.
출근·퇴근 성공 시 기간 기록·합계·현재 근무자와 월 전체 급여판 캐시를 함께
갱신한다. 관리자가 급여판을 열어 둔 상태에서도 새 근무 시작과 확정된 퇴근
금액을 별도 새로고침 없이 다시 조회한다.

서버가 현재 상태를 불러오지 못하면 출근하지 않은 것으로 추정해 쓰지 않는다.
오류 상태와 `다시 시도`를 표시한다. 중복 출근 `409`, 월마감, 배정 변경 등
서버 오류는 원문 계약을 사용자 문구로 보여 주고 기존 선택을 유지한다.

## 본인 기간 기록

PC `근무 기록`과 모바일 `근무 기록 / 지출`은 정본 `WorkRecord`의 날짜,
유형, 출퇴근 시각, 휴게, 확정 근무시간, 출근 시점 시급, 금액을 읽기 전용으로
보여 준다. 진행 중 기록과 퇴근 시각은 있으나 시간 또는 금액 계산이 끝나지 않은
기록은 `0시간`·`0원`으로 확정해 보이지 않고 `계산 전`·`계산 미완료`로 표시한다.
각 기록의 `휴게`는 유급 시간에서 제외되는 일반 휴게 `break_minutes`와 식사
`meal_minutes`의 합계이며, PC와 모바일이 같은 합계를 표시한다.
기간 합계는 서버의
`/staffs/{staff_id}/summary/`를 사용하며 근무 공제 전 총액, `기본 공제 3.3%`
공제, 공제 후 급여, 승인 환급비, 이체 예정액을 같은 순서로 표시한다.
시급제 기본 공제율이며, 계산된 이체 예정액과 실제 송금 완료는 구분한다.
합계 요청이 로딩 중이거나 실패한 동안에는 값이 없는 상태를 `0원`으로 바꾸지
않고 급여 카드를 숨긴다. 실패 시 오류와 다시 시도만 보여 실제 0원 합계와
조회 실패를 구분한다.
각 기록 날짜는 `8/15(토)`처럼 요일까지 표시하고 유형, 출퇴근, 휴게, 시간, 적용
시급, 공제 전 금액과 관리자 수정 여부를 한 카드에서 확인한다.

`tenantRole=staff` 조교도 모바일 상단 `메뉴`의 `내 계정 → 근무 기록 / 지출`을
통해 이 화면에 진입한다. 조회 월을 바꾸면 그 달의 정확한 시작일·말일로 기록과
합계를 다시 요청하며, 날짜·유형·시간·적용 시급·공제 전 금액을 390px 화면에서도
가로 넘침 없이 확인한다. 서버는 연결된 `Staff.user`가 본인일 때만 `200`을
반환하고 다른 직원 ID의 기록과 합계는 `403`으로 닫는다.
메뉴의 알림·권한 정보가 뒤늦게 갱신되더라도 사용자가 펼친 그룹은 임의로 접지
않으며, 현재 경로가 바뀔 때만 그 경로의 메뉴 그룹을 자동으로 펼친다.

이 화면은 레거시 `/core/profile/attendance/` 수기 기록을 읽거나 쓰지 않는다.
기존 레거시 행은 백엔드에 보존되지만 근무유형·출근 시점 시급을 안전하게
복원할 수 없으므로 현재 정산 기록과 자동 병합하지 않는다.

## 관리자 기록 정정

종료 날짜를 지정하면 24시간 이상·익일 이후 퇴근도 정확한 날짜로 저장한다.
시간 입력은 분 단위로 표시하되 직접 수정하지 않은 출퇴근 값의 원래 초·소수초는
보존한다. 메모만 정정해 기존 시간이나 수동 확정 금액을 재계산하지 않는다.
날짜가 없는 기존 기록은 기존 익일 추론을 유지한다. 관리자 목록·날짜별 상세와 직원 본인
PC·모바일 기록에는 출근일과 다른 퇴근일을 명시한다. 종료 일시 오류는 입력값을 유지한 채 정정할 수 있다. 시간·금액 계산과
마감 기록 보존 정책은 백엔드 직원 도메인 문서가 소유한다.

급여 관리자는 `/workspace/staff/attendance`의 월 전체 근무 기록과 직원 상세
팝업의 `근무기록` 탭에서 잘못 입력된 날짜, 근무유형, 출퇴근 시각, 휴게시간과
메모를 수정할 수 있다. 두 진입점은 같은 근무기록 패널과
`PATCH /staffs/work-records/{id}/` 계약을 사용하므로 금액과 근무시간은 서버가
다시 계산하고 변경 이력을 감사 로그에 남긴다. 월 마감 상태를 확인 중이거나
확인에 실패한 경우, 그리고 이미 마감된 월에는 추가·수정·삭제를 모두 막는다.
현재 월에 새 기록을 추가할 때만 오늘을 날짜 후보로 채운다. 과거·미래 월은
날짜를 비워 실제 근무일 선택을 요구하고, 날짜 선택기는 선택한 월에서 바로 열린다.
수정 화면은 기존 날짜를 보존한다. 직원 선결제 환급의 관리자 수기 추가도 같은
날짜 규칙을 사용한다. 개인 프로필 지출의 과거 월 첫날 기본값은 별도 계약이다.
직원 상세의 `비용` 탭도 `/workspace/staff/expenses`와 같은 패널을 사용해 대기
환급의 추가·수정·삭제·승인·반려와 상태 필터를 동일하게 제공한다.
월 마감 성공 뒤에는 필터 객체를 포함한 근무기록·비용 목록 캐시를 루트 키로
무효화해 다른 운영 탭으로 돌아왔을 때 마감 전 데이터를 재사용하지 않는다.
근무기록 저장·삭제, 환급 추가·수정·승인·반려·삭제, 월 마감 성공은 월 전체
급여판 캐시도 공통 루트 키로 무효화한다. 따라서 직원별 화면에서 급여판으로
돌아오면 서버를 다시 조회해 근무 공제 전 총액, 승인 환급, 이체 예정액과
정산 상태를 갱신한다.

## 관리자 월 전체 급여판

상단에서 전체 직원의 근무 공제 전, 공제 후 급여, 승인 환급 포함 이체 예정액,
검토 인원을 비교한다. 직원 표와 모바일 카드에도 공제 전·기본 공제 3.3%·공제 후·환급을
각각 표시한다. 모든 금액은 서버 응답의 원 단위를 사용하고 근무시간은 소수 둘째 자리까지
표시한다. 검색·상태 필터는 목록만 좁히며 상단은 전체 합계임을 표시한다.
이체 예정액을 송금 완료로 안내하지 않는다. 마감 금액과 원장 불일치는 대사 필요로 표시한다.

`/workspace/staff/attendance`는 직원이 선택되지 않았을 때 빈 상세 패널 대신
월 전체 급여판을 연다. 서버의 `/staffs/payroll-overview/` 응답만 사용해 전체
근무 공제 전 총액, 근무시간, 승인 환급, 근무유형별 시간과 직원별 금액·상태를
표시한다. 상단은 공제 전·공제 후 급여·이체 예정액·확인 필요 인원을 나눠 비교하고,
산출 원장은 근무 공제 전 → 기본 공제 3.3%(3%+0.3%) → 공제 후 급여 →
승인 환급 → 이체 예정액 순서를 2열로 보존한다. 이름 검색,
`전체·확인 필요·마감` 필터와 `기본순·이체액 높은순·낮은순` 정렬은 URL에 저장되어
새로고침, 상세 탭 전환, 상세 진입 뒤에도 같은 조회 문맥을 유지한다. 검색 직후
필터·정렬·직원 선택을 연속 조작해도 현재 URL에 변경을 합쳐 직전 검색을 보존한다. 금액 동률은
서버가 준 직원 순서를 유지한다. 행을 누르면 같은 연월·검색·필터·정렬을 유지한 채
직원별 근태로 이동한다. 모바일은 선택 직원 상세 헤더를 즉시 화면과 초점에 놓되
직원 목록을 제거하지 않으며, 상세 헤더의 `전체 급여판`으로 돌아오면 진입 직원 행과
이전 스크롤 문맥을 복원한다. 상세에서 새로고침해 급여판 캐시가 비어 있어도 데이터가
준비된 뒤 한 번만 복원하며, 근태·비용/경비·월 마감·급여 정산·리포트 탭을 오가도 조회
문맥을 잃지 않는다. 모바일 핵심 보조 글자는 11px 이상, 이전·다음·전체 급여판 버튼은
40px 이상의 세로 조작 영역을 유지한다.

첫 화면은 중복 직원 목록 없이 급여판에 전체 폭을 사용한다. 행에서 직원을 고른
뒤에는 왼쪽 직원 목록과 오른쪽 상세를 함께 보여 대상을 빠르게 바꿀 수 있다.
PC는 비교 가능한 표를, 390px 화면은 재직·퇴사 상태와 직원별 승인 환급까지
포함한 구분선 기반 장부 행으로 쌓아 가로 스크롤 없이 제공한다. 이름·근무유형과
확인 사유는 왼쪽, 이체 예정액은 오른쪽에 정렬하고 공제 전·환급 근거는 행
아래에 유지한다. 상단 `확인 필요 인원`은 근무기록
이상뿐 아니라 비용 대기, 시급태그 누락, 월급 수동 확인, 마감 대사를 모두 포함한
직원 수이며, 백엔드 마감 차단 직원 수와 근무기록 점검 건수는 별도 문구로 구분한다.
검색·필터 결과가 0명이면 조건을 바꾸는 다음 행동을 안내하며 실제 행을 정상적인 빈
데이터처럼 오해시키지 않는다. 경고는 기록을 숨기거나 수정을 막지 않는다. 마감 상태와 검토 사유는 색상뿐 아니라 텍스트로 함께
표시하며 조회 실패를 0원으로 추정하지 않고 다시 시도 상태로 닫는다. 직위,
계정 유형, 직원관리 유효 권한은 서로 다른 API 필드로 표시하고 직위를 권한처럼
해석하지 않는다.

## 직원 목록과 일괄 작업

검색 중에도 선택 직원은 유지하며 엑셀·비밀번호·퇴사·시급 배정은 전체 목록에서 같은
선택 집합을 해석한다. 대상 이름을 표시하고 대표 행은 직원 일괄 작업에서 제외한다.
목록에서 사라진 선택 대상은 새로 선택하도록 안내하며 임의로 다른 직원으로 대체하지 않는다.
퇴사는 실제 재직 대상 이름과 수를 확인한 뒤 수행한다.

시급 태그는 모든 직원 화면에서 정확한 원/시간으로 표시한다. 일괄 배정은 태그와 대상 확인 후
실행하고, 일부 실패하면 이름·사유·완료 수를 창에 유지한다. 재시도는 실패한 직원만 처리하며
성공한 배정은 되돌리거나 중복 요청하지 않는다. 닫고 다시 열면 새 선택으로 시작한다.
배정 성공 시 직원 상세·급여판·본인 정보·선택 직원의 배정 캐시를 갱신하며,
퇴사 성공 시 직원 목록·상세·급여판을 갱신한다.

## 반응형·접근성

- 선택창은 1366px PC와 390px 모바일에서 화면 밖으로 넘치지 않는다.
- 근무유형과 비근무 로그인은 모두 키보드로 도달 가능하며 포커스 윤곽을
  표시한다. 처리 중에는 중복 제출을 막는다.
- owner·student·parent의 비밀번호 변경 권장 모달은 본문 스크롤을 잠그고
  포커스를 내부에 유지한다.
- 모바일 상단 타이머는 최소 44px 터치 영역을 유지하고 현재 상태를 색상뿐
  아니라 접근성 이름으로도 전달한다.
- 전환 애니메이션은 짧은 테두리·이동 피드백만 사용하고
  `prefers-reduced-motion`에서는 제거한다.

### 시급제 기본 공제 (2026-10-07)

시급제 직원은 기본 공제 3.3%를 사용한다. 대표 월 합계·직원별 표·본인 내역·마감
정산 화면은 서버 산출값만 표시한다. 마감 화면은 스냅샷 API의 `default_deduction`을
사용하고 기존 `reference_*` 응답 이름도 호환성을 위해 유지한다. 공제는 직원별
급여에서 원 단위 반올림하고 승인 환급은 그대로 더한다. 이체 예정액은 송금 완료
상태가 아니다. PDF·엑셀도 동일한 서버 정책을 사용하며 원금·마감 이력은 보존한다.
검증: 직원 운영 mock, 1366px/390px 실사용 월마감 및 PDF·엑셀 다운로드,
백엔드 실제 파일 내용·소액 반올림 합산·환급만 있는 월 회귀 테스트.

엑셀은 사용자 다운로드 클릭마다 기존 `force_rerun` 계약으로 새 작업을 요청한다.
이전 실패 작업이나 1시간 뒤 만료된 다운로드 URL을 다시 받지 않는다. 버튼은 생성 중
중복 요청을 막고, 실패 사유를 표시한 뒤 다시 누르면 실제 새 파일을 받을 수 있다.
자동 POST 재시도는 하지 않으며 PDF도 실패 메시지와 다시 클릭할 수 있는 상태를 유지한다.

개발 실사용 검증의 급여 다운로드는 인증된 QA 테넌트에서 실제 접수한 작업과
완료 응답, 요청 연월의 파일명을 연결한다. 해당 개발 버킷의 정확한 tenant/job 키와
서명·MIME·attachment 응답만 통과시키고 다른 테넌트·운영 버킷·앱 인증정보 전달·
리다이렉트는 차단한다. 실제 파일 바이트를 그대로 검증하며 정리는 같은 tenant의
`exports/<id>/`에 한정한다.

격리 실사용의 급여 검사에서는 1시간 근무에 61분 휴게 입력을 거부하고 원래 금액을
보존하는지, 30분으로 정정한 금액과 0분 복구 후 재조회가 일치하는지도 확인한다.
동일 일회용 학원의 표시 설정은 잘못된 JSON 거부→정상 저장→재조회→원래 이름
복구까지 실제 API로 확인하며, 다른 학원이나 운영 설정은 변경하지 않는다.
