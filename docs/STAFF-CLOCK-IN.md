# 조교 출퇴근·근무기록 화면 계약

조교가 시스템 로그인과 유급 근무 시작을 혼동하지 않고, 클리닉·현장 등
배정된 근무유형을 직접 선택해 출퇴근하며 같은 기록을 PC·모바일과 관리자
정산 화면에서 확인하는 현재 계약이다.

## 역할과 진입점

| 사용자·화면 | 진입점 | 가능한 작업 |
|---|---|---|
| 조교 `tenantRole=staff` | 새 로그인 직후 선택창 | 유형별 출근 또는 `출근하지 않고 로그인` |
| 조교 PC | 상단 근무 시계, `/workspace/profile/attendance` | 출퇴근·휴식, 본인 기간 기록·공제 전 근무액 조회 |
| 조교 모바일 | 상단 타이머, `/workspace/mobile/my-records` | 출퇴근·휴식, 본인 기간 기록·공제 전 근무액 조회 |
| 대표·admin | `/workspace/staff/*` | 직원별 기록·비용·월마감·정산 관리 |

`is_manager=true`인 강사·조교도 동료 직원의 시급·비용·정산 또는 직원 계정
설정에는 들어가지 않는다. `/staffs/me/`의 오래된 true 값만으로 메뉴나 직접 URL을
열지 않으며 `tenantRole=owner/admin`을 함께 확인한다. 직원 생성·수정·상세·목록·
Excel에도 이 오래된 값을 권한 토글이나 권한 열로 노출하지 않는다.

새 자격증명 로그인 성공 시에만 세션 힌트를 만들며, 새로고침이나 기존 토큰으로
브라우저를 다시 연 것만으로 선택창을 반복하지 않는다. 이미 열린 근무가 있으면
새 기록을 만들지 않고 현재 근무 상태로 이어진다.

## 프런트 구조와 상태 소유권

- `src/shared/staff/api.ts`가 `/staffs/me/` 직원 identity와 배정 근무유형 계약을
  소유한다. 관리자 화면과 조교·강사 상단 시계가 별도 타입이나 요청 함수를
  만들지 않는다.
- `src/features/staff-clock/`이 현재 근무 조회, 출근·휴게·퇴근 명령, 관련
  React Query 캐시 무효화와 경과시간 계산을 소유한다.
- PC `HeaderCenterStaffClock`, 모바일 `CompactStaffClockButton`, 로그인 선택창은
  모두 같은 `useStaffClock`을 사용한다. 화면별 타이머나 mutation을 복제하지
  않으며 진행 중 유형·시급은 현재 근무 API 응답만 표시한다.
- 공용 `src/shared/staff/queryKeys.ts`가 직원 identity, 현재 근무, 현재 근무자,
  근무기록·합계 캐시 루트를 소유한다. 관리자 정산과 본인 화면의 갱신은 문자열이
  우연히 같은 별도 키가 아니라 이 정본 키를 공유한다.
- 새 로그인 여부는 인증 화면의 세션 힌트일 뿐 근무 상태가 아니다. 인증 역할을
  읽은 뒤 `tenantRole=staff`일 때만 힌트를 만들며, 다른 역할로 로그인하면 남은
  힌트를 제거한다.

## 로그인 선택

- 로그인 자체는 시간을 계산하지 않는다.
- 선택창은 `00:00 · 아직 근무 시작 전`을 먼저 보여 준다.
- 서버가 `/staffs/me/`로 반환한 본인의 활성 `assigned_work_types`만 카드로
  표시한다. 카드에는 근무유형과 적용 시급을 함께 보여 준다.
- 근무유형 선택은 `POST /staffs/{staff_id}/work-records/start-work/`가 성공한
  뒤에만 창을 닫는다. 실패하면 오류를 알리고 선택창을 유지한다.
- `출근하지 않고 로그인`은 근무 API를 호출하지 않고 선택창만 닫는다. 이후에도
  상단 근무 상태에서 출근할 수 있다.
- 배정 유형이 없으면 출근 버튼을 만들지 않고 관리자에게 배정을 요청하도록
  안내한다. 비근무 로그인은 계속 허용한다.
- 조교가 아닌 owner·admin·teacher에는 로그인 선택창을 띄우지 않는다.
- 직원 역할은 과거 `must_change_password` 값이 남아 있어도 변경 권장 모달을
  표시하지 않고 출근 선택을 바로 연다. 실제 첫 로그인 계정 안내가 표시되는
  동안에만 출근 선택창을 렌더하지 않아 뒤 화면이 포커스를 가로채지 않는다.
- 로그인 선택창과 별개로 연결된 `Staff`와 배정 유형이 있는 강사·admin은 기존
  상단 근무 상태에서 본인 출퇴근을 계속 사용할 수 있다.

## 진행 중 근무와 퇴근

상단 근무 상태는 선택 유형, 출근 시점에 고정된 시급, 휴게를 제외한 실시간
경과시간을 표시한다. 휴식 중에는 타이머를 멈추고 `근무 다시 시작`을 제공한다.
퇴근 성공 시 기록을 닫고 기간 기록·합계·현재 근무자 캐시를 함께 갱신한다.

서버가 현재 상태를 불러오지 못하면 출근하지 않은 것으로 추정해 쓰지 않는다.
오류 상태와 `다시 시도`를 표시한다. 중복 출근 `409`, 월마감, 배정 변경 등
서버 오류는 원문 계약을 사용자 문구로 보여 주고 기존 선택을 유지한다.

## 본인 기간 기록

PC `근무 기록`과 모바일 `근무 기록 / 지출`은 정본 `WorkRecord`의 날짜,
유형, 출퇴근 시각, 휴게, 확정 근무시간, 출근 시점 시급, 금액을 읽기 전용으로
보여 준다. 진행 중 기록은 `계산 전`으로 표시한다. 기간 합계는 서버의
`/staffs/{staff_id}/summary/`를 사용하며 `총 근무액 (공제 전)`만 표시한다.
세금 3.3%나 실수령액을 임의로 추정하지 않는다.

이 화면은 레거시 `/core/profile/attendance/` 수기 기록을 읽거나 쓰지 않는다.
기존 레거시 행은 백엔드에 보존되지만 근무유형·출근 시점 시급을 안전하게
복원할 수 없으므로 현재 정산 기록과 자동 병합하지 않는다.

## 관리자 기록 정정

대표·admin은 `/workspace/staff/attendance`의 월 전체 근무 기록과 직원 상세
팝업의 `근무기록` 탭에서 잘못 입력된 날짜, 근무유형, 출퇴근 시각, 휴게시간과
메모를 수정할 수 있다. 두 진입점은 같은 근무기록 패널과
`PATCH /staffs/work-records/{id}/` 계약을 사용하므로 금액과 근무시간은 서버가
다시 계산하고 변경 이력을 감사 로그에 남긴다. 월 마감 상태를 확인 중이거나
확인에 실패한 경우, 그리고 이미 마감된 월에는 추가·수정·삭제를 모두 막는다.
직원 상세의 `비용` 탭도 `/workspace/staff/expenses`와 같은 패널을 사용해 대기
환급의 추가·수정·삭제·승인·반려와 상태 필터를 동일하게 제공한다.
월 마감 성공 뒤에는 필터 객체를 포함한 근무기록·비용 목록 캐시를 루트 키로
무효화해 다른 운영 탭으로 돌아왔을 때 마감 전 데이터를 재사용하지 않는다.

## 관리자 월 전체 급여판

`/workspace/staff/attendance`는 직원이 선택되지 않았을 때 빈 상세 패널 대신
월 전체 급여판을 연다. 서버의 `/staffs/payroll-overview/` 응답만 사용해 전체
공제 전 합계, 근무시간, 대상·마감·확인 필요 인원과 직원별 금액·상태를 표시한다.
행을 누르면 같은 연월을 유지한 채 직원별 근태로 이동한다.

첫 화면은 중복 직원 목록 없이 급여판에 전체 폭을 사용한다. 행에서 직원을 고른
뒤에는 왼쪽 직원 목록과 오른쪽 상세를 함께 보여 대상을 빠르게 바꿀 수 있다.
PC는 비교 가능한 표를, 390px 화면은 같은 정보를 직원 카드로 쌓아 가로 스크롤
없이 제공한다. 마감 상태와 검토 사유는 색상뿐 아니라 텍스트로 함께
표시하며 조회 실패를 0원으로 추정하지 않고 다시 시도 상태로 닫는다. 직위,
계정 유형, 직원관리 유효 권한은 서로 다른 API 필드로 표시하고 직위를 권한처럼
해석하지 않는다.

## 반응형·접근성

- 선택창은 1366px PC와 390px 모바일에서 화면 밖으로 넘치지 않는다.
- 근무유형과 비근무 로그인은 모두 키보드로 도달 가능하며 포커스 윤곽을
  표시한다. 처리 중에는 중복 제출을 막는다.
- owner·student·parent의 비밀번호 변경 권장 모달은 본문 스크롤을 잠그고
  포커스를 내부에 유지한다.
- 모바일 상단 타이머는 최소 44px 터치 영역을 유지하고 현재 상태를 색상뿐
  아니라 접근성 이름으로도 전달한다.
- 전환 애니메이션은 짧은 테두리·이동 피드백만 사용하고
  `prefers-reduced-motion`에서는 제거한다.
