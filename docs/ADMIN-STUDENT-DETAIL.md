# 관리자 학생 상세

## 목적과 진입
관리자·직원·교사는 학생 목록, 수강·출결 명단, 클리닉에서 같은 학생 상세를 연다.
기존 URL과 배경 화면을 유지하고 닫기·Escape·뒤로가기로 원래 업무에 돌아간다.
학생 ID가 바뀌면 탭과 하위 편집창을 새 학생의 상태로 시작한다.

## 정보 배치와 조작
이름·현재 강의·학교·관리 분류·계정 상태를 헤더에서 확인한다. `관리 중`은
업무 분류이며 로그인 허용과 별개다. `정보 수정`, `학생 화면 보기`는 바로
접근하고 알림톡 안내·비밀번호 초기화·관리 대상 변경·삭제는 `계정·관리`에 둔다.
계정 안내/비밀번호 변경/삭제의 기존 확인 절차와 서버 권한을 유지한다.
정보 수정 중에는 창을 닫지 못하게 하며 성공·실패 응답을 확인한 뒤 다시 조작한다.

데스크톱은 기본 정보·공통 메모를 왼쪽, 수강·시험·과제·오답노트·클리닉·질문·활동을
오른쪽에 둔다. 알림톡 이력은 펼쳐서 확인한다. 390px에서는 `연락처·메모 보기`로
기본 정보를 열며 모든 기록 탭을 두 줄에 표시한다. 탭은 좌우 방향키·Home·End를
지원하고 복사는 키보드로도 가능하다. 아이디의 점·기호를 제거하지 않고 표시값을
그대로 복사하며 실패하면 직접 복사 안내를 표시한다. 간단한 펼침 모션은
`prefers-reduced-motion`에서 생략한다.

## 저장과 복구
학생 공통 메모는 기존 `Student.memo`를 사용한다. 다른 곳을 누르거나 저장 버튼을
누르면 저장하며, 변경 없는 값은 전송하지 않는다. 학생별 저장을 직렬화하고
앞선 응답/재조회가 새 입력을 덮어쓰지 않게 한다. 상세의 닫기·다른 기록으로 이동·
정보 수정은 현재 메모 저장 결과를 기다린다. 실패 시 상세와 초안을 유지하고
`다시 저장`을 제공한다. 태그 추가·제거와 메모 저장은 목록/관련 명단 캐시도 갱신한다.
메모 수정 응답에서는 저장된 메모만 반영하여 응답에 없는 태그·수강 정보를 보존한다.
저장 전 시작한 상세 재조회는 취소하고 저장 후 최신 정보를 다시 받으므로 태그 변경과
저장이 겹쳐도 늦게 도착한 응답이 저장 결과를 되돌리지 않는다.
저장 순서는 QueryClient·학생별 요청 대기열로 보존하여 저장 중 상세를 닫고 다시 열어도
앞선 쓰기를 추월하지 않는다. 배포 변환에서 예외가 발생하는 Query mutation scope는
사용하지 않고 일반 mutation의 진행 상태 추적을 유지한다. 서버가 지운 메모를 `null`로
반환하면 빈 메모로 확인하며, 메모 필드가 누락된 응답은 저장 확인 실패로 처리한다.
저장을 요청한 인증 세션·테넌트는 대기 전에 고정한다. 대기 중 로그아웃·재로그인·학원
전환이 발생해도 이전 입력을 새 세션의 권한으로 자동 전송하지 않는다. 새 세션에서
입력이 남아 있다면 사용자가 명시적으로 다시 저장해야 새 요청을 만들 수 있다.

브라우저 뒤로가기에는 아직 저장하지 못한 초안을 인증 세션의 테넌트·직원·학생별 메모리
캐시에서 재진입 시 복원한다. 새로고침·탭 닫기는 저장 전 브라우저 경고를 표시한다.
사용자가 새로고침을 수락하거나 로그아웃·인증 만료로 캐시가 초기화되면 미저장
초안은 복구되지 않는다. 브라우저 영구 저장소에 학생 메모를 복제하지 않는다.
공통 메모와 강의 메모의 역할/공개 범위는 [메모 계약](STUDENT-LECTURE-MEMOS.md)을 따른다.
서로 다른 직원의 동시 변경 정책은 기존 학생 수정 API를 따른다.

## 조회 경계
질문은 `GET /community/posts/?author_student={id}&post_type=qna`로 해당 학생의
질문만 조회한다. 클리닉은 `GET /clinic/participants/?student={id}`를 사용한다.
각 기록의 전체 건수는 서버 응답을 사용하며 50건 이후는 `이력 더 보기`로 읽는다.
다음 페이지도 같은 학생 조건을 유지하고 서버의 임의 URL을 따라가지 않는다.
초기 로딩·정상 빈 값·실패를 구별하고 재시도를 제공한다. 추가 조회 실패에는
앞서 읽은 기록을 보존하고 페이지 간 중복 기록은 한 번만 표시한다. 성적·계정 알림톡·맞춤 정보도 오류를 빈 값으로
단정하지 않는다. 잘못된 학생 번호/404와 일시 조회 오류를 구별한다.

학생·학부모 연결, tenant/역할 권한, 삭제·복원 및 질문 공개 범위는
[백엔드 학생 계약](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/student-core.md)이 소유한다.
기존 학생/학부모 계정·학습 기록·첨부·메모를 이전하거나 삭제하지 않는다.

## 선생님 앱의 질문 이력

`/workspace/mobile/students/:studentId`의 **질문** 탭도 서버가 지원하는
`author_student` 조건으로 현재 학생이 작성한 글만 조회한다. 기존에 보내던
`created_by`는 서버 조회 필터가 아니어서 선택 학생과 무관한 학원 게시글이
표시될 수 있었다. 학생 번호는 Student ID이며 로그인 계정 ID로 변환하지 않는다.

이 화면은 기존 범위인 학생 작성 글(Q&A·상담 등)을 유지한다. 관리자 상세의
`post_type=qna` 전용 목록과 달리 상담을 제외하지 않는다. 최신 50건부터 표시하고
**이력 더 보기**는 같은 학생 조건으로 다음 페이지를 요청한다. 서버가 반환한
임의의 다음 URL을 직접 열지 않으며, 페이지가 겹친 기록은 한 번만 표시한다.

초기 조회·빈 이력·실패를 구분하고 **다시 시도**를 제공한다. 추가 조회가 실패하면
앞서 읽은 기록을 보존하고 실패한 페이지를 재시도한다. 잘못된 응답은 빈 목록으로
간주하지 않는다. 다른 학생으로 이동하면 그 학생의 별도 조회 키로 기록을 읽는다.
`e2e/teacher/student-question-history.mock.spec.ts`는 두 학생의 작성자 범위, 51번째
상담, 재로드·학생 전환, 초기·추가 조회 실패와 복구, 정상 빈 이력을 390px와
데스크톱에서 확인한다.
같은 산출물의 `student-parent-community-realuse.spec.ts`는 학부모가 선택 자녀로
작성한 질문·상담이 해당 학생의 선생님 상세에서만 표시되는지, 다른 자녀의
빈 이력과 재로드까지 격리 개발 환경에서 확인한다.

## 선생님 앱의 클리닉 이력

같은 학생 상세의 **클리닉** 탭은 `student={id}`로 선택 학생의 참가 기록을
조회한다. 최신 100건을 먼저 보여 주고 **클리닉 이력 더 보기**로 그 이전
기록을 계속 읽는다. 모든 페이지에 학생 조건과 생성일·ID 내림차순을 유지하며
서버의 다음 URL을 직접 따르지 않는다. 중복 기록은 한 번만 표시한다.

첫 조회 중에는 로딩 상태를 보여 주며 실패를 **클리닉 이력 없음**으로
오인시키지 않는다. 초기 실패와 추가 조회 실패 모두 **다시 시도**를 제공하고,
추가 조회 실패에는 이미 읽은 기록을 유지한다. 잘못된 응답도 재시도할 수
있는 오류로 표시한다. 학생을 바꾸면 독립된 조회 키를 사용한다.
오류 안내와 재시도는 화면 가운데로 가져와 긴 이력 아래에서 놓치지 않게 한다.
이동은 사용자의 reduced-motion 설정을 따른다.

취소된 참가 기록도 기존 API 공개 범위 안에서 이력으로 유지한다. 세션 제목,
운영일·시작 시간·장소·클리닉 사유·상태 표시를 보존하며 예약·취소·등원·출결
저장 정책, tenant/역할 권한 및 기존 데이터는 변경하지 않는다. 예약과 실제
이용 시간 정책은 [클리닉 도메인](../src/app_teacher/domains/clinic/README.md)이 소유한다.

`e2e/teacher/student-clinic-history.mock.spec.ts`는 101번째 기록, 초기·추가 조회
오류와 잘못된 응답의 복구, 정상 빈 이력, 학생 전환·새로고침을 390px와
1366px에서 검증한다. 격리 개발의 `student-parent-clinic-realuse.spec.ts`는
학생 예약 → 학부모 조회·취소 → 서버 저장 확인 → 선생님 이력·새로고침까지
같은 실제 참가 기록으로 확인하고 기존 가족·참가자 정리 및 cleanup-zero를 따른다.

## 검증과 배포
- `e2e/admin/student-detail-entrypoints.mock.spec.ts`: 주요 진입/복귀, 하위 창,
  화면 폭 1366/1100/390, 키보드·복사, 느린 메모 저장·새 입력·실패·재시도,
  잘못된 ID, 기록 조회 실패와 50건 이후.
- 기존 맞춤 컬럼·강의 메모 테스트로 후속 화면의 회귀를 검사한다.
- 학생 상세 회귀는 `test:e2e:bundle-smoke`에서도 실행하여 배포용 JavaScript의
  저장·대기열·빈 메모 응답을 확인한다. 개발 서버 실행만으로 통과를 판단하지 않는다.
- `e2e/student/student-parent-community-realuse.spec.ts`: 동일 배포 산출물의
  격리 개발환경에서 실제 학생별 질문·상담 구분, 형제 학생 격리, 관리자 메모
  저장→reload→학생 프로필 반영과 desktop/390px 화면을 검증한다.
  기존 합성 가족/게시글 정리와 tenant/user 잔여 0 게이트를 유지한다.
- 서버의 작성자 필터를 먼저 배포한다. DB migration이나 데이터 변환은 없다.
  기존 클라이언트/API와 호환하며 열린 앱을 강제 새로고침하지 않는다.
