# 개발자 콘솔 운영 화면 계약

`https://dev.hakwonplus.com/dev/*`는 Academy SaaS 플랫폼 운영자가 테넌트와
운영 신호를 확인하고 허용된 조치를 실행하는 별도 콘솔이다. 이 화면의 첫 번째
목표는 많은 수치를 보여 주는 것이 아니라 **지금 확인할 위험, 영향을 받는 경계,
다음 안전한 조치**를 빠르게 판단하게 하는 것이다.

## 접근과 환경 경계

- `program.isPlatformAdmin`이 명시되면 그 값을 권한 기준으로 사용한다. 구형
  응답만 `hakwonplus` 또는 `9999` 테넌트 코드로 폴백한다. 허용되지 않은
  사용자는 `/workspace`로 돌려보낸다.
- 좌측 레일과 모바일 전체 메뉴는 같은 라우트 목록을 사용한다. 기능을 추가하거나
  제거할 때 두 메뉴를 따로 수정하지 않는다.
- 화면 상단 운영 상태 레저는 현재 실행 환경, 플랫폼 관리자 경계, 인증 테넌트와
  현재 섹션을 계속 노출한다. `dev.hakwonplus.com`에서만 `PRODUCTION`으로
  표시하고 로컬 개발 서버는 `LOCAL PREVIEW`로 구분한다.
- `운영 콘솔` 링크는 개발자 전용 origin에서는 중앙 운영 origin의 `/workspace`로,
  로컬 통합 개발에서는 현재 origin의 `/workspace`로 이동한다.

## 정보 구조

| 라우트 | 주 업무 | 쓰기 경계 |
|---|---|---|
| `/dev/dashboard` | 매출·테넌트·문의·자동화 상태와 우선 확인 큐 | 읽기 전용 |
| `/dev/tenants` | 테넌트 검색·생성·활성 상태 관리 | 생성·상태 변경 |
| `/dev/tenants/:tenantId` | 사용량·활동·브랜딩·도메인·소유자 | 탭별 명시 조작 |
| `/dev/billing` | 구독 만료·인보이스·입금 신고 | 기간 연장·입금/세금계산서 기록 |
| `/dev/inbox` | 도입 문의·버그·개선 의견 분류와 답변 | 답변·처리 상태·운영 메모 |
| `/dev/product-analytics` | 역할별 방문·참여·완료 신호 | 읽기 전용 |
| `/dev/automation` | 감사 로그 필터와 허용된 크론 실행 | 화이트리스트 크론만 실행 |

대시보드는 다음 순서로 읽는다.

1. 오늘의 운영 요약에서 즉시 확인할 경계 수를 판단한다.
2. 핵심 지표와 주의 신호에서 규모와 영향도를 확인한다.
3. 우선 확인 큐에서 결제, 문의, 자동화, 만료 경계로 이동한다.
4. 최근 활동과 점검 모드에서 방금 발생한 변경과 플랫폼 자세를 확인한다.

우선 확인 큐는 백엔드 요약값을 재분류할 뿐 새로운 비즈니스 상태를 만들지 않는다.
연체 인보이스, 미답변 문의, 24시간 실패 작업, 7일 이내 만료가 0보다 크면 확인
항목으로 강조한다. 값이 0이어도 경계를 숨기지 않고 정상 상태로 보여 준다.

## 시각·반응형 계약

- 콘솔은 밝은 작업면과 어두운 제어 레일을 사용한다. 명령은 파랑, 주의는 앰버,
  실패는 빨강, 확인 완료는 틸로 고정한다. 색만으로 상태를 전달하지 않고 문구와
  수치를 함께 표시한다.
- 본문과 조작은 앱 산세리프를, 테넌트 코드·시각·액션·운영 수치는
  `SFMono-Regular` 계열을 사용해 사람 언어와 시스템 식별자를 구분한다.
- 데스크톱은 252px 제어 레일과 최대폭 작업 캔버스를 사용한다. 넓은 화면에서
  카드가 무한히 늘어나거나 작은 글자가 퍼지지 않게 한다.
- 768px 이하에서는 좌측 레일을 숨기고 상단 명령 바와 하단 핵심 메뉴를 사용한다.
  하단에는 `대시보드`, `테넌트`, `문의함`, `전체`만 두고 결제·기능 신호·자동화는
  전체 메뉴에서 제공한다. 390px에서 문서 가로 스크롤이 없어야 한다.
- 모션은 새로고침 진행, 메뉴 전환, 상태 피드백에만 사용한다.
  `prefers-reduced-motion: reduce`에서는 애니메이션과 전환을 제거한다.
- 키보드 포커스는 모든 메뉴, 버튼, 탭, 명령 팔레트 항목에서 2px 윤곽으로
  명확하게 보여야 한다. 글로벌 검색은 `Cmd/Ctrl+K`와 사이드바/모바일 검색
  버튼으로 동일하게 연다.

## 조회 실패와 쓰기 안전

- 목록 조회 실패를 빈 배열 또는 0건으로 표시하지 않는다. 원인을 설명하고
  `다시 시도`를 제공한다.
- 테넌트 조회 실패 시 생성·소유자 추가를, 결제 구독 조회 실패 시 기간 연장을,
  인보이스 조회 실패 시 입금 확인을, 크론 목록 조회 실패 시 수동 실행을 잠근다.
- 테넌트 브랜딩 조회 실패는 빈 설정으로 대체하지 않는다. 오류와 `다시 시도`만
  표시하고 성공 조회 전에는 로고 업로드, 표시값 편집, 저장을 노출하지 않는다. 이전
  성공값을 본 뒤 재조회가 실패하면 로컬 편집 기준을 폐기하고, 재시도 성공값으로 폼을
  다시 초기화해 수정하지 않은 필드를 오래된 값으로 덮어쓰지 않는다.
- 대시보드 조회 실패 시 이전 수치나 추정값을 보여 주지 않는다. 오류 안내와
  재시도만 제공한다.
- LIVE 결제 조작, 소유자 임퍼소네이션, 크론 실행의 기존 확인·감사 계약을
  유지한다. 시각 리뉴얼은 API payload, 테넌트 범위, 권한 또는 확인 단계를
  변경하지 않는다.
- 테넌트·소유자 생성과 승격의 상세 실패 안전 계약은
  [DEV-TENANT-OPERATIONS.md](DEV-TENANT-OPERATIONS.md)를 따른다.

## API 경계

프런트엔드 콘솔은 `src/app_dev/domains/*/api`의 기존 `/core/dev/*`, billing,
inbox API를 그대로 사용한다. 대시보드 60초 자동 갱신과 각 도메인 query key를
보존하며, 쓰기 성공 후 소유 hook이 관련 query를 무효화한다. 새 UI 상태를
localStorage에 영속화하지 않는다. 임퍼소네이션 토큰 보존·복구만 기존 별도
계약을 사용한다.

## 검증

```powershell
pnpm typecheck
pnpm guard:legacy-api
pnpm lint
pnpm build
$env:E2E_BASE_URL='http://127.0.0.1:5174'
pnpm exec playwright test e2e/admin/dev-console-enterprise.mock.spec.ts e2e/admin/dev-console-owner-safety.mock.spec.ts --project=chromium --reporter=list
pnpm test:e2e:gate
```

`dev-console-enterprise.mock.spec.ts`는 1440px에서 운영 상태 레저, 우선 확인 큐,
감사 활동과 문서 폭을 확인하고 390px에서 핵심 하단 메뉴, 전체 메뉴의 나머지
라우트, 문서 가로 넘침을 확인한다. 운영 배포 뒤에는 `dev.hakwonplus.com`의
로그인·origin 경계와 인증된 읽기 전용 라우트를 데스크톱/390px에서 다시 본다.
