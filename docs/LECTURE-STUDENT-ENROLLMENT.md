# 강의에 기존 학생 직접 등록

강의 상세 → 수강생 등록은 학원의 기존 학생 선택 명단을 바로 연다.
교직원은 차시·엑셀 없이 여러 학생을 선택하고 `N명 강의에 추가`로 저장한다.
학생 검색은 이름·학교·전화번호를 사용하며 전화번호의 공백·하이픈을 정규화한다.
검색창 바로 아래 학교 구분·학년 조건을 함께 적용한다. 예를 들어 `언남` 검색에
`고등`·`1학년`을 선택하면 해당 조건을 모두 만족하는 학생만 불러온다.
학교 구분과 학년 범위는 학원의 학교급 설정을 따르며, 초등 4–6학년 선택 후
중등으로 바꾸면 유효하지 않은 학년 조건을 해제한다. 조건 초기화는 검색어와
선택 명단을 유지한다. 개편 중 빠졌던 조건 선택을 복구하며 기존 수강 데이터는 변경하지 않는다.
이름이 같은 학생은 학교·학년·학생/학부모 연락처로 구분한다.
선택 화면은 학생의 실제 이름을 그대로 표시하며 페이지별 임시 번호를 붙이지 않는다.
키보드/스크린리더에서도 학교·연락처 설명으로 동명이인을 구분할 수 있다.
관리자 PC 화면에서는 왼쪽에서 학생을 계속 검색하면서 오른쪽 선택 명단의 이름·학교와 학생·학부모 연락처를 대조한다. 좁은 화면에서는 같은 명단이 검색 결과 아래에 놓인다.
선택 명단에는 등록된 연락처가 없는 역할을 `번호 없음`으로 표시하고, 발송을 끈 역할은 연락처 옆에 `발송 안 함`을 표시한다. 실제 발송 여부는 등록 후 수신자별 결과에서 확인한다.

- 검색·조건 변경과 페이지 이동 중에도 선택 명단을 유지한다. 조건 변경 시 첫
  페이지부터 조회한다. 현재 페이지 선택은 필터를 만족하는 해당
  페이지의 미등록 학생만 추가한다. 모두 선택한 페이지는 같은 버튼으로 해당
  페이지만 해제할 수 있다. 하단 선택 목록에서 개별/전체 해제한다.
- 기존 ACTIVE 수강생은 `수강 중`으로 표시한다. 학생·학부모 중 한 명 이상에게 기존 수신자 포함 발송을 선택하면 수강 중인 학생도 선택할 수 있다.
  INACTIVE/PENDING 학생은 재등록 대상/등록 대기로 구분하며 명시적 선택 시 ACTIVE로
  전환한다. 한 번에 최대 200명을 처리하고 초과 선택을 알린다.
- 엑셀은 별도 보조 동작으로 유지한다. 학생 선택 중 닫기·엑셀 이동은 미저장
  선택 취소를 확인한다. 등록 중 닫기·중복 제출을 막는다.
- 조회 실패는 빈 목록과 구별하고 재조회한다. 저장 또는 저장 확인 실패는 선택을
  보존하고 재시도를 제공한다. 서버가 등록을 승인한 뒤 확인만 실패했다면 선택을
  고정하고 `등록 결과 다시 확인`으로 읽기만 재시도하며 등록 요청을 반복하지 않는다.
  성공 전 전체 수강 명단을 재조회해 선택한 학생의 ACTIVE 상태를 확인한다.
  확인된 명단은 즉시 반영하고 강의 인원·출결·학생 목록은 백그라운드 갱신한다.
  느린 주변 화면 조회 때문에 등록 완료를 지연시키지 않는다.
- 한글 조합 종료·Enter·추가 클릭을 기다리지 않고, 화면에 표시된 검색어의 입력이
  250ms 멈추면 검색한다. 마지막 한글 음절이 조합 중이어도 결과를 볼 수 있다.
  검색 대기/페이지 전환 중 이전 목록은
  선택할 수 없으며 검색 중임을 표시한다. 이전 검색 요청을 취소하고 30초 이내
  재방문한 학생 페이지는 캐시를 사용한다. 수강 상태는 별도로 최신 조회한다.
  격리 개발 실사용의 `student-parent-learning-realuse.spec.ts`도 390px·데스크톱에서
  조합 종료 전 실제 검색 응답을 확인하고, 등록·새로고침·학생/학부모 학습 화면까지 이어서 검사한다.
  학생 검색 실패는 이미 선택한 학생의 등록을 막지 않으며, 수강 상태 조회 실패는
  재조회 후 등록한다. 검색어 지우기는 검색창 포커스를 유지한다.

## 등록 시 로그인 정보 알림톡

관리자 강의의 수강생 등록 모달과 교사 강의의 수강생 탭 등록 화면 모두 추가 버튼 위에
첫 수강 확정 시 학생과 학부모에게 계정 안내를 자동 요청한다는 설명을 표시한다. 390×600 화면에서도 이 안내와 변경한 수신자별 설정 요약은 등록 버튼과 함께 고정된다. 상세 설정은 본문에서 펼치며 학생 명단을 스크롤해도 버튼 위의 발송 요약을 확인할 수 있다.
원장·관리자·교사는 `수신자별 발송 설정`에서 학생과 학부모를 각각 설정한다. 조교는 기본 설정으로 수강을 등록하고 자신이 요청한 결과를 확인할 수 있다.

- `첫 수강 시 자동 발송`은 첫 수강 대상만 발송한다. 추가 수강에 중복 요청하지 않는다.
- `기존 수신자 포함 발송`은 과거 안내 수신 여부와 관계없이 요청한다. 이미 수강 중인 학생도 선택할 수 있고 저장 직전 대상과 중복 가능성을 확인한다.
- `발송 안 함`은 해당 수신자에게 이번 알림톡을 보내지 않는다. 최초 수강에서 선택한 미발송은 이후 자동 발송에서도 유지된다. 두 사람 모두 끄면 강의 등록만 진행한다. 학부모에게 보내는 안내에는 학생 로그인 정보도 포함된다.

등록 후 수강 명단 위 `최근 등록 알림톡 결과`에 현재 교직원이 이 강의에서 마지막으로 요청한 학생별 학생·학부모 결과를 표시한다.
연락처 없음, 같은 번호로 학부모 안내에 포함, 선택에 따른 미발송, 최초 수강 대상 아님, 대기·처리·접수·실패·불명·최종 전달을 구분한다.
대기·처리 상태는 화면에서 갱신하고 `발송 상태 새로고침`으로도 조회한다. 로그가 있으면 `최종 전달 확인`을 눌러 공급자 결과를 확인한다.
공급자가 결과를 제공하지 못하거나 조회 요청이 실패하면 마지막으로 확인한 발송 상태와 함께 조회 안내를 표시한다. 같은 수신자의 조회를 다시 시도해도 안내를 재발송하지 않는다.
새로고침 및 다른 기기에서 서버의 최근 결과를 읽는다. 처리 여부가 불확실한 요청은 같은 탭·학원·교직원·강의에 요청 번호와 선택만 임시 보관한다.
다시 열고 `등록 결과 다시 확인`을 누르면 정확한 요청을 읽는다. 서버에서도 찾지 못했을 때에만 사용자가 같은 요청 번호로 재시도를 선택할 수 있다.
서버 결과와 활성 수강 명단을 모두 확인하면 복구 정보를 지운다.

## API와 데이터 경계

`GET /students/`의 페이지 목록과 `GET /enrollments/?lecture=...`의 전체 명단을
사용한다. 관리자와 교사의 직접 등록은 `POST /enrollments/register-with-notices/`에 강의·학생 ID 목록, 요청 UUID와 학생·학부모 각각의 발송 선택을 보낸다.
`GET /enrollments/registration-notices/?lecture=…`는 현재 학원·강의·요청자의 최근 결과를 조회하고, `request_id` 지정 시 해당 요청만 조회한다.
`POST /enrollments/verify-registration-notice/`는 강의·요청 번호·발송 로그가 같은 등록 요청에 속할 때 최종 전달 결과를 확인하고 저장한다. 이후 최근 결과에서도 확인한 전달 성공·실패를 조회한다.
학교 구분·학년은 `GET /students/`의 `school_type`·`grade`로 검색어와 함께 전달한다.
조건마다 별도 캐시를 사용하고 서버 페이지 전체에 적용하므로 현재 페이지에서만
학생을 거르는 방식이 아니다. 조건 조회 중 이전 목록의 선택을 잠그며 실패 시
조건·선택을 보존하고 재조회한다. 0명일 때 검색어/조건 변경 안내를 표시한다.
기존 학원·교직원 권한 검증과 삭제 학생 차단, 수강료·첫 계정 안내 정책을 유지한다.
강의 수강만 저장하며 차시·차시 배정·출결은 만들지 않는다. 이후 각 차시의
`강의 수강생 불러오기`에서 출결 대상을 선택한다.
백엔드 정책: [학생 생명주기](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/student-lifecycle.md).

기존 방식 선택 화면의 차시 생성 유도는 직접 선택 UI로 대체했다. 차시 생성은
원래 강의의 수업 추가에서 계속 제공하며 기존 수강/차시/출결 데이터는 변경하지 않는다.

## 접근성·검증

키보드 체크박스, 검색 라벨, 선택 상태 안내, 저장 오류 안내, 모달 포커스 유지와
이탈 복귀를 제공한다. 390px에서 연락처를 다음 줄에 배치하고 명단·선택 목록을
독립 스크롤한다. 명단 높이를 남은 공간에 맞춰 검색창·선택 요약·저장 버튼을 유지한다.
선택 전후 요약 높이를 일정하게 해 화면이 밀리지 않게 한다. 낮은 창/가상 키보드에서는
본문 스크롤로 모든 항목에 접근한다. 선택 칩의 짧은 전환은 reduced-motion에서 끈다.

`e2e/admin/lecture-student-picker.mock.spec.ts`는 1366/1100/390px 등록, 페이지·검색
선택 유지, 활성 중복 제외와 재등록, reload, 저장 확인 실패/재시도, 이탈 취소,
200명 한도, 한글 조합/느린 응답/캐시, 검색 실패 중 저장, 지연된 출결 갱신,
낮은 모바일/다크 테마와 이름·전화번호 명단 검색을 검사한다. 같은 학교의 다른
학년 구분, 학교급 조건, 조건 초기화·빈 결과·조회 실패 복구와 초등 학년 범위도 확인한다.
기존 Excel 회귀도 같은 등록 버튼에서 시작한다. 수신자별 중복 발송 확인·취소, 전체 미발송, 접수와 공급자 최종 전달의 구분, 응답 유실 후 새로고침과 동일 요청 번호 복구를 검사한다. 교사 화면은 `e2e/teacher/student-search.mock.spec.ts`에서 등록 후 학생·학부모 결과의 재조회를 확인한다.
`student-parent-learning-realuse.spec.ts`는 격리 개발 환경에서 차시 없는 강의에
UI로 학생을 등록하고 reload 및 이후 교사·학생·학부모 학습 화면까지 확인한다.
학교명 검색과 학교 구분·학년 조합으로 한 학년만 선택한 뒤 다른 학년을 추가해
선택이 유지되고 최종 수강 명단에 함께 저장되는지 실제 API로 검증한다.
이 합성 QA 시나리오의 390px·데스크톱 스크린샷은 `development-release-evidence`
산출물에 정확한 파일명으로 보존해 동일 배포 후보의 화면을 검토한다. 운영 학생
정보나 다른 실사용 시나리오의 스크린샷을 이 업로드에 포함하지 않는다.

강의 상세 명단은 출결 matrix의 기존 차시 이력과 ACTIVE 강의 수강 명단을 학생 ID로
합쳐 표시한다. 차시 미배정 학생도 저장·reload 후 보이며 출결은 빈 값으로 유지한다.
기존 차시 이력은 제거하지 않는다. 출결 엑셀 다운로드는 기존 차시 출결 내보내기다.
강의 명단의 전화번호 검색은 숫자·공백·괄호·하이픈 입력에만 적용한다. 한글 이름이나
숫자를 포함한 이름이 빈 전화번호 검색 조건으로 전체 학생과 일치하지 않도록 한다.
명단에 표시된 동명이인 구분명도 검색할 수 있다.
