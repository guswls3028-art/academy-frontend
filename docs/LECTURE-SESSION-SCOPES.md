# 강의 정규 수업·보강 진입 계약

## 목적과 진입점

원장과 선생님은 관리자 앱의 **강의 → 강의 상세**에서 기존처럼 전체 수업을
순서대로 보거나, 정규 진도 수업과 보강 수업을 나눠 관리한다. 화면 상단의
`보기 방식` 필터가 `전체 보기`와 `정규·보강 나눠 보기`를 전환한다. 나눠 보기의
`정규 수업`과 `보강` 탭은 해당 유형의 수업 수를 함께 보여 준다.

데이터와 권한 규칙은
[backend/docs/domain/lecture-sessions.md](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/lecture-sessions.md)가
소유한다.

## 강의 목록 순서와 생성·설정

- 활성/지난 강의 목록은 API의 tenant별 `display_order`, `id` 순서를 기본으로
  사용한다. 검색어와 열 정렬이 모두 비어 있을 때만 작은 점 손잡이 drag,
  손잡이의 위·아래 방향키, 손잡이를 눌러 여는 위·아래 메뉴로 scope 전체 순서를
  저장할 수 있다. 폭 40px의 열에 테두리 없는 점 아이콘을 표시한다. desktop과
  390px mobile 모두 손잡이 hit target을 40×40px로 보장한다.
- 목록은 각 강의의 `ACTIVE` 수강등록 수를 `수강생` 열에 표시하고, 현재 검색
  결과의 합을 상단 `강의 N개 · 수강 등록 N명` 요약에 함께 표시한다. 이 값은
  학생 계정 수나 중복 제거 학생 수가 아니라 강의별 현재 수강등록 합계다.
- 검색 결과나 임시 열 정렬은 표시만 바꾸며 부분 목록을 서버에 저장하지 않는다.
  이때 순서 조작을 비활성화하고 이유를 화면에 표시한다.
- 순서 저장 중에는 중복 조작을 막는다. 저장 실패 또는 stale `409`는 mutation 전
  query snapshot으로 정확히 되돌린 뒤 tenant 강의 목록을 다시 조회한다.
- 현재·지난 강의 설정 메뉴에서 직원이 **강의 삭제**를 선택하면 강의 이름, 복구
  불가, 사용 기록이 없는 차시·분반 등 연결 설정의 삭제 가능성을 확인한다. 취소가
  기본 포커스이며, **영구 삭제**를 확인해야 tenant 범위의 기존 강의 삭제 API를
  호출한다. 서버가 보호하는 수강·출결·게시물·수강료 설정 등의 연결 기록이 있으면 강의는
  유지되고 실패 이유를 표시한다. 기록을 보관하려는 경우 활성 강의는 **강의 종료**를
  이용한다. 성공 시 목록과 상태 캐시를 재조회한다. 삭제 확인·취소·실패·새로고침은
  `e2e/admin/lecture-management-ordering.mock.spec.ts`에서 확인한다.
- 강의 생성 모달은 1100px에서 세부 정보와 일정·시간을 두 열로 보여 세로
  과밀을 줄이고, 좁은 화면에서는 한 열로 전환한다. portaled 시간 선택기는
  1100px에서 모달, 390px에서 viewport 경계를 벗어나지 않는다.
- 차시 설정의 작은 메뉴는 trigger 우측 정렬을 유지하지만, 편집 dialog는
  trigger에서 main 영역 쪽으로 열어 사이드바를 침범하지 않는다. `Escape`는
  dialog를 닫고 설정 trigger로 포커스를 돌려준다.

## 상호작용

1. 강의 상세에 처음 들어오면 호환 기본값인 `전체 보기`를 선택하고 정규·보강
   수업을 기존 순서대로 함께 보여 준다.
2. `정규·보강 나눠 보기`를 선택하면 `정규 수업`과 `보강` 탭을 노출한다.
   처음에는 정규 수업을 보여 주되, 현재 수업 상세에서는 그 수업의 유형을 맞춘다.
3. 나눠 보기에서 `보강`을 누르면 주말 클리닉 같은 보강 수업만 보여 준다.
4. 차시 상세에서 유형을 바꾸면 현재 반을 우선해 그 유형의 첫 수업으로
   이동하고, 출결·성적·시험·과제 등 현재 업무 탭은 유지한다.
5. 전체 보기로 돌아갈 때는 현재 수업과 업무 탭을 유지하고 목록만 다시 합친다.
6. 해당 유형에 수업이 없으면 첫 수업을 추가하도록 안내한다.
7. 나눠 보기의 추가 버튼은 생성 모달에서 같은 유형을 미리 선택한다. 전체 보기의
   추가 버튼은 기존 생성 흐름을 열어 사용자가 유형을 고르게 한다.
8. 정규 차시는 `차시 번호`와 별도로 `차시 이름 (선택)`을 입력한다. 예를 들어
   7차시를 `직보(직전보강)`으로 표시해도 `session_type=REGULAR`와
   `regular_order=7`을 유지한다. 이름을 비워 두면 번호로 표시한다. 번호 칸은
   숫자만 허용하며 이름을 입력해도 보강으로 자동 전환하지 않는다.
   보강은 정규 진도와 별도로 추가하는 수업으로, `보강 이름`과 날짜·시간을
   입력한다. 보강은 `regular_order`를 사용하지 않아 다음 정규 번호가 바뀌지 않는다.
   저장 이름은 강의 카드, breadcrumb, 출결·성적·시험 차시 선택에 재사용된다.
9. 보강 카드의 설정 메뉴에서 이름과 날짜를 수정한다. 이름 수정은 현재 상세
   화면을 닫거나 다른 경로로 이동시키지 않으며, 저장 후 재조회해 유지한다.
10. 정규 카드의 설정 메뉴에서는 `차시 이름 (선택)`, 날짜와 `차시 번호`를
    수정한다. 이름은 기존 `title`, 번호는 `regular_order`로 저장한다. 이름을
    지우면 빈 문자열을 저장해 `N차시` 표시로 돌아간다. 저장 직후 카드·상세
    제목을 갱신하고 새로고침 뒤에도 유지한다. 같은 강의·반에 이미 존재하는
    번호 등 서버 검증 실패는 편집 창과 입력을 유지하고 원인을 표시한다.
11. 차시·클리닉 시간 선택기는 30분 간격 목록과 `+30분`·`+1시간` 빠른 조정을
    유지하면서 `분 단위 직접 입력`을 함께 제공한다. 따라서 `19:20~22:00`,
    `16:30~19:10`처럼 학원 운영 시각을 반올림하지 않고 저장한다.
12. 차시 상세의 `공지·게시판` 탭은 현재 강의·차시 URL 안에서 같은 공지
    조회·작성·수정·삭제 화면을 연다. 현재 강의·차시 문맥을 쿼리에 고정하고
    범위 트리만 숨기며, 왼쪽 `커뮤니티`의 전체 콘솔과 같은 데이터·API·권한을
    사용한다. 탭을 오가도 차시 헤더와 출결 집계가 유지되어야 한다.

선생님 모바일 앱의 **강의 상세 → 차시 추가/편집**에서도 정규 이름은 선택
입력이다. 수정 시 유형을 변경하지 않고, 차시 목록·상세·출석표를 다시 조회한다.
목록의 편집 아이콘은 `차시 수정: {차시 이름}`이라는 이름의 독립 버튼이다.
정규·보강 모두 Tab으로 접근한 뒤 Enter·Space 또는 클릭으로 같은 편집 창을
열며, 닫거나 저장하면 누른 편집 버튼으로 포커스가 돌아온다. 취소는 저장 요청을
보내지 않는다. 차시 상세 이동 버튼과 편집 버튼은 서로 중첩하지 않는다.
학생 수업 목록과 영상 강의/차시 화면도 같은 표시 규칙을 사용한다. 영상 차시
직접 진입·새로고침은 해당 계정의 영상 목록 API에서 현재 이름을 조회한다.
이름 조회 실패는 기존 영상 목록을 유지하면서 오류와 다시 불러오기를 표시한다.

## API와 기존 데이터

기존 차시 `title`, `session_type`, `regular_order`, `order`, `display_label`을
사용하며 새 필드는 만들지 않는다. 명시적인 `session_type`이 유형 판단의
기준이므로 `보강`이라는 단어가 포함된 정규 이름도 정규 수업으로 유지한다.
이름 변경은 수업 ID, 표시 순서 `order`, 출결·시험·과제 연결과 권한을 바꾸지 않는다.
백엔드는 기존 tenant/강의 권한과 번호 중복 검증을 계속 담당한다.

정규 생성은 `session_type=REGULAR`와 선택적인 `regular_order`를 전송한다.
관리자 생성의 기존 시간 표기 결합은 유지하며 `title`에 이름과 시간이 저장된다.
선생님 생성과 두 앱의 수정에서 정규 `title: ""`을 허용해야 한다. 수정 요청은
이름과 번호만 바꿀 때 `session_type`이나 `order`를 전송하지 않는다.
보강의 빈 이름은 UI에서 차단한다.

응답의 사용자 지정 `display_label`을 우선 사용한다. 이전 API가 정규 이름을
무시한 번호 라벨을 반환하면 `title`의 사용자 이름으로 표시한다. 과거 자동
제목인 `1`, `1차시`, `1차시 (14:00~16:00)`은 현재 정규 번호로 표시하므로
번호 변경 후 옛 번호가 되살아나지 않는다. `직보(직전보강)`처럼 의미 있는
괄호와 이름 안의 `차시`는 보존한다. 기존 저장 데이터의 일괄 변환·삭제는 없다.

보기 방식은 화면 방문마다 `전체 보기`로 시작하며 서버나 브라우저 저장소에
사용자 선택을 기록하지 않는다. 반 편성 기능을 사용하는 tenant에서도 동일한
보기 필터를 적용한 뒤 공통 수업과 반별 수업 레인을 보여 준다. 필터를 바꿔도 반
구조나 수업 ID는 바뀌지 않는다.

강의의 **출석 관리** 표는 참여 인원이 많은 정규 운영을 우선하도록 화면 방문마다
`정규`를 기본값으로 사용한다. 상단의 `정규·보강·전체` 분할 필터는 각 차시 수를
표시하며, 선택 범위의 차시 열만 최근 차시부터 보여 준다. 보강 출결 데이터는
삭제하거나 숨은 기본값으로 저장하지 않고 `보강` 또는 `전체`를 누르면 즉시 다시
표시한다. 학생 검색·선택과 출결 값은 필터 전환에도 유지한다.

## 상태와 실패 처리

- 로딩 중에는 목록 로딩 상태를 표시한다.
- 목록 조회 실패 시 오류 문구와 `다시 불러오기`를 제공한다.
- 전체 목록이 비어 있거나 선택 유형이 비어 있으면 현재 보기 방식에 맞는 추가
  CTA를 제공한다.
- 생성·수정 실패는 서버 메시지를 가능한 범위에서 보여 주고 편집 입력과 기존
  카드 이름을 유지한다. 같은 입력으로 재시도하며 성공한 뒤 편집 창을 닫는다.
- 차시·보강 삭제 실패는 서버가 제공한 원인과 복구 안내를 기존 오류 피드백에
  표시한다. 응답의 안내가 비어 있으면 `차시 삭제에 실패했습니다.`를 유지한다.
  거절된 카드를 성공처럼 제거하지 않으며 다시 조회해도 원래 차시가 남는다.
  연결 커뮤니티 글을 확인해 불필요한 글만 삭제한 뒤 재시도할 수 있고, 글을
  보존하려면 연결 강의·차시를 유지한다. 권한과 삭제 결정은
  [백엔드 커뮤니티 정책](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/community.md)이
  소유하며 프런트에서 임의로 글이나 공개 범위를 변경하지 않는다.
- 정규 차시 번호는 1 이상의 정수로 검증한다. 이름이 비어도 정규 수업은 저장할
  수 있으며, 필수 날짜·시간 누락은 생성 화면에서 안내한다.
- 이름이 긴 정규·보강 수업은 카드 안에서 두 줄로 제한하지만 상세 경로와 접근 가능한 이름은
  전체 저장값을 사용한다.

## 접근성과 반응형

- 보기 방식 필터는 `group`과 `aria-pressed`를 사용한다.
- 시간 선택 목록은 빠른 30분 선택과 접근 가능한 `type=time` 직접 입력을 모두
  제공하며, 잘못된 값은 적용하지 않고 입력 가까이에 오류를 표시한다.
- 출석 관리의 차시 범위 필터도 `group`과 `aria-pressed`를 사용하며, 기본
  `정규` 선택을 보조기기에 전달한다.
- 나눠 보기의 유형 전환은 `tablist`/`tab`과 `aria-selected`를 사용한다.
- 현재 수업 카드는 기존 `aria-current`/선택 윤곽 계약을 유지한다.
- 보강 설정과 추가 버튼은 각각 `보강 설정`, `보강 추가`라는 명확한 접근 가능한
  이름을 가진다.
- 1366px, 1100px 데스크톱과 390px 모바일에서 보기 방식 필터, 두 유형 탭,
  현재 범위의 첫 수업에 키보드·터치로 접근할 수 있어야 한다.
- 정규 이름 입력은 연결된 label과 설명을 제공한다. 편집 창은 viewport 너비와
  높이를 넘지 않도록 제한하고 내부 스크롤로 저장·취소에 접근한다.

node --test scripts/tests/session-ordering.test.mjs

이름 회귀는 정규 생성·수정·실패 후 재시도·빈 이름 복원·재조회, 유형별 목록,
기존 자동 제목의 번호 변경, 긴 한글 이름과 390px 입력을 확인한다. API mock의
재조회 검증은 실제 백엔드 저장 또는 운영 검증을 대신하지 않는다. 통합 시 동일
후보의 격리 개발 환경에서 두 앱 저장 → 재조회 → 학생 표시와 tenant 격리를 확인한다.


## 차시별 수업일

관리자의 `/workspace/lectures/:lectureId/sessions/:sessionId`에서 한 차시를
수요일반·목요일반처럼 여러 실제 날짜에 진행한다. 새 차시나 평가 데이터를
복제하지 않는다. 수업일 설정이 없는 기존 차시는 기존 단일 날짜 흐름을 유지하며,
관리자 화면에는 작은 `수업일 관리` 진입만 추가된다.

### 관리 흐름

- `수업일 관리`에서 이름·실제 날짜·선택 시간과 학생 배정을 한 번에 저장한다.
  검색 결과 전체 선택 및 개별 선택 후 수업일을 배정한다. 같은 학생을 다른
  수업일에 배정하면 이전 배정에서 이동한다. 삭제는 배정만 해제하며 기존 출결,
  성적, 시험, 과제, 영상은 보존한다. 마지막 수업일까지 지우고 저장하면 원래
  차시 날짜로 돌아간다는 확인을 거친다. 학생이 없는 수업일도 저장할 수 있다.
- `이전 차시에서 가져오기`는 저장된 수업일이 없을 때만 사용한다. 작성 중인 내용을
  대신해 이전 설정을 가져와 즉시 저장하는 작업임을 확인한 뒤 실행한다.
  날짜 이동, 활성 명단과 신규 출결 UNSET 처리는
  서버가 소유한다. 클라이언트는 기존 기록을 복사하거나 상태를 추정하지 않는다.
- 저장 중 중복 작업과 닫기를 막는다. 실패 시 입력은 남고 재시도할 수 있다.
  창을 닫고 같은 차시에서 다시 열어도 입력이 남는다. 미저장 새로고침/페이지
  종료에는 브라우저 경고가 나온다. SPA에서 같은 차시의 탭 이동은 초안을 유지하고,
  다른 차시/화면 이탈은 폐기 확인을 거친다. 취소하면 원래 화면과 초안을 유지한다.
  차시별 컴포넌트 키로 다른 차시에 이전 초안이 제출되지 않게 한다. 이동/새로고침을 확정하면
  메모리 초안은 사라진다. 개인정보가 포함된 명단을 브라우저 저장소에 복제하지 않는다.
- 409는 동시 수정으로 표시하며 초안을 덮어쓰지 않는다. `최신 내용으로 다시 시작`
  선택과 미저장 폐기 확인 후 최신 명단/버전을 읽어 재작성한다. 400/통신 오류를
  빈 설정으로 바꾸지 않는다.

### 범위와 공용 자료

전체는 `schedule` 쿼리가 없고, 개별 수업일은 `schedule=<id>`, 미배정은
`schedule=0`이다. 차시 탭 이동에서 범위를 유지한다. 변경 시 출결/성적의 학생
선택을 비우고 출결 페이지를 처음으로 돌린다. 성적 편집 중 수업일 칩이나 관리
창을 열면 먼저 저장·편집 종료를 완료한다. 실패하면 기존 범위를 유지한다.

출결 목록과 일괄 현장 출석, 성적 표/출력용 출결/재조회·CSV·발송 준비에는
동일 범위를 보낸다. 화면의 검색·출결상태 필터는 일괄 현장 출석 대상이 아니며
서버 수업일 명단이 대상이다. 요약 출결 집계는 `전체 출결`로 명시한다.
시험·과제·영상·공지 탭은 차시 공용이며 필터링되었다고 표시하지 않는다.
수업일 정보/범위 검증 실패 시 선택한 명단 대신 전체 학생을 보여주지 않는다.
삭제한 수업일을 보고 있던 경우 저장 성공 후에도 URL 범위를 유지하고 오류를
표시한다. 사용자가 직접 전체/다른 수업일을 선택하기 전에는 명단을 표시하지 않는다.

쿼리 캐시는 수업일을 포함하며 저장은 모든 수업일의 출결·성적·등록 캐시를
무효화한다. 점수/출결 수정은 기존 기록을 그대로 사용하므로 다른 범위에서도
최신 내용이 조회된다. 수업일 관리 권한·테넌트 격리와 교차 차시/학생 검증은
기존 인증 API와 서버가 소유한다. 권한 오류를 우회하거나 전체 학생으로 재시도하지 않는다.

수업일 전환은 성적 저장/복구 보호 절차가 끝난 시점의 현재 URL에서 `schedule`만
변경한다. 출결 도구에서 명단으로 돌아온 직후 수업일을 눌러도 이전 `view=tools`가
되살아나지 않는다. 저장을 기다리는 동안 다른 탭/차시로 이동했다면 늦게 끝난
수업일 전환으로 원래 화면에 돌아가지 않는다. 기존 성적 저장 실패/복구 안내와
수업일 관리 초안의 이탈 확인은 유지한다. 저장 대기부터 전환 적용까지 수업일 선택
영역의 `aria-busy`로 처리 중 상태를 알린다.

### API 계약

`GET /lectures/sessions/{id}/schedules/` →
`{version,schedules:[{id,label,date,start_time,end_time,enrollment_ids}],roster:[{enrollment_id,student_name}],unassigned_enrollment_ids}`.
`PUT`은 `{version,schedules}` 전체 설정을 원자적으로 교체하며 신규 항목의 `id`는
생략한다. `POST`는 `{version,source_session}`으로 이전 차시 설정을 가져온다.
저장/복사 모두 같은 응답을 반환한다. 버전은 문자열이며 stale 409, invalid 400.

`GET /lectures/attendance/` 및 `GET /results/admin/sessions/{id}/scores/`에
선택된 `schedule` 쿼리를 보낸다. `POST /lectures/attendance/bulk_set_present/`는
`{session,schedule}` 본문을 보낸다. 전체에서는 `schedule`을 생략하고 `0`은 보존한다.
서버 정책 정본은 [backend 강의 도메인](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/lecture-sessions.md)에서 관리한다.

관리자 차시 상단은 선택한 수업일의 실제 날짜와 반 이름을 표시한다. 전체에서는
차시의 원래 날짜를 `기본 수업일`로 구분하고, 미배정에서는 날짜 대신 `수업일 미배정`을
표시한다. 상단과 선택 버튼은 같은 조회 결과를 사용하므로 저장·복구 후에도 함께 갱신된다.

### 학생·학부모 소비 화면

학생 세션 목록/상세와 Today 응답의 `date`는 본인 배정 실제 날짜 또는 null이다.
선택 필드 `schedule_label`, `schedule_configured`를 그대로 표시한다.
`schedule_configured=true && date=null`은 `수업일 미배정`이며 원래 차시 날짜로
대체하지 않는다. 달력 날짜 칸에 임의로 넣지 않고 별도 미배정 목록에서 상세로
진입한다. 공용 자료 링크는 유지한다. 배정된 학생은 달력/상세/Today/다음 일정에
반 이름을 볼 수 있다. 해당 필드가 없는 기존 단일 날짜 응답도 지원한다.

### 선생님 Today와 모바일

Today의 날짜별 조회는 서버 `schedule_dates` 중 오늘 항목의 이름·시간을 표시한다.
일치 항목이 하나면 기존 차시 상세·출석·성적 링크에 `schedule=id`를 이어 준다.
여러 항목이면 같은 차시 카드 안에서 오전/오후 등 수업일을 직접 선택해야
상세·출석·성적으로 진입할 수 있다. 일치 항목이 없으면 재조회로 복구하며 전체
명단으로 보내지 않는다. 독립 출석/성적 화면에도 실제 날짜·반 이름을 표시한다.
`include_progress`는 서버가 해당 날짜의 학생을 집계하며
`오늘 수업일 출결 입력`으로 표시한다. 수요일 원래 차시 날짜를 목요일 제목에
재사용하지 않는다. 차시 목록은 실제 날짜와 반 이름을 함께 표시한다.

Today 상단 `다음 수업` 요약과 `수업 열기`도 오늘에 해당하는 실제 수업일을 시작
시각순으로 정렬해 반 이름·시간을 표시하고 같은 `schedule=id` 상세로 진입한다.
설정된 수업일 중 오늘 항목이 없으면 원래 날짜·전체 명단으로 대체하지 않는다.
같은 날 여러 반에서 하나를 선택하면 카드 설명에는 선택한 반과 시간만 표시한다.
클릭 가능한 요약 카드는 네이티브 버튼으로 제공해 Enter·Space로도 동일하게 진입한다.

모바일 출석은 모든 페이지 요청과 일괄 현장 출석에 동일 범위를 보낸다. 성적은
수업일 API의 배정 명단과 범위별 성적 캐시를 사용하고 빈 명단/실패를 시험 전체
결과로 대체하지 않는다. 모바일 성적 초안도 차시/수업일로 분리한다. 공용 자료
탭은 수업일 선택과 별개임을 표시한다.

### 접근성과 검증

기존 AdminModal의 포커스 가두기·Escape·포커스 복귀, 공용 DatePicker와
TimeRangeInput, 디자인 토큰과 버튼을 사용한다. 수업일 칩은 `aria-pressed`,
입력에는 이름, 피드백에는 status/alert를 둔다. 390px에서 필드는 한 열로 배치하고
수업일 칩은 가로로 넘기는 한 줄로 표시해 명단을 지나치게 아래로 밀지 않는다.
관리 창의 선택 시간은 `시간 설정 (선택)`을 펼쳐 입력하며 저장된 시간은 접힌
요약에도 표시한다. 명단은 창 내부에서 스크롤하고 짧은 상태 전환은 reduced-motion을 따른다.
학생·학부모의 데스크톱 일정 달력은 날짜 칸 높이와 전체 너비를 제한해 배정된
수업과 미배정 안내가 과도하게 아래로 밀리지 않도록 한다. 모바일 달력은 기존 배치를 유지한다.

`e2e/admin/session-schedules.mock.spec.ts`: 390/1366 생성·배정·저장·reload,
출결→성적 범위 유지, 선택 초기화, 미배정 일괄 출석, 입력 보존, 400/409 복구,
빈 설정으로 이전 차시 복사, 마지막 수업일 삭제 확인, 삭제된 URL 유지,
SPA 이탈 취소/초안 보존, 교사 목요일 Today→출석/성적, 조회 실패/잘못된 범위의
전체 fallback 방지. 명단 복귀 직후 수업일 변경은 정상 포인터 동선과 두 컨트롤의
이벤트를 같은 브라우저 실행 턴에서 호출하는 경계 검사를 함께 사용해, 이전 도구
URL의 복원과 명단/URL 불일치를 확인한다. 성적 잠금 해제 응답을 보류하는 회귀는
다른 탭 이동 후 대기 종료·새로고침까지 경로와 학생 명단을 유지하는지 확인한다.
`e2e/student/session-schedules.mock.spec.ts`: 학생/학부모 390/1366 달력의 실제 날짜와
미배정 진입, 자료 링크, reload, 기존 단일 날짜 호환. 두 spec은 routeMockSpecs에 등록한다.

`e2e/helpers/verifySessionSchedules.ts`는 기존 격리
`student-parent-assessment-realuse.spec.ts`의 한 step으로 실행한다. 테스트 수나
runner 게이트는 바꾸지 않는다. 생성된 합성 가족/차시만 사용하며 UI 날짜·배정
저장/reload→출결/성적 범위→학생 실제 날짜, 실제 API 동시 수정에 대한 409 초안
보존, 마지막 설정 삭제 확인과 원래 날짜 복귀, 출결 ID/상태·성적 행 보존을 검증한다.
실패 시에도 fresh version으로 빈 설정을 복구하고 기존 fixture가 차시/가족 cleanup을
소유한다. 운영 쓰기를 허용하지 않는다.

Mock 검증은 서버의 원자성/날짜 이동/실제 보존을 증명하지 않는다. 릴리스 담당자는
기존 Codespace에서 typecheck/lint/build/정책 게이트·route mock 실행 후 동일 artifact
격리 development에서 저장→reload→출결·성적·학생 달력, 신규 학생 UNSET, 기존 기록
유지, stale/권한/타 테넌트 거절과 cleanup zero를 검증한다. 실제 390/1366 화면과
키보드·시간 선택·긴 이름·명단 검색의 시각 판단은 별도 확인한다.
삭제 오류 회귀 `e2e/admin/session-delete-recovery.mock.spec.ts`는 1366/1100/390px에서
403의 실제 안내와 빈 detail의 기본 문구가 화면에 보이는지 확인한다. 거절 후
카드 재조회·재시도 성공·재조회 후 제거도 확인하며, route mock 결과를 실제 서버
저장 또는 운영 검증으로 기록하지 않는다. 연결 글 삭제와 테스트 학원 cleanup은
동일 후보의 공식 isolated 실사용에서 별도로 검증한다.
