# 학원 수납 화면

원장·관리자는 `/workspace/fees`에서 비목, 청구서, 수납을 관리한다. 학생·학부모의
조회와 수납·취소·청구의 서버 정책은 [backend fees](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/fees.md)가 소유한다.

관리 목록은 API 첫 페이지를 전체로 간주하지 않는다. 비목·학생 비용·청구·수납·강의
선택지는 요청을 시작한 계정 세션과 학원에 고정하여 모든 페이지를 읽는다. 서버의
next URL은 직접 방문하지 않고 동일 경로·필터의 다음 번호로 요청한다. 중간 실패,
건수 변경·중복·누락·잘못된 응답은 부분 결과나 빈 목록으로 성공 처리하지 않는다.
청구·비목 화면은 조회 실패와 실제 0건을 구분하고 다시 시도 동선을 제공한다.

`미납/부분납` 바로가기는 서버의 `status=UNPAID` 묶음을 조회한다. 미납·부분납·연체를
포함하고 완납·취소는 제외한다. 전체 버튼으로 필터를 해제할 수 있다. 기존 정렬 및
청구·납부 금액은 바꾸지 않는다.

월 청구 생성 창을 열면 **선택된 청구 월의 말일**을 기본 납부기한으로 표시한다.
날짜만 있는 값은 UTC 시각으로 변환하지 않아 한국 시간에서 하루 앞당겨지지 않는다.
윤년과 월 길이를 반영하고, 사용자가 수정한 기한은 해당 창의 제출 때 그대로 보낸다.
입력이 비어 있으면 생성할 수 없다. 생성 시 월납·일회성 비목의 처리 여부는 서버가 결정한다.

검증: `e2e/admin/fees-operations-contract.mock.spec.ts`는 한국 시간 월말·윤년·월 변경과
직접 입력한 기한, 501건 조회, 중간 실패→재시도, 미납 필터→전체 복구를 검사한다.
합성 API 검사는 실제 수납이나 메시지 발송을 하지 않는다. 운영 승격에는 필수 CI와
동일 빌드 격리 실사용, cleanup 0 및 운영 버전·영향 동선 확인을 별도로 적용한다.
