# 차시 수강생 배정·출결 일괄 작업 안전 계약

## 목적과 진입

성적표의 영상 출석 행에는 같은 차시·수강의 저장된 `영상 N%`, `영상 완료`, 또는 `영상 기록 없음`을 표시한다. 서버의 nullable 진행 상태를 사용하며 다른 차시나 과거 응시로 진행률을 추정하지 않는다. 영상 출석은 기존대로 평가 대상이다. 데스크톱·390px의 결석 제외/배정 회귀에서 진도 표시와 새로고침 후 명단 보존을 함께 확인한다.

이 문서는 관리자 앱의 **강의 → 차시 → 출결**에서 수강생을 일괄 배정하고
출결을 확정하는 현재 사용자 흐름을 설명한다. 학생을 빠르게 넣되, 등록과
현장 출석을 같은 동작으로 오인하거나 일괄 변경을 실수로 확정하지 않게 하는
것이 목적이다.

소유 구현:

- 수강생 선택·등록: `src/app_admin/domains/lectures/components/SessionEnrollModal.tsx`
- 출결 목록·전체 현장·되돌리기:
  `src/app_admin/domains/lectures/pages/attendance/SessionAttendancePage.tsx`
- 차시 전체 탭의 출결 집계:
  `src/app_admin/domains/sessions/components/SessionAttendanceSummary.tsx`
- API 계약: `src/shared/api/contracts/attendance.ts`
- 백엔드 상태·복구 불변조건:
  [`state-transitions.md`](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/state-transitions.md#b19-attendance)

## 결석자의 평가 TODO

교직원이 실제 `ABSENT`로 저장한 학생은 차시 명단과 과거 점수·제출 이력에 계속
보인다. 아직 수행하지 않은 시험·과제 칸은 `결석 제외`로 표시되고 현재 평가 검토,
성적표 선택, 미배정 경고 및 시험·과제 일괄 배정에서는 빠진다. `ONLINE`, `PRESENT`,
출결 미입력 학생은 정상 평가 대상이다. 결석 상태를 영상 또는 현장 상태로 바꾸면
다시 대상이 되며, 오류가 보이면 출결 탭의 상태를 확인하고 재시도한다. 변경 후
성적표를 새로고침해도 같은 대상 여부가 유지되어야 한다. 서버의 정확한 데이터·
클리닉 보존 규칙은 [백엔드 출결 계약](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/attendance.md#실제-결석과-평가-todo)이 소유한다.

테스트 오답 보기에서도 결석자 행과 기존 점수·제출 이력을 유지한다. 전체 필터는
아직 평가 이력이 없는 결석자까지 표시하며, 미완료·채점 대기·처리됨 필터는 출결과
무관하게 저장된 시험 오답 상태로 판별한다. 각 필터 인원은 검색 후 표시 행과
일치한다. 일반 판정과 테스트 오답 보기 모두 기존 개별 점수 수정·저장·새로고침이
가능하다. `현재 결과 선택`은 보이는 행 중 현재 평가 대상만 선택하므로 결석자는
선택하지 않는다. 기존 미수행 평가 배정 및 오답 확인 저장 제한은 유지한다.

교사 모바일 성적 입력도 기존 점수 수정은 유지한다. 현재 결석자의 오답 상태 변경에는
결석 제외 이유와 **출결 확인** 링크를 표시한다. 해당 차시 출결에서 온라인 또는 출석으로
복구하면 성적 캐시를 갱신해 뒤로 돌아왔을 때 오답 상태를 저장할 수 있다. 상태 저장 뒤
새로고침에서도 점수와 처리 상태가 유지된다. 교직원 권한과 테넌트 경계는 기존 API를 따른다.
교사 출결 상태 선택창은 데스크톱 고정 메뉴 위에 표시되어 모든 상태 버튼을 누를 수 있다.

`e2e/admin/score-entry-autosave.spec.ts`는 1366px·390px에서 결석자의 명단·빈 칸,
영상 수강자의 미배정 복구, 재로드 및 배정 API 대상 ID를 검증한다.
`e2e/teacher/mobile-score-correction-status.spec.ts`는 같은 두 폭에서 결석자의 기존 점수
수정·재조회, 출결 링크 → 온라인 변경 → 오답 상태 저장·재조회를 검증한다.

## 선생님 출석 체크 전체 명단

선생님 앱의 차시 **출석 체크**(`/workspace/mobile/attendance/:sessionId`)는 이름순으로
500행씩 모든 페이지를 읽고, 서버 전체 인원과 중복 없는 수집 인원이 일치한 뒤
카드와 집계를 표시한다. 200명을 넘는 차시에서도 마지막 학생을 선택하거나
스와이프해 출결을 저장할 수 있다. 기존 페이지형 출결 API를 쓰는 다른 화면의
페이지 이동은 유지한다.
연결된 차시 학생·출석 탭도 같은 전체 명단을 사용하므로 뒤쪽 학생의 저장된 상태가
첫 페이지 밖에 있다는 이유로 **미체크**로 표시되지 않는다.

조회 전체는 시작한 로그인 세션과 학원에 고정된다. 중간 요청 실패, 응답 형식 오류,
중복 행, 전체 인원 변경 또는 누락이면 부분 명단을 표시하지 않는다. 화면에
**출석 명단을 불러오지 못했습니다**와 **다시 시도**를 표시하고, 재시도는 첫
페이지부터 다시 읽는다. 명단을 읽는 동안과 실패한 상태에서는 **전체출석**을
실행할 수 없으며, 정상 조회 후 기존 서버 권한과 일괄 출결 범위에 따라 실행한다.
잘못된 차시 주소는 요청하지 않고 차시로 돌아갈 수 있게 한다.

단건 저장과 전체출석 성공 시 전체 명단·차시 출결·성적 캐시를 갱신한다.
`e2e/teacher/attendance-roster-pages.mock.spec.ts`는 501명 명단의 마지막 학생 저장,
재로드, 차시 학생 탭의 상태 반영, 전체출석과 재로드를 1366px·390px에서 확인한다. 중간 HTTP 실패·중복·누락·
인원 변경·잘못된 응답 이후 재시도와 정상 저장도 검증한다. 실제 권한·데이터 격리와
다른 역할의 출결 반영은 같은 아티팩트의 격리 개발 실사용 검증을 따른다.
`student-parent-learning-realuse.spec.ts`는 두 화면 폭에서 교직원이 이 화면으로
출결을 저장하고 API·새로고침에서 확인한 뒤 학생과 학부모의 출결 반영을 확인한다.

## 수강생 일괄배정

1. 관리자는 전체 학생, 직전 차시 또는 강의 활성 수강생에서 대상을 고른다.
2. 모든 불러오기는 서버 저장이 아니라 오른쪽 **선택 목록**만 바꾼다.
3. 선택·해제·전체 선택은 최근 20단계까지 `Ctrl+Z`와
   `Ctrl+Shift+Z` 또는 화면 버튼으로 되돌리고 다시 실행할 수 있다.
4. 일반 `Enter`는 등록을 실행하지 않는다. `Ctrl+Enter` 또는 하단
   **N명 검토 후 등록**은 최종 확인창을 연다.
5. 확인창은 대상 인원, 선택 학생, 시작 상태 `미입력`을 다시
   보여 준 뒤에만 `bulk_create`를 호출한다.
6. 선택 또는 읽어 둔 Excel이 남은 상태에서 닫으면 미저장 닫기 확인을 한다.

새 출결은 `UNSET`(미입력)으로 시작한다. 자동으로 `PRESENT`가 되지 않으며,
등원 또는 참여 방식 확인 후 현장·영상·결석 등을 기록한다. 이미 차시에 있는
학생은 목록과 등록 대상에서 제외한다. 차시만 퇴원한 학생은 강의 수강등록이
`ACTIVE`이면 다시 선택해 명시적으로 등록할 수 있다. 보관된 퇴원 출결은 중복
등록 제외 목록에서 빼며, 등록 성공 시 같은 출결 행을 `UNSET`으로 복구한다.
메모·진도·다른 차시 이력은 유지하고 자동 현장 처리는 하지 않는다. 전체 학생
목록은 현재 강의의 `INACTIVE/PENDING`
수강 이력이 있는 학생을 제외하고 이유를 표시한다. 선택 뒤 다른 화면에서 수강
상태가 바뀔 수 있으므로 최종 확인 직전에 강의 수강 상태를 전 페이지 다시 읽어
비활성·대기 학생을 선택 목록에서 제거한다. 상태를 읽지 못하면 일부를 추측해
저장하지 않는다.

직전 차시 불러오기는 과거 명단 행의 현재 `enrollment_status`가 `ACTIVE`인 학생만
사용한다. 강의 수강생 가져오기는 500명 단위 응답의 `count`까지 다음 페이지를
계속 읽으므로 500명 초과 강의도 첫 페이지만 등록하는 일이 없어야 한다. 서버의
원자적 활성 수강 가드는 이 사전 필터와 별도로 최종 경쟁 상태를 계속 차단한다.

중복 등록 제외 목록도 500행 단위로 끝까지 읽는다. 퇴원 행을 제외하기 전의
원본 행 수와 서버 `count`가 일치해야 하며, 빈 중간 페이지·수집 한도 초과 등으로
목록을 완성하지 못하면 오류를 표시한다. 사용자는 **다시 시도**로 명단을 다시
읽고 선택·검토·등록을 진행할 수 있다. 일부 명단을 정상 조회로 간주하지 않는다.

## 퇴원 범위 선택

출결 탭에서 **퇴원**을 누르면 범위 선택창이 열린다. 성적 표의 출결은 읽기
전용 배지이므로 성적 탭에서 시작한 경우 출결 탭으로 이동해 처리한다.
`SessionScoresPanel`의 공통 퇴원 처리 함수는 남아 있지만 현재 표의 배지에
연결되어 있지 않으며, 성적 표에서 직접 퇴원할 수 있다는 계약은 없다.
매번 **1. 이 차시만 퇴원**이 기본값이며 **2. 강의 전체 퇴원**으로 바꿀 수 있다.
선택만으로 저장하지 않고 하단의 선택 범위가 적힌 버튼을 눌러야 실행한다.
취소·Escape·닫기는 API를 호출하지 않는다. 한 차시만 퇴원한 행에서도 다시
선택창을 열어 강의 전체 퇴원을 선택할 수 있다.

`useSecessionConfirm`과 `updateAttendance`가 공통 UI/API 계약을 소유한다.
확정 시 `confirm_secession: true`, `secession_scope: session|lecture`를 명시한다.
서버를 먼저 배포해야 하며 구 서버에 새 범위 선택을 보내지 않는다.
실패 시 기존 출결 상태를 유지하고 오류를 표시하며 다시 선택해 재시도할 수 있다.
성공 후 출결·성적·매트릭스·차시 등록·중복 등록 제외 목록 캐시를 갱신한다.
중복 등록 제외 키는 `shared/api/queryKeys/attendance.ts`의 `enrolledIds`가 소유하며,
강의의 `attendanceEnrolledIds` 별칭과 성적의 무효화는 같은 키를 사용한다.
등록 창을 이미 열었다가 닫았어도 차시 퇴원 직후 다시 등록할 학생을 표시한다.
재등록 후 출결을 입력하고 새로고침하면 출결 및 성적 탭에 같은 상태가 반영된다.
구체적인 데이터 회수·보존 규칙은
[백엔드 출결 계약](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/attendance.md)이 소유한다.

선택창은 기존 모달·버튼을 사용하며 라디오 버튼은 키보드로 선택할 수 있다.
1366px·390px에서 선택지와 확정 버튼을 모두 표시하고 가로 넘침이 없어야 한다.
390px 수강생 등록 창은 본문 전체를 세로로 스크롤하며 학생 목록에 최소 높이를
보장한다. 선택 목록은 그 아래에 놓이고 검토·등록 버튼은 고정된 하단에 유지한다.
모바일 목록 하단의 인원과 페이지 이동은 두 줄로 배치해 겹치지 않으며, 처음·이전·
다음·마지막 버튼은 모두 40px 이상의 터치 영역을 유지한다. 이 모달의 기존
`AdminModal.className`으로 스타일을 한정해 `:has()` 지원 없이도 스크롤한다.
`e2e/admin/session-attendance-bulk-safety.mock.spec.ts`는 기본값·취소 무쓰기·두 범위의
정확한 PATCH 값·새로고침·모바일 너비를 검증한다. 실제 데이터·영상 회수 검증은
격리 개발 환경에서 별도로 수행한다.
같은 회귀 파일은 차시 퇴원 후 재등록 선택·확정·미입력·현장 저장·새로고침과
중복 제외, 501행 조회 및 불완전한 명단의 오류 후 재시도를 검증한다.

## 전체 현장 출석과 되돌리기

**전체 현장 출석**은 확인창에서 변경 범위와 예외를 설명한 뒤 실행한다.
서버는 `PRESENT`, `SECESSION`, 비활성 수강등록을 제외한 실제 변경 행만
잠그고 `PRESENT`로 바꾼다. 성공하면 프론트는 화면 상단에 **최근 일괄 출결
작업**을 표시하고 10분 동안 되돌리기 버튼을 제공한다.

서명 토큰과 만료 시각은 해당 탭의 `sessionStorage`에 학원·로그인 사용자·차시별로
분리해 보관한다. 같은 화면을 새로고침해도 남은 유효 시간 안에는 되돌릴 수 있다.
다른 학원·사용자·차시의 기록은 표시하지 않으며, 만료·복원 성공·기록 닫기에는
해당 기록만 제거한다. 저장소를 사용할 수 없으면 현재 화면에서만 되돌리기를 제공한다.

선택 출결 삭제는 모든 요청의 성공·실패를 확인한 뒤 명단·수강등록·성적·PDF 조회를
갱신한다. 일부만 성공하면 성공 인원과 실패 인원을 표시하고 실패한 행만 선택 상태로
남겨 재시도할 수 있다. 성공 행이 화면에 남아 재삭제되는 상태를 만들지 않는다.
`session-attendance-bulk-safety.mock.spec.ts`가 새로고침 후 되돌리기와 일부 실패 후
재조회·재시도·새로고침을 검증한다.

되돌리기는 클라이언트가 상태를 추측해 여러 PATCH를 보내지 않는다. 서버가
발급한 서명 토큰을 `bulk_undo_present`에 보내며, 서버가 같은 테넌트·차시의
대상 전체를 잠가 현재 상태가 모두 `PRESENT`인지 확인한 뒤 각 직전 상태를
한 트랜잭션으로 복원한다. 한 행이라도 삭제·퇴원되었거나 현재 상태가
`PRESENT`가 아니거나 토큰이
만료·변조되었으면 일부만 복원하지 않고 전체를 거부한다.

## 명단 정렬

모든 테넌트의 출석 탭은 처음 여는 계정의 명단을 이름 가나다순으로 표시한다.
교직원이 이름, 학부모 전화번호, 학생 전화번호 머리글이나 **미도착 우선**으로 정렬을 바꾸면
같은 계정과 브라우저의 다른 차시 출석 화면에서도 마지막 정렬을 유지한다. 저장
키는 테넌트·계정 ID별로 분리해 공용 PC에서 다른 계정의 선택이 섞이지 않으며,
브라우저 저장소를 사용할 수 없거나 저장값이 유효하지 않으면 이름 가나다순으로
복구한다.

검색 옆 **가나다순** 버튼으로 다른 정렬에서 이름순으로 바로 돌아갈 수 있다.
이름 뒤 A·B는 이름의 일부로 보존하며 `김가온 → 김가온A → 김가온B → 나누리A`
처럼 학생 명부와 같은 서버 기준으로 정렬한다. 이름을 바꾸거나 접미사를 제거하지
않으며 같은 이름은 출결 ID로 순서를 고정한다. 상태·전화번호 정렬의 동률도 이
이름순을 따른다.

정렬 설정은 화면 표시만 바꾸며 출결 데이터나 서버 상태를 수정하지 않는다.
**미도착 우선**은 미입력·결석 학생을 먼저 표시하고 각 그룹 안에서는 이름순을
유지한다. 출결 저장 성공 후 현재 상태로 순서가 갱신되며, 저장 실패 시 기존 상태와
행을 유지하고 오류 안내 후 재시도할 수 있다. 끄면 이름 가나다순으로 돌아간다.
다른 머리글 정렬을 고르면 미도착 우선은 해제된다. 기본 이름순에서는 출결을
바꿔도 행이 움직이지 않는다. 이전 브라우저에 저장된 상태순 정렬은 이름 가나다순으로
복구하고, 상태별 확인은 기존 상태 필터를 사용한다. 데스크톱과 390px 모두 검색
옆 필터 영역의 버튼으로 선택하며, 선택 상태를 `aria-pressed`로 전달한다.
브라우저는 현재 선택을 `ordering`으로 보내고 서버는 테넌트·검색·상태 필터의
전체 결과를 먼저 정렬한 뒤 50명 단위로 페이지를 나눈다. 따라서 51명 이상인
차시에서도 페이지 사이 이름순이 끊기지 않으며 브라우저가 받은 페이지를 다시
복사·정렬하지 않는다. 각 정렬 머리글은 오름차순, 내림차순, 이름 가나다순으로
순환한다. 서버 계약은 백엔드
[`docs/domain/attendance.md`](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/attendance.md)가 소유한다.

정렬 변경은 첫 페이지 이동과 함께 적용해 이전 페이지를 새 정렬로 중복 조회하지
않는다. 첫 조회·정렬 변경·저장 뒤 재조회가 실패하면 이전 명단을 최신 결과처럼
표시하지 않고 오류와 **다시 시도**를 보여 준다. 재시도는 같은 검색·필터·정렬을
유지해 조회만 다시 실행하며 이미 저장된 출결을 중복 저장하지 않는다.

`session-attendance-bulk-safety.mock.spec.ts`는 1366px·390px에서 키보드 선택,
정렬·출결의 새로고침 복원, 저장 실패 후 재시도, 기본 정렬 복귀 및 가로 넘침을
확인한다. 정렬·저장 후 조회 실패의 복구와 페이지 전환 시 중복 조회 방지도 포함한다.
전체 페이지·동명이인·검색·상태·테넌트 경계는 백엔드 정렬 회귀가 검증한다.
`student-parent-learning-realuse.spec.ts`는 격리 개발 환경의 합성 학생을 실제로
등록하고 A 접미사 이름의 순서, 역순에서 복귀, 새로고침 유지와 1366px·390px
화면을 같은 배포 산출물로 확인한 뒤 학생·학부모의 학습 조회까지 검증한다.

## API와 실패 처리

| 요청 | 성공 응답 | 실패 처리 |
|------|-----------|-----------|
| `GET /lectures/attendance/?ordering=...` | 테넌트 전체 결과를 정렬한 페이지 | 잘못된 정렬값은 기본 이름순으로 복구 |
| `GET /enrollments/session-enrollments/?session=...` | 과거 명단과 현재 `enrollment_status` | 현재 쓰기는 `ACTIVE`만 사용하고 알 수 없는 상태는 제외 |
| `POST /lectures/attendance/bulk_create/` | 새 출결 목록 (`UNSET`) | 선택 목록을 유지하고 서버 오류를 표시 |
| `POST /lectures/attendance/bulk_set_present/` | 변경 수, 서명 토큰, 유효시간 | 목록을 다시 읽을 수 있게 두고 오류 표시 |
| `POST /lectures/attendance/bulk_undo_present/` | 복원 수, 차시 ID | 400은 잘못된 토큰, 409는 만료 또는 현재 상태 충돌로 안내 |

모든 요청은 인증된 교직원과 현재 테넌트 경계 안에서만 동작한다. 다른
테넌트의 세션·토큰은 존재 여부를 드러내지 않고 거부한다. 일괄 등록 성공
후에는 차시 수강생, 출결 목록, 출결 매트릭스, 강의 수강생 캐시를 갱신한다.
전체 현장과 되돌리기 뒤에는 출결 목록·매트릭스·성적 집계 캐시를 갱신한다.

## UI와 접근성

- 차시 헤더의 **출결 원장**은 출결·성적·시험·과제·공지·영상 탭을 이동해도
  유지되며, 해당 차시 전체 명단을 페이지 끝까지 읽은 `총원·상태별 인원`만
  표시한다. 일부 페이지만 읽힌 경우에는 숫자를 추정하지 않고 다시 불러오기
  상태로 닫힌다. 출결 변경·수강생 추가 뒤에는 목록과 같은 캐시 무효화 경계를
  사용해 자동으로 다시 집계한다.
- 데스크톱 빠른 선택 레일, 모바일 압축 선택기의 옵션, 상태 필터는 공용
  `SelectionButton`을 사용한다. `미입력`을 포함한 11개 상태를 일반 텍스트로
  표시하고 선택된 버튼의 바깥 윤곽을 강조한다. 읽기 전용
  `AttendanceStatusBadge`는 상태 표시 역할을 유지한다. 표면·대비·포커스와
  라벨/그룹 배치의 기준은 [테마와 공용 컨트롤 계약](README.md#테마와-공용-컨트롤-계약)을
  따른다. 모바일은 한 행에 11개를 억지로 줄이지 않고 압축 선택기를 유지한다.
  학생 이름과 강의 딱지는 기존 공용 compact 배치로 한 줄에 유지하며,
  긴 이름은 말줄임하고 학생 상세 진입을 유지한다.
- 공용 컨트롤 적용은 표시와 조작 표현을 통일하며 기존 상태 변경 핸들러,
  API 요청·권한·테넌트 경계, 성공 후 캐시 갱신과 실패 안내·재시도 흐름을
  유지한다. 상태 필터는 조회 범위만 바꾸며 출결을 저장하지 않는다. 선택
  모양만 바뀐 것으로 저장 성공을 간주하지 않고 서버 결과와 재조회로 확인한다.
- 오른쪽 검토 레일은 시작 상태 `미입력`, 선택 인원, 실행취소/다시실행을
  한 묶음으로 보여 준다.
- 최근 일괄 작업은 단순 토스트가 아니라 닫을 수 있는 인라인 기록으로 남긴다.
- 버튼은 로딩 중 중복 실행을 막고, 아이콘 버튼에는 접근 가능한 이름과
  툴팁을 제공한다.
- 최소 검수 폭은 1366px, 1100px, 390px다. 좁은 화면에서도 확인 문구,
  선택 목록, 등록·취소, 되돌리기가 잘리면 안 된다.

## 강사 개별 출결 저장과 되돌리기

출석 카드는 탭·Enter·Space로 같은 상태 선택창을 연다. 상태 선택은 공용
`BottomSheet`를 사용하며 모바일의 아래쪽 배치와 기존 상태 선택·저장 API를 유지한다.
PC에서는 공통 대화상자 폭을 사용하고, 닫기·Escape는 저장 없이 카드로 초점을
돌려준다. Tab은 창 안에서 순환하고 선택 상태는 `aria-pressed`로 전달한다.
선택지 글자는 공용 본문 색으로 읽기 대비를 유지하고, 기존 상태 색은 선택된
버튼의 테두리·배경에 사용한다. 색상만으로 현재 선택을 전달하지 않는다.
중복 배경·스크롤 잠금·애니메이션은 공용 구현으로 대체하며 데이터 이전은 없다.
아래 회귀 검사의 느린 저장 사례가 390/1366px 키보드 진입·닫기와 저장 복구를 검증한다.

강사 출석 체크의 성공 안내와 3초 되돌리기 기회는 서버 저장 및 관련 목록
재조회가 끝난 뒤 시작한다. 저장 중에는 진행 안내를 표시하고 개별 변경·전체
출석·되돌리기의 중복 쓰기를 막는다. 실패한 저장은 성공으로 표시하지 않으며
원래 상태에서 다시 선택할 수 있다. 같은 상태를 다시 누르면 쓰지 않는다.

되돌리기는 직전 성공한 변경의 이전 상태를 같은 출결 API로 복원한다.
퇴원 상태 복원에는 기존 `confirm_secession` 확인을 함께 보낸다. 복원이
실패하면 오류와 되돌리기 버튼을 유지하며 재시도 또는 닫기를 제공한다.
재시도 성공이나 새로운 개별·전체 출석 저장 성공 시 이전 복원 안내를 정리한다.
새 안내가 이전 타이머 때문에 사라지지 않도록 타이머를 교체하고 화면 종료 시
해제한다. API 권한·테넌트 범위와 저장된 기존 출결 데이터의 의미는 유지한다.

`e2e/teacher/attendance-save-undo.mock.spec.ts`는 390·1366px의 느린 저장,
저장 거절 후 재시도, 복원 거절 후 재시도, 퇴원 복원 확인과 새로고침 유지,
저장 중 중복 입력, 전체출석 후 재조회 중 입력 차단과 이전 복원 안내 제거,
가로 넘침을 검증한다. 실패 안내는 밝은 버튼·포커스와
44px 터치 영역을 유지하며 등장 모션은 reduced-motion 설정을 따른다.
격리 개발의 `student-parent-learning-realuse.spec.ts`는 두 화면 폭에서
실제 저장 → 되돌리기 → 서버 재조회 → 새로고침 → 연결 차시·학생·학부모의
출결 확인을 같은 일회용 가족 시나리오에 포함하고 기존 cleanup-zero를 따른다.

## 검증

격리 개발의 `student-parent-assessment-realuse.spec.ts`는 실제 출결 API로 준비한
일회용 학생 2명으로 1366/390px의 미도착 우선 선택·순서·새로고침 복원·해제를
확인한다. 같은 차시의 테스트 오답에서 결석자의 기존 이력 표시, 전체 인원과 행 수,
평가 대상만 선택되는 동작과 새로고침을 확인하고 기존 tenant/user cleanup-zero를
유지한다. API 응답을 mock하지 않으며 아래 route-mock의 실패/복구 검증과 함께 사용한다.

```powershell
pnpm typecheck
pnpm exec eslint src/app_admin/domains/lectures/components/SessionEnrollModal.tsx `
  src/app_admin/domains/lectures/pages/attendance/SessionAttendancePage.tsx
pnpm exec playwright test e2e/admin/session-attendance-bulk-safety.mock.spec.ts --reporter=list
pnpm build
```

핵심 회귀는 탭 간 헤더 집계 유지와 변경 직후 재집계, 빠른 선택의 단일 표면과
선택 윤곽, 읽을 수 있는 미선택 라벨, 모바일 선택·필터 조작,
기본 이름 가나다순, 계정별 정렬 저장·새로고침 복원, 선택 불러오기
무기록, 선택 undo/redo, 일반 Enter 무반응,
현재 강의 비활성 학생 사전 제외와 최종 재검증, 500명 초과 강의 전 페이지 조회,
최종 확인 전 무기록, 신규 행 `미입력`, 전체 현장 성공 기록, 정확 복원,
충돌 시 전체 거부, 1366/1100/390px overflow와 콘솔 오류 0건이다.
공용 컨트롤의 세 화면 스타일·사용자 강조색 상태·대비 검증은 위에 연결한 공용 계약을 따른다.
개별 출결 변경도 선택 → 저장 결과 → 새로고침 후 유지와 집계 반영, 저장 실패
안내 후 재시도를 검수한다. 이 절의 명령과 항목은 필요한 검증 범위이며,
실행하지 않은 검사를 통과한 것으로 기록하지 않는다.
