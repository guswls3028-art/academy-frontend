# 홈페이지 영상과 게시자 스튜디오

백엔드 정책 정본: [공개 YouTube 영상](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/public-video-showcase.md).
화면: `src/landing/pages/PublicVideosPage.tsx`, `VideoStudioPage.tsx`, `VideoEditorPage.tsx`.
기존 godmin의 녹색·민트·크림과 Pretendard를 유지하며 홈페이지 대표 영상, 영상 목록,
개별 공유 페이지, 지정 게시자 스튜디오를 제공한다. godmin의 홈·영상 목록·상세·관리·편집은
`GodminSiteChrome`의 같은 로고/메뉴/푸터를 사용한다. 390px에서도 주요 메뉴를 숨기지 않고
헤더 두 번째 행에 유지하며, 영상 영역은 현재 메뉴로 표시한다. 임의의 별도 `VIDEOS` 브랜드를 붙이지 않는다.
영상에서 홈페이지의 수업 철학·학습 관리·강사 메뉴를 누르면 클라이언트 경로로 이동한 뒤
홈페이지가 렌더링된 시점에 해당 섹션으로 스크롤한다. 모바일 고정 헤더 아래 여백도 유지한다.

## 이용 경로

- godmin 홈페이지 `/landing`: 대표 영상이 있으면 첫 화면의 미디어 카드로 보여준다.
  등록한 대표가 없으면 기존 신민T 프로필을 유지한다. 영상 열기를 누르면 공식 플레이어
  하나가 dialog 안에 나타난다. Escape/닫기/배경 클릭 시 iframe을 제거하고 포커스가 돌아간다.
  플레이어 창은 확대 변환 없이 열고 배경의 페이드 효과는 유지한다. 모바일 WebKit에서도
  열리는 중 닫기 버튼의 위치가 바뀌지 않으며 닫기 터치 영역은 44px이다.
  아래 영상 섹션에는 원본 업로드일(미확인 시 홈페이지 공개일)이 최근인 공개 영상 최대 네 편을 표시하고 전체 목록으로 연결한다.
- `/landing/videos`: 사용자가 정한 영역 제목·소개 아래 `동영상`(기본)/`Shorts` 탭,
  `최신순`/`인기순`/`오래된순` 버튼과 제목·자유 분류·채널 검색을 제공한다.
  YouTube 채널의 실제 동영상/Shorts 탭과 정렬 구조를 참고했다. 종전 페이지 내부 형식별
  묶음/바로가기를 전체 공개 영상에 적용하는 서버 필터로 대체했다. 홈페이지의 혼합 영상 소개는 유지한다.
  동영상은 16:9, Shorts는 9:16이며 390px에서 각각 한 열/두 열이다.
  `format`, `sort`, `q`, `page`를 URL에 유지해 새로고침·뒤로가기·상세 왕복에 복원한다.
  API는 DRF의 예약된 format 쿼리와 충돌하지 않도록 `kind`를 쓴다. 조건 변경 시 첫 페이지로 이동한다.
  수량은 필터/검색에 해당하는 전체 편수이며 서버 정렬 후 12편씩 페이지를 나눈다.
  최신/오래된순은 YouTube 원본 업로드일, 미확인 시 홈페이지 공개일을 사용하고 카드에 구분해 표시한다.
  인기순은 실제 YouTube 조회수 내림차순이며 미확인 영상은 마지막이다. 미확인을 0회로 바꾸지 않는다.
  조회수가 모두 미확인이면 명시적인 오류·재시도·최신순 복귀를 제공한다. 빈 검색은 정상 빈 결과다.
  제목/분류/소개/채널·조회수·날짜를 보여주며 데이터 갱신 정책은 백엔드 정본을 따른다.
- `/landing/videos/:id`: 직접 링크와 새로고침이 가능한 상세. 공식 플레이어, 원본 채널,
  YouTube에서 보기·좋아요, 링크 복사. 미공개/다른 tenant 영상은 열 수 없다.
  영상 제목을 플레이어 위에 두며 Shorts 높이는 화면 높이에 비례해 최대 약 569px로 제한한다.
  데스크톱은 플레이어 옆에 현재 시청 중인 제목과 다른 영상 목록을 고정하고, 긴 목록은 그 안에서 스크롤한다.
  모바일은 고정을 풀어 플레이어 아래에 목록과 `다른 영상` 바로가기를 둔다.
  다른 영상을 고르면 URL과 플레이어 하나만 교체하고 위로 이동한다. 같은 형식/정렬/검색 도구와
  페이지 상태를 상세/목록 왕복에 유지하며 필터나 목록 페이지를 바꿔도 재생 중인 iframe은 교체하지 않는다. 다른 영상 로딩/오류는 현재 재생과
  분리되어 재시도할 수 있다. 원본 조회수·업로드일과 최근 확인 시각을 표시한다. 자동 다음 재생이나 임의 추천·조회수는 만들지 않는다.
- `/landing/admin/videos`: 지정 게시자의 임시저장/공개/비공개 목록과 대표 여부.
  `공개 영상 보기`와 `새 영상 등록`을 상단에 함께 제공하고 등록 수·영상별 수정 진입을 표시한다.
  모바일에도 편집 안내를 남기며 한 페이지뿐이면 무의미한 이전·다음 버튼을 만들지 않는다.
  서버 can_publish가 true인 계정에 공통 헤더 `영상 관리`, 공개 화면 `영상 등록`,
  상세 `이 영상 수정`을 노출한다. 로그인 완료 상태를 로그인 링크로 잘못 표시하지 않는다.
  홈페이지 영상 영역에도 `영상 등록`을 제공하며 기존 홈페이지 편집 화면의 `영상 관리` 진입은 유지한다. 다른 계정에는 게시 도구를 노출하지 않는다.
  `영상 영역 설정`에서 영역 제목(60자)·소개(선택, 220자)를 직접 저장한다. 홈페이지 영상 영역과
  영상 목록에 함께 적용되며 기본은 `영상`과 빈 소개다. 충돌하면 입력을 유지하고 최신 설정을
  확인한 뒤 불러오기/내 입력 유지 중 선택한다. 저장 실패는 입력 보존·재시도, 이탈은 확인한다.
  목록 불러오기 실패의 재시도와 페이지 이동도 작성 중인 영역 설정을 유지한다.
- `/landing/admin/videos/new`, `/:id`: YouTube 링크 확인 → 제목·소개·분류·형태 편집 →
  미리보기·직접 공개 또는 임시저장 후 공개. 먼저 임시저장해야만 공개할 수 있는 단계는 없다. 대표 체크는 공개할 때 적용된다. 수정한 공개 영상도
  명시적으로 다시 공개하기 전까지 방문자에게 기존 스냅샷이 보인다.
  분류는 선택 입력(40자)이며 `category_label`에 저장한다. 기존 category 코드는 API 호환용으로
  보존하고 표시하지 않는다. 사용자 입력은 텍스트로 출력하며 고정 `인터뷰/과학 이야기/신민T의 일상`
  분류나 `수업 너머의 신민T/생각을 나누는 시간` 같은 임의 문구를 기본으로 부여하지 않는다.
  `영상 삭제`는 저장된 제목과 홈페이지/관리 목록·대표 해제 영향을 확인한 후 실행한다.
  성공하면 관리 목록으로 돌아가 완료를 알리며 같은 링크로 다시 등록할 수 있다.
  삭제 실패는 편집 내용을 유지하고 재시도한다. 다른 게시자의 수정·대표/설정 변경과 충돌하면
  최신 상태 확인 후 다시 결정한다. 원본 YouTube는 삭제하지 않는다. DB 보존/감사 정책은 백엔드 소유다.

## 권한·데이터·복구

godmin의 신민/박철은 기존 자료게시판의 정확한 두 지정 계정을 공유한다. UI는 이름으로
권한을 판단하지 않으며 백엔드가 활성 계정·tenant 역할·지정 슬롯을 검사한다.
인증 초기 로딩이 끝나기 전에는 거절 화면을 표시하지 않는다. 권한 조회는 tenant·계정별
키로 공유하므로 헤더와 본문에서 중복 요청하지 않으며, 계정/tenant 변경 시 이전 허용 상태를 재사용하지 않는다.
인증 조회 장애와 권한 조회 장애는 구분해 해당 확인을 재시도한다. 권한 확인 실패는 재시도, 미인증/권한 없음은 로그인/공개 영상으로 돌아가기를 제공한다.
공개 GET에는 인증을 붙이지 않고 관리 API에는 기존 axios tenant/auth 경계를 사용한다.
공개 홈·영상 목록·시청 중 로그인 세션이 만료되면 토큰과 계정 상태를 폐기하고
같은 화면을 방문자 상태로 유지한다. 검색·정렬 URL과 플레이어는 유지하고 관리 버튼은
제거한다. `/landing/admin/videos`와 편집 화면은 계속 로그인으로 이동하며 복귀 경로를
보존한다. 데스크톱·390px에서 만료 세션의 공개 진입/reload와 보호된 편집 진입을 검증한다.

등록 request_id를 재사용해 응답 유실을 복구한다. 중복 URL은 기존 영상 편집으로 연결한다.
409는 입력을 유지하고 최신 제목·소개·분류·형태·상태·대표 여부를 확인하게 한다.
게시자가 최신 내용을 불러오거나 자기 입력으로 이어서 수정하기를 선택한 뒤 재저장한다.
일시적 실패는 입력을 남기며 저장 완료/공개 완료/비공개 완료를 구별해서 표시한다. 새 영상의 저장/직접 공개로 편집 URL이 바뀌어도 완료 안내와 공개 화면 확인 링크가 유지된다.
원본 메타데이터 조회가 실패해도 제목을 직접 입력해 초안을 저장할 수 있다.
공개 시 원본 확인이 실패하면 기존 공개/대표가 보존된다. 비공개 시 초안은 남고 대표이면
기존 프로필로 돌아간다. 저장되지 않은 입력은 페이지 종료/링크 이동 시 확인한다.
공개 POST는 원본 확인과 최초 조회수 갱신의 제한 시간을 포함하도록 45초까지 완료를
기다리며 기존 진행 표시·중복 제출 방지를 유지한다. 다른 요청의 시간 제한은 유지한다.
조회수 공급자 장애만으로 완료된 공개를 취소하지 않으며 정기 갱신으로 다시 확인한다.

조회수는 YouTube의 유효 재생 판정에 따라 원본 영상·채널에 귀속된다. 자동 재생,
스크립트 playVideo, 자체 좋아요·조회수는 구현하지 않는다. iframe autoplay=0,
playsinline=1, origin, strict-origin-when-cross-origin과 기본 컨트롤을 유지한다.
좋아요/댓글은 원본 YouTube에서 로그인 후 직접 한다. 임베드 제한/제공자 장애 시 원본
링크가 항상 보인다. Shorts도 최소 200×200 이상의 실제 플레이어 하나로 연다.

## 공유·접근성·검증

Cloudflare Functions는 tenant API로 확인한 tenantCode로만 공개 상세 메타데이터를 읽는다.
YouTube 썸네일, 제목과 소개를 OG로 제공하며 no-store, 미공개 404/noindex를 적용한다.
소개가 비어 있으면 공유 설명도 브랜드명과 `영상`만 사용한다.
React 상세에도 메타데이터를 반영하고 이탈 시 복구한다. SSR API 실패는 noindex와
클라이언트 재시도로 복구한다. 캐시에서 이전 비공개 영상 정보를 되살리지 않는다.

desktop/390px에서 목록·폼·재생 dialog·단일 iframe·키보드·넘침을 검증한다.
재생창은 기존 Ant Design Modal을 사용해 native HTMLDialogElement.showModal을
지원하지 않는 브라우저에서도 열리고 닫히며 트리거 포커스를 복구한다.
Safari의 클릭 포커스 차이를 보완하고, aspect-ratio/dvh 미지원 환경에는 영상 비율과 재생창 높이의 CSS 대체 규칙을 적용한다.
hover 이동/확대는 짧게 적용하고 prefers-reduced-motion에서는 제거한다.
PR route mock과 iPhone WebKit, 격리 개발 동일 산출물 실사용은 등록→새로고침→
공개→다른 지정 게시자 수정→초안 보존→재공개→비공개→익명 확인을 포함한다.
영역 제목·소개와 자유 분류의 저장/reload/익명 반영, 삭제 취소·충돌·실패 복구,
삭제 후 관리/공개 상세 404·대표 해제와 같은 링크 재등록도 확인한다. 실사용 검증은
기존 1개 영상 시나리오 안에서 두 게시자·1366px/390px 모두 실행한다.
백엔드 0014와 조회수 API 연결·전체 배포 확인 후 프론트엔드를 승격한다. 기존 초기 4개 영상은
유지하고 초기 자동 소개와 정확히 같은 부분만 중립화하며 사용자 수정은 보존한다.
등록 직후에는 주소 변경뿐 아니라 저장된 편집 데이터의 GET과 제목 표시까지 확인한 뒤
새로고침한다. 화면 이동 중인 문서를 먼저 폐기하여 Safari 권한 확인 요청과 경합하지 않는다.
실사용 데이터는 disposable qa tenant 안에서만 생성하며 최종 tenant/user cleanup zero를 유지한다.
두 게시자는 실제 UI로 로그인하고 토큰 응답 200과 영상 목록 복귀를 각각 확인한다.
첫 게시자의 UI 응답에서 받은 access를 메모리 안에서 API 확인·cleanup에 재사용해
별도 사전 API 로그인으로 같은 계정의 제한 횟수를 추가 소모하지 않는다. 실패 진단에는
토큰·계정·응답 본문 없이 HTTP 상태만 남긴다. 429에서 요청을 재전송하거나 로그인
제한을 변경하지 않으며, 두 게시자의 공개·수정·삭제와 최종 cleanup 검증을 유지한다.
격리 개발 검증은 해당 QA API 응답에서 확인한 YouTube ID의 고정 썸네일과 autoplay=0인 iframe만 실제 HTTPS로 연다. 그 프레임 내부의 Google/YouTube 공개 공급자 요청만 허용하고, 앱 인증 헤더·운영 API·다른 origin·프레임 이탈은 계속 차단한다. 응답이나 재생 화면을 모의 데이터로 교체하지 않는다.
운영 배포 후 실제 공개 API·원본 iframe·OG와 version.json을 읽어 확인한다.
탐색 회귀는 30개 혼합 fixture로 전체 필터/정렬과 2페이지·검색·reload·상세 왕복,
조회 장애/미확인/빈 결과를 1366px/390px에서 검증한다. 격리 개발 실사용은 기존 게시자
시나리오 안에서 실제 YouTube 조회수 수신과 형식/정렬/검색·상세 복귀를 확인한다.

실제 플레이어 공급자의 같은 origin·같은 path GET/HEAD query redirect만 hop마다 검사해 최대 3회·전체 30초로 전달한다. 다른 출처/경로와 쓰기 redirect는 거부한다. 원본 응답을 그대로 사용하며 썸네일/iframe 진입의 redirect는 허용하지 않는다.

홈페이지 통합 회귀는 1366px/390px에서 공통 메뉴·현재 탭·로그인 상태, 상세에서 다른 영상 선택과
새로고침/단일 플레이어, 등록/수정 진입을 확인한다. 로그인/관리 버튼은 44px 이상의 터치 높이를
유지하고 모바일에서도 다섯 홈페이지 메뉴를 노출한다. 권한 확인 실패 후 재시도, 로그인한 비게시자의
관리 제한, 새 영상 직접 공개 완료 메시지도 route mock으로 검사한다. 격리 실사용의 두 게시자는
각자 공개 상세에서 등록/관리 CTA와 해당 영상 수정 진입까지 확인한다. 운영 기존 영상/권한은 변경하지 않는다.

## 영상 탐색 구조의 디자인 근거

2026-10-15 확인한 [EBS 클래스e](https://classe.ebs.co.kr/)의 섹션별 콘텐츠 묶음과
[인프런 강의](https://www.inflearn.com/courses)의 공통 메뉴·콘텐츠 목록 계층을 참고한다.
이는 godmin에 맞춘 설계 판단이며 해당 사이트의 콘텐츠·상표·인기 지표를 복제하지 않는다.
기존 Pretendard, 본문 #142f29, 강조 #0d6655, 보조 #657a72, 경계 #dce8e1,
배경 #fbfdfc/#f1f7f3을 유지하고 왼쪽 정렬·실제 썸네일을 중심으로 구성한다.
홈페이지 대표 영상의 기울임·별도 영문 라벨은 제거하고 동일한 카드 규칙을 사용한다.
`다른 영상도 둘러보기`는 전체 목록으로 연결한다. 목록에 시청용 대표 카드를 중복 배치하지 않아
현재처럼 적은 영상도 빠르게 훑을 수 있다. 임의 주제·가짜 검색/인기순·페이지 안에서만 작동하는
전역 필터는 추가하지 않는다. 기존 사용자 데이터와 API 계약은 그대로 유지한다.

회귀에는 형식별 목록/빈 유형/반응형 비율, 25편 페이지 이동, 시청 중 목록 오류·재시도에도
같은 iframe 보존, 목록 복귀·새로고침 시 페이지 유지가 포함된다. 디자인 판단은 실제 원본
썸네일을 사용하는 동일 빌드의 별도 시각 검토로 확인하며 mock 화면을 운영 실사용 증거로 취급하지 않는다.
