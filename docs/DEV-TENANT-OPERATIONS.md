# 개발자 콘솔 테넌트·소유자 운영 계약

개발자 콘솔 전체 정보 구조와 공통 운영 셸은
[DEVELOPER-CONSOLE.md](DEVELOPER-CONSOLE.md)가 소유한다. 이 문서는 그중
테넌트·소유자 쓰기 흐름의 추가 안전 계약을 정의한다.

`/dev/tenants`와 `/dev/tenants/:tenantId`는 플랫폼 운영 계정만 사용하는 테넌트
온보딩 화면이다. 목록의 빈 상태는 성공 응답이 실제 빈 배열일 때만 표시한다.
테넌트·상세·소유자 조회가 실패하면 오류와 `다시 시도`를 표시하며, 현재 대상을
확인할 수 없으므로 새 테넌트 또는 소유자 추가 기능을 잠근다.

## 테넌트와 소유자 생성

- `Owner 계정 함께 생성`을 선택하면 아이디와 임시 비밀번호를 모두 입력해야
  테넌트 생성 요청을 보낸다.
- 테넌트 생성부터 owner 등록이 끝날 때까지 제출 버튼을 잠가 중복 요청을 막는다.
- 테넌트는 생성됐지만 owner 등록이 실패하면 성공으로 오인해 폼을 비우지 않고
  생성된 테넌트 상세로 이동해 실제 소유자 목록에서 복구한다.
- 신규 owner는 아이디와 임시 비밀번호가 필수이고 이름·전화번호는 선택이다.

## 기존 계정 승격

소유자 추가 폼은 아이디를 먼저 확인할 수 있다. 같은 테넌트에 기존 계정이 있으면
API의 `owner_promotion_confirmation_required` 응답을 받아 현재 역할과 대상
아이디를 보여 주는 별도 확인창을 연다. 확인 후 두 번째 요청은
`promote_existing=true`와 아이디만 보내며 비밀번호·이름·전화번호를 보내지 않는다.
승격은 멤버십 역할만 바꾸고 기존 자격 증명과 프로필을 보존한다.

이미 owner인 계정, 비활성 계정, 같은 표시 ID가 여러 개인 계정은 생성·승격하지
않고 원인별 안내를 표시한다. owner 목록 조회 실패를 0명으로 간주하거나 오류 후
자동으로 재제출하지 않는다. owner 멤버십의 사용자 계정이 비활성이면 행에
`계정 비활성` 배지를 함께 표시해 로그인 가능한 owner와 구분한다. 활성 owner는
서버의 `handoffStatus`를 기준으로 `비밀번호 설정 필요`, `최초 로그인 대기`,
`인계 완료` 중 하나를 표시한다. 구버전 백엔드와의 롤링 배포 구간에서만
`isActive`·`hasUsablePassword`·`mustChangePassword`를 같은 우선순위로 해석한다.
단순히 owner 행이 존재한다는 이유로 실제 인계를 완료로 간주하지 않는다.

목록 위 인계 체크포인트는 완료 인원과 대기 인원, `계정 준비 → 본인 비밀번호
변경` 2단계 진행률, 가장 먼저 처리할 owner와 다음 동작을 보여준다. 비밀번호가
없으면 해당 owner의 임시 비밀번호 패널을 바로 열고, 최초 로그인 대기이면 실제
테넌트 기본 도메인의 `/login`을 새 탭으로 연다. `상태 새로고침`은 대표자의
비밀번호 변경 뒤 서버 상태를 다시 읽으며 조회 중 중복 요청을 잠근다. 행의
`운영 로그인`은 감사되는 임퍼소네이션임을 실제 대표자 로그인과 명확히 구분한다.
390px에서는 소유자 행을 카드형 2열 정보 블록으로 바꾸고 동작 버튼을 다음 줄에
배치하며, 체크포인트와 동작 버튼도 한 열로 재배치해 아이디·이름·전화번호·역할·
동작을 잘림 없이 유지한다.

## 기존 소유자 비밀번호 초기화

승격된 기존 계정처럼 현재 비밀번호를 알 수 없는 활성 소유자는 행의
`비밀번호 재설정`에서 임시 비밀번호와 확인값을 입력한다. 두 값이 일치하고
4~128자일 때만 별도 비밀번호 초기화 API를 호출한다. 성공하면 입력값을 즉시
비우고 패널을 닫으며, 기존 로그인 종료와 다음 로그인 비밀번호 변경 필요를 함께
안내한다. 성공 처리는 owner 목록과 활동 로그 재조회를 모두 기다린 뒤 끝나므로
직전 상태가 화면에 남지 않는다. 상태는 `최초 로그인 대기`로 표시되고, 대표자가
본인 비밀번호 변경을 끝낸 뒤에는 `인계 완료`로 전환된다. 비활성 사용자 계정은
초기화 버튼을 사용할 수 없다.

이 작업은 이름·전화번호 수정이나 소유자 추가·제거와 분리한다. 프론트엔드는
비밀번호를 React Query 캐시에 저장하지 않고 요청 본문 외에는 보관하지 않는다.
서버는 대상 테넌트의 활성 owner를 다시 확인하고 연결된 학부모·학생·직원 데이터와
멤버십을 그대로 보존한다. 세션 폐기·강제 변경·감사 로그 계약은
`backend/docs/operations/tenants/custom-domain.md`가 소유한다.

pnpm typecheck

중복 제출 잠금과 긴 안내문 오버플로를 확인한다. 백엔드의 계정·멤버십 원자성,
마지막 활성 owner 보호와 감사 로그 계약은
`backend/docs/operations/tenants/custom-domain.md`가 소유한다.
