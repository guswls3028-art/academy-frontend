# 브라우저 호환성

로그인과 학생·학부모의 학습 화면은 기기 이름으로 차단하지 않는다. 모듈을
지원하지 않는 구형 브라우저도 같은 계정, 권한, API와 화면을 사용하며,
필요한 실행 코드와 스타일만 해당 브라우저에서 읽을 수 있는 형태로 제공한다.
사진의 로딩 복구 화면이 보였다는 사실만으로 기종이나 실패 원인을 확정하지 않는다.

## 제공 경로와 대상

`vite.config.ts`의 legacy 빌드 대상은 iOS Safari 10.3 이상, Chrome 64 이상,
Firefox 60 이상, Samsung Internet 8 이상이다. iPhone 5 계열처럼 운영체제
업데이트가 제한된 기기와 구형 Android 브라우저를 포함하기 위한 컴파일
기준이며, 각 기기의 실제 OS·브라우저 버전과 재생 능력은 별도로 확인한다.

- 최신 브라우저는 기존 모듈 번들을 사용한다.
- 구형 브라우저는 생성된 `nomodule` 로더로 SystemJS 번들을 읽는다. 로그인
  이후의 지연 로딩 화면도 legacy 번들을 제공하므로 첫 화면만 표시한 뒤
  메뉴 이동에서 실패하는 방식으로 완료를 판단하지 않는다.
  생성된 SystemJS 코드도 원본 모듈의 strict 실행 의미를 보존하여 모달 등
  지연 로딩 화면의 함수·변수 동작이 달라지지 않게 한다.
- 필요한 JavaScript 표준 기능과 브라우저 API 보완은 앱 실행 전에 적용한다.
  미지원 `fetch`, 요청 취소, 텍스트 인코딩, 관찰자 API를 보완하며
  `crypto.randomUUID`가 없으면 안전한 난수 기반 공용 UUID 함수를 사용한다.
  `matchMedia`는 구형 `addListener`/`removeListener`도 지원한다.
- legacy 로더는 같은 자산에서 생성한 legacy CSS를 선택한다. 테마 변수와
  의미를 유지하면서 구형 엔진이 해석하지 못하는
  레이어, 선택자, 색상·뷰포트 표현을 호환 형태로 바꾼다. 앱 시작과 지연
  로딩 화면 모두 해당 legacy 스타일을 사용한다. 최신 모듈 경로의 스타일은
  유지한다.
- Ant Design이 실행 중 생성하는 스타일도 legacy 진입에서 `StyleProvider`의
  높은 해시 우선순위와 논리 속성 변환을 적용한다. 정적 CSS 변환만으로
  다룰 수 없는 모달 선택자·화면 전체 덮개 배치를 이 경로에서 보완한다.

소유 구현은 `vite.config.ts`, `index.html`, `scripts/legacy-css.mjs`,
`src/main.tsx`, `src/shared/browser/`와 `src/shared/utils/`의 브라우저 호환 코드다.
정확한 보완 목록과 적용 순서는
빌드 설정·부트스트랩이 정본이다. 새 패키지나 브라우저 API를 추가할 때는
현재 대상에서 변환되는 문법인지, 별도 런타임 보완이 필요한지도 확인한다.

## 사용자 흐름과 경계

로그인 폼은 입력값을 보존하여 기존 토큰 API를 호출하고, 저장된 세션으로
역할별 홈에 이동한다. 구형 경로에서도 메뉴 이동, 공지 상세, 새로고침과
직접 URL 진입이 가능해야 한다. 학생 320px·360px·390px 화면에서는 주요
입력·버튼과 본문이 화면 밖으로 밀려 조작할 수 없는 상태가 없어야 한다.
학생 앱의 문서 스크롤 잠금은 `StudentLayout`의 마운트 표시를 사용하므로
구형 브라우저의 `:has()` 지원 여부에 의존하지 않는다. 로그아웃으로 학생
앱을 벗어나면 해당 표시를 제거한다.

호환성 처리는 인증·테넌트·학부모 자녀 선택을 우회하지 않는다. 계정·데이터
마이그레이션도 없다. 기존 저장소의 로그인·초안·취향 범위는
[브라우저 저장 계약](BROWSER-PERSISTENCE.md)을 따르고, 저장소 접근 실패와
API 오류는 해당 화면의 오류·재시도 흐름으로 남긴다. 로딩 복구 안내가
나타났거나 재시도 버튼이 있다는 사실을 정상 로그인으로 집계하지 않는다.

영상은 동일한 서버 재생 권한과 정책을 사용한다. 브라우저가 HLS를 직접
재생할 수 있으면 네이티브 경로를 우선 사용하며, 그렇지 않으면 기존
`hls.js`/MediaSource 경로를 사용한다. 구형 WebKit의 `video.play()`가 Promise를
반환하지 않아도 재생·재개 호출 자체가 오류로 끝나지 않는다. 재생 권한,
건너뛰기 제한, 재생 갱신과 이어보기 정책은
[개별 영상 접근 계약](VIDEO-DIRECT-ACCESS.md) 및 서버 정책을 그대로 따른다.

## 검증

`pnpm build` 후 `vite preview`로 실제 산출물을 띄워
`pnpm test:e2e:bundle-smoke`를 실행한다. 개발 서버에서 성공한 결과만으로
legacy 산출물의 정상 부팅을 판정하지 않는다.

`e2e/smoke/legacy-bundle-runtime.spec.ts`는 실제 HTML에서 module 실행과
preload만 제외하고 생성된 nomodule 로더를 실행한다. 선택된 브라우저 API가
없는 상태에서 legacy 자산 요청, 로그인 요청값, 학생 홈, 공지 이동·본문,
세션을 유지한 새로고침, 사용 신호 기록, legacy 스타일 요청·실제 색상·버튼
크기, 문제 신고 모달의 입력·전송 없는 닫기·실행 중 생성된 스타일,
가로 넘침, 로그아웃의 스크롤 표시 정리와 브라우저 오류를 확인한다.
스타일 링크 이름뿐 아니라 각 자산의 HTTP 성공과 CSS 적용 여부도 확인한다.
390px 학부모 검증은 선택 전 학생 조회가 없음을 확인한 뒤 두 자녀를 순서대로
선택하고, 선택된 자녀의 요약·`X-Student-Id`와 새로고침 후 선택 복원을 확인한다.
영상 검증은 네이티브 HLS 선택과 Promise 없는 재생·일시정지
조작, 구형 클릭 이벤트의 숨은 컨트롤 복구, 위치 저장·새로고침 후 이어보기를
실제 컨트롤러로 확인한다.
API 응답과 미디어 이벤트는 모의한다.
이 결과는 현재 Playwright 브라우저의 기능 부재 재현이며 실제 iPhone 5의
엔진·코덱·네트워크에서 성공했다는 증거가 아니다.

공용 런타임 회귀 검증은 `scripts/tests/legacy-runtime-apis.test.mjs`가 소유한다.
CSS 변환은 `scripts/tests/legacy-css.test.mjs`, legacy 모듈 실행 의미는
`scripts/tests/legacy-module-semantics.test.mjs`에서 추가 검증한다.
기존 Safari 로그인·저장소·역할 이동 검증도 함께 유지한다. 실제 기기 검수는
OS와 브라우저 버전, 로그인→역할 홈→수업·공지 이동→영상 시작·정지→새로고침
후 상태 복구를 기록한다. 기기 인증·업무 데이터 변경이 필요한 QA는
[격리 개발 런타임](../../backend/docs/operations/persistent-development-runtime.md)에서
실행하고 생성한 QA 테넌트와 사용자 잔여가 0인지 확인한다.
