# 개발자 문의함 사용 가이드

## 화면 오류에서 바로 제보

- 화면 전체가 열리지 않으면 관리자·선생님·학생·학부모 앱과 개발자 콘솔이
  공통 오류 카드를 표시한다. **다시 불러오기**로 복구하거나 **버그 제보**를
  열어 증상을 보낼 수 있다. 앱이 시작되기 전 자산 로드에 실패한 경우에는
  같은 카드에서 연결 확인과 다시 불러오기를 제공한다. 새 버전을 자동으로
  다시 불러오는 동안은 진행 상태를 표시한다.
- 기존 프로필·메뉴의 **문제 신고**도 같은 입력 화면과 접수 결과를 쓴다.
  현재 학원에 로그인한 계정으로 증상을 최대 1,000자까지 보낼 수 있다.
  일반 접수 실패는 작성 내용을 유지하며 재시도를 안내한다. 로그인이나
  권한이 필요한 경우에는 제보에 필요한 조건을 표시한다.
- **버그 제보가 접수됐어요**는 `POST /core/problem-reports/`의 DB 저장 성공
  뒤에 표시한다. 쿼리와 해시를 뺀 경로(숫자와 UUID 가림), 화면 크기,
  오류 추적 번호가 있으면 해당 번호를 함께 보낸다. 제보 본문은 운영 접수에 저장한다.
  플랫폼 운영자는 개발자 콘솔 문의함의 **빠른 신고**에서 확인한다.
  [백엔드 접수·권한 계약](https://github.com/guswls3028-art/academy-backend/blob/main/docs/operations/dev-console-inbox.md)
- 빌드 브라우저 스모크는 데스크톱과 390px에서 오류 안내, 입력·제출, 실패 뒤 재시도,
  성공 표시와 새로고침을 검증한다. 구형 번들은 앱 시작 실패와 프로필 모달에서
  제보하는 경로를 검증한다.

## 학원장·선생님

1. 관리자 또는 선생님 앱의 `버그 제보`·`피드백` 화면에서 제목과 내용을
   작성한다.
2. 스크린샷이나 파일을 첨부할 수 있다. 문의 등록 후 첨부만 실패하면 새 문의를
   다시 만들지 말고 화면의 `첨부만 다시 올리기`를 누른다.
3. 아래 `우리 학원 제보/피드백 내역`에서 처리 상태와 개발팀 답변 본문을
   확인한다. 이력은 같은 학원의 직원이 함께 보는 운영 기록이다.
4. 제출된 문의·대화·첨부는 기록 보존을 위해 수정하거나 삭제할 수 없다.
   답변 뒤 추가 확인이 필요하면 해당 문의에 후속 답변을 남긴다.

## 플랫폼 운영자

1. `/dev/inbox`는 기본적으로 미처리 문의를 보여준다.
2. 상단 집계에서 전체 도입 문의·버그·개선 의견·완료 건수를 확인하고, 검색과
   유형·상태 필터로 대상을 좁힌다.
3. 도입 문의와 빠른 신고는 내부 메모를 저장한 뒤 `처리 완료` 또는
   `미처리로 전환`한다. 내부 메모는 문의자에게 공개되지 않는다.
4. 지원 티켓은 개발팀 답변을 등록하면 완료된다. 문의자가 그 뒤 후속 답변을
   남기면 자동으로 미처리 상태로 돌아온다.
5. 실제 도입 문의의 전화번호와 내용은 운영 목적에만 사용하고, 검증 중 상태나
   메모를 임의로 변경하지 않는다.
