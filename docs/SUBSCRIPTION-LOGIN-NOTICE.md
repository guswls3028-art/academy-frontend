# 로그인 시 이용기간 안내

관리자·교사 작업공간(`/workspace`, `/workspace/mobile`)은 실제 자격증명 로그인
성공 후 현재 테넌트의 연체 안내를 한 번 표시한다. 서버가 활성 테넌트 구성원인
owner/admin/teacher/staff 중 연체했지만 서비스 이용이 가능한 대상에게만
`GET /core/me/`의 `subscription_notice`를 내려준다. 조교는 staff 역할이다.
학생·학부모·학생 지원 미리보기·개발자 콘솔에는 표시하지 않으며 전역
`is_staff`만으로 안내 대상이나 납부 권한을 부여하지 않는다.

응답은 `null` 또는 `{subscription_expires_at: 'YYYY-MM-DD',
service_access_expires_at: 'YYYY-MM-DD', days_overdue: number, days_remaining: number}`다.
클라이언트는 “이용기간이 지났습니다. 결제 내역을 확인해주세요.”와 서버 날짜·일수를 표시하며 유예기간·연체 여부를 계산하지 않는다.
갱신 후 서버가 `null`을 보내면 열린 안내도 사라진다. 필드가 없는 이전 서버에도
안내 없이 호환된다. 정책 소유자는 [백엔드 문서](../../backend/docs/README.md)다.

공통 `login()`의 토큰 저장 성공에서만 테넌트와 인증 generation에 묶인 일회성
메모리 예약을 만든다. 첫 계정 안내·비밀번호 안내와 조교 출근 선택을 먼저 마친다.
예약은 작업공간 안내 진입에서 소비한다. 닫기·확인·Escape로 계속 작업할 수 있다.
안내가 없는 로그인도 이후 화면 이동에서 뒤늦게 안내를 열지 않는다.
페이지 이동, 새로고침, 기존 세션 복원, 탭 포커스, 토큰 갱신은 예약을 만들지 않는다.
새 실제 로그인은 다시 안내할 수 있다. 저장소에 안내 날짜나 청구 정보를 남기지 않는다.

추가 `/core/subscription/` 요청, 결제 화면 링크 또는 납부 권한 변경은 없다.
안내 UI chunk는 직원 작업공간 인증 뒤에만 lazy-load해 로그인·학생 진입 번들에
직원 모달 UI를 넣지 않는다. 로딩 중에도 작업공간은 그대로 이용할 수 있으며
chunk 실패는 기존 앱의 자산 재시도·복구 경계를 따른다.
별도 로딩 UI·확인 저장 요청도 없다. `/core/me/` 로딩·실패·재시도는 기존 로그인과
인증 복구 화면이 담당하며 응답 실패를 정상 안내로 꾸미지 않는다. 닫기는 네트워크와
무관하게 즉시 가능하다. 이 안내는 서비스 차단 오버레이나 접근 정책을 대체하지 않는다.

공용 AdminModal·Button을 사용해 제목, focus trap/복귀, Escape·Enter를 유지한다.
1100/1366px와 390px에서 긴 한국어 안내와 날짜가 화면 안에 배치되며 짧은 등장
모션은 reduced-motion에서 꺼진다.

`e2e/auth/subscription-notice.mock.spec.ts`는 실제 로그인 폼과 완전히 mock한 API로
양쪽 작업공간의 역할·화면 폭, 안내 순서, 닫기, 탐색·새로고침·토큰 갱신 후 미노출,
재로그인, 서버 갱신, 학생·학부모 제외, 이전 응답 호환, 실패 후 재시도를 검증한다.
운영 복구·백엔드 유예 정책·실배포 검증은 별도 릴리스 소유자가 담당한다.
