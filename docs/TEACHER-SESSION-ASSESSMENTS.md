# 선생님 차시 성적 조회

## 목적과 진입

선생님 워크스페이스의 `/workspace/mobile/classes/:lectureId/sessions/:sessionId`
성적 탭은 같은 학생의 시험·과제를 함께 확인하는 **종합 조회**를 기본으로 연다.
학생·출석·성적·시험·과제·영상 탭과 기존 출석 체크·성적 입력 동선은 유지한다.
클리닉 탭의 노출 조건 및 서버 판정은 이 화면 변경의 소유 범위가 아니다.

## 조회와 이동

- 종합 조회는 차시의 모든 시험·과제를 학생별로 묶는다. 휴대폰에서는 학생별
  행 묶음, 640px 이상에서는 학생 이름과 평가 제목 헤더가 고정되는 비교 표다.
  비교표의 높이는 화면 높이의 65% 이내이며 표 내부에서 상하·좌우로 이동한다.
  마지막 학생을 볼 때도 평가 제목을 유지한다. 긴 평가명·학생명은 생략하지
  않고 줄바꿈한다.
- 평가명은 기존 시험/과제 상세 화면으로 이동하는 링크다. 시험은 만점과
  응답에 존재하는 통과 기준을 함께 보여 준다. 완료형 과제는 숫자 점수 대신
  완료/미완료/미입력으로 표시한다. 시험이 없어도 과제만 조회할 수 있다.
- 시험 상세의 `성적 입력 열기`도 해당 시험 ID를 입력 주소에 전달한다.
  차시가 여럿인 시험은 선택한 차시와 현재 시험을 함께 유지한다.
- `시험별 조회`는 기존 시험별 학생 결과와 점수 입력/수정 경로를 유지한다.
  유효한 선택이 없으면 현재 차시의 첫 시험을 즉시 조회한다. 시험 선택 버튼은
  전체 제목이 보이고 최소 44px 높이를 확보한다.
- `tab`, `scoresView=all|exams`, `exam` 쿼리는 탭 전환·새로고침·상세에서
  돌아왔을 때 맥락을 복구한다. 알 수 없는 탭은 학생 탭, 조회 방식은 종합으로
  돌아간다. `exam`은 현재 차시의 응답에 포함된 ID만 사용하며 잘못되거나
  이전 차시의 ID는 조회하지 않고 첫 시험으로 대체한다.
- 시험별 입력/수정 및 성적 탭의 상단 성적 입력은 검증된 시험을
  `/workspace/mobile/scores/:sessionId?exam=:examId`로 전달한다. 저장 후
  뒤로 돌아오면 기존 공용 캐시 무효화에 따라 수정 결과를 다시 읽는다.

## 데이터와 권한

종합 조회의 정본은 `GET /results/admin/sessions/:sessionId/scores/`와
`scoresQueryKeys.sessionScores(sessionId)`다. 별도 목록 API를 조합하여 성적을
재구성하지 않는다. 시험별 결과는 기존
`GET /results/admin/exams/:examId/results/`와 teacher 결과 키를 유지한다.
인증·테넌트·역할·차시 접근 허용은 기존 공용 API와 서버가 소유한다.

`ScoreBlock.score`를 직접 읽고 평가 메타의 만점을 먼저 사용한다. 0점, 미채점,
미응시, 과제 미입력/미제출, 임시 점수, 검토 필요는 구분한다. 최종 판정은
공용 `deriveFinalPass`가 읽는 서버 필드로 표시하고 통과 기준과 점수를 비교해
재계산하지 않는다. 선생님 확인 완료는 별도 표시이며 이를 합격 또는 클리닉
해제와 동일시하지 않는다. 일반 합불 표시에서도 시험의 `correction_status=PENDING`은
`오답 미완료`로 별도 표시한다. 시험 통과·오답 확인·클리닉 대상은 서로 독립적이다.
`wrong_completion` 테넌트의 시험은 기존 공용 오답 상태 표시 함수를 따르며,
과제의 최종 판정은 유지한다. 완료형 과제에 미제출 상태도 있으면 완료 수치와 원본
미제출 상태를 함께 남긴다. 클리닉 대상 여부를 새로 계산하지 않는다.

조회는 쓰기를 하지 않는다. 성적 수정은 기존 입력 화면의 lease·점수 PATCH·
lease 해제 및 공용/시험별 캐시 갱신 경로를 그대로 사용한다. 정책/API 계약은
[backend 문서](../../backend/docs/README.md) 및
[과제 채점 정책](../../backend/docs/domain/homework-grading.md)이 소유하며 이 문서는
표시·이동만 소유한다.

선생님 레이아웃은 기존 Ant Design `App`과 공용 `FeedbackBridge`를 마운트하여
저장 성공·실패 안내를 실제로 표시한다. `component={false}`로 기존 DOM·밀도·
스크롤 레이아웃을 바꾸지 않는다. 교사 화면에 없던 메시지 수신부를 연결하는
변경이며, 점수/권한/서버 저장 정책을 수정하지 않는다. 공용 bridge의 기존
effect 정리 규칙에 따라 레이아웃을 떠나면 메시지 참조를 해제한다.
저장 실패 시 입력 초안을 지우지 않고 원래 서버 점수를 유지하며, 재시도 성공
후 같은 시험의 수정 결과를 다시 조회한다. 입력은 기존 Enter·포커스 이동 시
저장 계약을 유지한다. 복원된 초안에서 검색창 등으로 포커스를 옮기는 동작도
재저장을 시도하므로 검증에서 이를 별도의 사용자 저장 동작으로 다룬다.

## 대기·실패·빈 상태

조회 중에는 로딩을 표시한다. 요청 실패는 빈 성적표로 취급하지 않고 오류와
다시 시도를 제공한다. 평가가 없는 경우에는 강의에서 추가 동선을, 수강생이
없는 경우에는 차시 배정 확인 안내를 제공한다. 개별 학생 점수가 비어 있다고
해당 학생이나 평가 열을 제거하지 않는다. 학생별 평가 entry가 없으면 미배정이며,
entry가 존재하고 점수가 null인 미채점/미입력과 구분한다.

## 검증

`e2e/teacher/session-assessment-overview.mock.spec.ts`는 localhost의 합성 테넌트,
학생·시험·과제만 사용한다. 기본 종합 및 첫 시험 자동 선택의 변경 전 실패를
확인한 뒤 390/768/1024/1366px, 긴 제목, 상태 구분, 잘못된 선택, 과제 전용,
빈 상태·실패 재시도, 시험 B 입력→저장→뒤로→새로고침을 검증한다.
저장 성공 알림과 실패 알림, 실패 후 초안 유지·재시도도 실제 화면에서 확인한다.
DOM 가로 넘침 및 실제 렌더 캡처를 함께 확인한다. 이 fixture 검증은 실제
서버/운영 데이터 검증을 대체하지 않는다. 운영 반영 및 격리 개발 서버의
실사용 검증은 릴리스 소유 세션의 배포 게이트를 따른다.
