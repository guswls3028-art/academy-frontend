# 과제 만점·합격 정책·성적표 프런트엔드 계약

## 화면 흐름과 설정 관계

관리자·선생님은 **강의 → 차시**에서 과제를 만들 때 `숫자 채점` 또는
`완료 체크`를 과제마다 고른다. **과제 운영 설정**에서 채점 방식과
과제명·제출기한·만점·합격 기준을 확인한 뒤 **성적** 탭에서 학생 결과를
입력한다. 운영 준비 점검선과 대상자 흐름은
[ASSESSMENT-OPERATIONS-WORKSPACE.md](ASSESSMENT-OPERATIONS-WORKSPACE.md)가
소유한다.

```text
과제 A 만점 + 기준 ─ 성적표 A 합격·클리닉 판정
과제 B 만점 + 기준 ─ 성적표 B 합격·클리닉 판정
과제 C 만점 + 기준 ─ 성적표 C 합격·클리닉 판정
```

- **과제 만점**은 선택한 과제 하나의 설정이다. 문제 수가 다르면 각각 다른
  만점을 지정한다.
- **과제별 합격 기준**은 선택한 과제 하나에만 적용된다. 한 회차에서 과제를
  여러 개 만들어도 퍼센트/원점수와 값을 각각 다르게 저장할 수 있다.
- 개별 기준을 아직 저장하지 않은 기존 과제는 기존 차시 기본값을 표시한다.
  설정 화면에서 저장하면 해당 과제의 개별 기준으로 고정된다.
- 프런트는 차시 공통 정책을 더 이상 수정하지 않는다. 백엔드의 기존 정책 API는
  구버전 클라이언트와 개별 기준 없는 기존 데이터의 fallback으로 유지한다.
- 차시 과제 카드에는 `만점 N점 · 기준 N%/N점`을 함께 표시해 두 범위를
  혼동하지 않게 한다.
- **완료 체크** 과제는 만점·커트라인 입력 대신 `완료/미완료`만 사용한다.
  아직 검사하지 않은 `미입력`과 실제로 확인한 `미완료`는 구분한다.
- 완료 체크 생성 행에는 사용하지 않는 만점 입력을 노출하지 않고, 완료/미완료만
  선택한다는 설명을 보여 숫자 채점 설정으로 오해하지 않게 한다.
- 결과가 이미 입력된 과제는 채점 방식 변경을 요청해도 기존 기록 보호 오류를
  표시한다. 템플릿 가져오기와 다른 차시 복사는 원래 채점 방식을 보존한다.

저장·판정·tenant 불변 규칙은 백엔드
[`homework-grading.md`](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/homework-grading.md)가
소유한다.

## 만들기·복사·설정 저장

- 과제 생성은 각 행의 **제목을 먼저 입력**하는 흐름으로 안내한다. 제목이 비어
  있거나 숫자형 배점·기준이 유효하지 않으면 하단 `과제 만들기`를 비활성화하고,
  버튼 가까이에 지금 필요한 입력을 설명한다. 사용자가 활성화 조건을 찾기 위해
  모달을 훑게 하지 않는다.
- 한글 조합 중인 제목은 조합이 끝나기 전에 상위 상태로 덮어쓰지 않는다.
  `전자기유도` 같은 입력은 표시·요청 값 모두 원문 순서를 보존한다.
- 과제 생성 모달은 제목, `max_score`, 과제별 커트라인을 한 요청으로 저장한다.
  여러 행의 커트라인 입력은 서로 독립이다. 만점이 1 미만이거나 해당 과제의
  원점수 커트라인보다 낮으면 아무 과제도 만들기 전에 오류를
  표시한다.
- 다른 차시 과제를 복사할 때 원본 과제의 만점과 합격 기준을 보존한다.
  100점·회차 기본 기준으로 재설정하지 않는다.
- 과제 운영 설정은 `PATCH /homeworks/{id}/`에 `title`, `max_score`,
  `cutline_mode`, `cutline_value`, `round_unit_percent`와 기존 값을 보존한
  `meta.due_date`를 한 번에 보낸다. 성공하면 과제 상세, 차시 과제 목록,
  성적표 캐시를 모두 무효화해 새 제목·기한·분모·판정 기준을 즉시 다시 읽는다.
- 서버 검증 오류는 입력값을 남긴 채 메시지로 보여 주며 저장 성공으로
  가장하지 않는다.

## 성적표 표시와 입력

- 성적표의 **만점 표기** 모드는 각 과제 메타의 `max_score`로 `점수/만점`을
  표시한다. 예를 들어 43점 만점에 41점이면 `41/43`이다.
- 셀 입력은 0부터 해당 과제 만점까지만 허용한다.
- 자동 저장과 `Ctrl+S` 요청에는 화면이 읽은 과제 만점을 함께 보내지만,
  최종 정본과 초과 점수 검증은 서버가 소유한다.
- 미입력 `-`, 미제출, 미배정, 검수 대기 상태를 0점과 혼동하지 않는다.
- 점수 저장 실패 시 입력값과 복구 초안을 유지하고 사용자가 다시 시도할 수
  있게 한다.
- 완료형 컬럼은 숫자 입력 칸 대신 `미입력·미완료·완료` 선택기를 표시한다.
  선택은 기존 자동 저장·실행 취소·편집 lease 흐름에 포함되고, 서버가 반환한
  `passed`와 클리닉 판정을 다시 읽는다.

## 학생 상세에서 바로 수정

- 학생 상세 과제 탭은 점수가 생긴 과제만 나열하지 않고 이 학생에게 배정된
  운영 과제를 기준으로 표시한다. 따라서 검사 전 과제도 행이 유지된다. 서버의
  `meta_status=NOT_SUBMITTED`는 **미제출**, 점수·미제출 기록이 모두 없는 상태는
  **검사 전**으로 표시하며 둘을 `0점`이나 빈 목록으로 바꾸지 않는다.
- 각 행은 채점 방식을 `숫자 채점` 또는 `완료 체크`로 함께 보여 준다. 상단
  요약은 완료 수와 미제출 수를 분리하고, 완료형에 `0/1`을 노출하지 않는다.
- **학생 목록 → 학생 상세 → 과제**에서 각 과제의 `바로 수정`을 누르면 현재
  화면 안에 작은 편집 패널이 열린다. 차시 화면으로 이동하지 않는다.
- 완료형은 `미완료/완료` 두 버튼을 누르는 즉시 저장한다. 숫자형은 점수를
  직접 입력하거나 `전부 완료`로 과제 만점을 저장한다. 숫자형의 완료 여부는
  임의 토글이 아니라 저장 점수와 서버 합격 기준으로 다시 계산한다.
- 저장 중에는 중복 입력을 막고, 잠긴 결과 또는 다른 성적표 편집 lease가 있으면
  원인을 표시하며 기존 값을 유지한다. 성공 후 학생별 성적을 재조회해 배지와
  점수, 클리닉 판정을 함께 갱신한다.
- 편집 패널은 키보드로 조작할 수 있고 `Escape`로 패널만 닫는다. 사이드바나
  모바일 화면 때문에 과제 목록 컨테이너가 좁아지면 제목 아래에 점수·상태·
  `바로 수정` 동작을 온전히 배치하고, 편집기의 입력과 동작 버튼은 세로로
  배치해 가로 넘침이나 잘림을 만들지 않는다. 열림 전환은 짧은 이동·투명도
  피드백만 사용하고 `prefers-reduced-motion`에서 제거한다.
- 생성·설정 모달은 낮은 노트북 화면과 390px 모바일에서 본문만 스크롤되고,
  제목·닫기·주요 제출 동작은 계속 접근 가능해야 한다. 페이지 축소는 정상 사용
  방법으로 요구하지 않는다.

학생 상세 과제 탭은 기본적으로 **최근 차시순**으로 표시해 1차시가 목록 아래에
오도록 한다. `수업(정규·보강)`, `상태(확인 필요·완료)`, `정렬(최근 차시·
1차시부터·최근 수정)` 필터를 제공하며 결과 수를 함께 보여 준다. 같은 차시의
여러 과제는 과제 표시 순서를 유지한다. 필터는 조회 범위나 저장 권한을 넓히지
않고 현재 tenant·학생 응답 안에서만 작동한다.

## 워크북 원본과 문항 채점표

- 과제 **자산**의 **워크북 자료 올리기**는 문제+해설 한 파일, 문제 파일 하나,
  문제 PDF/이미지와 해설 HWP/HWPX 두 파일을 같은 모달에서 받는다.
- HWP/HWPX는 미주 번호를 짝짓기 기준으로 쓰며 선생님 필기 해설 원본 이미지를
  보존한다. 검수 화면에서는 문제 영역 높이와 번호·수록 여부를 교직원이 확정한다.
- 원본이 준비되면 과제 **결과**에 학생×문항 채점 장부가 열린다. 셀은 `—`, `O`,
  `X · 수록`, `O · 복습`이며 변경 즉시 서버 응답으로 장부를 다시 맞춘다.
- X는 오답노트에 포함한다. 다시 맞혔지만 계속 복습시킬 문항은 O·복습으로
  바꾸고, 완전히 제외할 때만 O로 바꾼다.
- 소유 구현은 `HomeworkAssetsPanel.tsx`, `HomeworkQuestionLedger.tsx`,
  `api/adminHomework.ts`다.

## 제출관리 파일별 검수

- **과제 → 제출관리**는 제출 행 건수를 평면 목록으로 보여 주지 않고 학생 제출
  묶음 안에 ordered 사진·동영상 파일을 펼친다. 상단에서 제출 학생, 활성 전체 파일,
  검수 가능, 업로드 오류 수를 분리해 선생님이 확인 우선순위를 바로 판단한다.
- 각 파일은 순서, 사진/동영상 종류, 안전한 원본 표시명, 용량, `저장 중·검수 가능·
  업로드 실패·교체됨` 상태와 서버 오류를 독립적으로 표시한다. 실패·저장 중·교체된
  파일의 미리보기 버튼은 비활성화한다.
- `미리보기`는 bucket key를 브라우저에 전달하거나 공용 storage inventory에 다시
  제출하지 않는다. 파일 opaque id를 과제 media preview API에 보내고 같은 tenant·
  교직원 권한을 통과한 짧은 서명 URL만 image/video viewer에 사용한다. 조회 실패는
  닫기 가능한 모달 안에서 재시도하며 목록을 빈 상태로 바꾸지 않는다.
- 학생별 카드와 파일 행은 데스크톱에서 빠르게 훑을 수 있는 밀도를 유지하고,
  390px에서는 학생 메타와 파일 동작을 줄바꿈해 문서 가로 스크롤을 만들지 않는다.
- 소유 구현은 `HomeworkSubmissionsPanel.tsx`, `HomeworkMediaPreviewModal.tsx`,
  `adminHomeworkSubmissions.api.ts`다. 집중 회귀는
  `e2e/admin/homework-media-review.mock.spec.ts`가 파일별 상태·오류·권한 미리보기와
  데스크톱/390px 레이아웃을 검증한다.
