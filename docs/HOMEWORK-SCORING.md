# 과제 만점·합격 정책·성적표 프런트엔드 계약

## 화면 흐름과 설정 관계

관리자·선생님은 **강의 → 차시**에서 과제를 만들 때 `점수형` 또는
`통과형 (O/X)`을 과제마다 고른다. **과제 운영 설정**에서 채점 방식과
과제명·제출기한·만점·합격 기준을 확인한 뒤 **성적** 탭에서 학생 결과를
입력한다. 운영 준비 점검선과 대상자 흐름은
[ASSESSMENT-OPERATIONS-WORKSPACE.md](ASSESSMENT-OPERATIONS-WORKSPACE.md)가
소유한다.

```text
과제 A 만점 + 기준 ─ 성적표 A 합격·클리닉 판정
과제 B 만점 + 기준 ─ 성적표 B 합격·클리닉 판정
과제 C 만점 + 기준 ─ 성적표 C 합격·클리닉 판정
```

- **과제 만점**은 선택한 과제 하나의 설정이다. 문제 수가 다르면 각각 다른
  만점을 지정한다.
- **과제별 합격 기준**은 선택한 과제 하나에만 적용된다. 한 회차에서 과제를
  여러 개 만들어도 퍼센트/원점수와 값을 각각 다르게 저장할 수 있다.
- 개별 기준을 아직 저장하지 않은 기존 과제는 기존 차시 기본값을 표시한다.
  설정 화면에서 저장하면 해당 과제의 개별 기준으로 고정된다.
- 프런트는 차시 공통 정책을 더 이상 수정하지 않는다. 백엔드의 기존 정책 API는
  구버전 클라이언트와 개별 기준 없는 기존 데이터의 fallback으로 유지한다.
- 차시 과제 카드에는 `만점 N점 · 기준 N%/N점`을 함께 표시해 두 범위를
  혼동하지 않게 한다.
- **통과형 (O/X)** 과제는 만점·커트라인 입력 대신 `통과/미통과`만 사용한다.
  아직 검사하지 않은 `미입력`과 실제로 확인한 `미통과`는 구분한다.
- 통과형 생성 행에는 사용하지 않는 만점 입력을 노출하지 않고, 통과/미통과만
  선택한다는 설명을 보여 숫자 채점 설정으로 오해하지 않게 한다.
- 결과가 이미 입력된 과제는 채점 방식 변경을 요청해도 기존 기록 보호 오류를
  표시한다. 템플릿 가져오기와 다른 차시 복사는 원래 채점 방식을 보존한다.
- 점수형은 [차시별 합산 설정](ASSESSMENT-TOTALS.md)에 따라 과제 총점에
  포함하며 통과형은 합산하지 않는다. 기존 API의 COMPLETION 기록은 보존한다.

저장·판정·tenant 불변 규칙은 백엔드
[`homework-grading.md`](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/homework-grading.md)가
소유한다.

## 만들기·복사·설정 저장

- 과제 생성은 각 행의 **제목을 먼저 입력**하는 흐름으로 안내한다. 제목이 비어
  있거나 숫자형 배점·기준이 유효하지 않으면 하단 `과제 만들기`를 비활성화하고,
  버튼 가까이에 지금 필요한 입력을 설명한다. 사용자가 활성화 조건을 찾기 위해
  모달을 훑게 하지 않는다.
- 한글 조합 중인 제목은 조합이 끝나기 전에 상위 상태로 덮어쓰지 않는다.
  `전자기유도` 같은 입력은 표시·요청 값 모두 원문 순서를 보존한다.
- 과제 생성 모달은 제목, `max_score`, 과제별 커트라인을 한 요청으로 저장한다.
  여러 행의 커트라인 입력은 서로 독립이다. 만점이 1 미만이거나 해당 과제의
  원점수 커트라인보다 낮으면 아무 과제도 만들기 전에 오류를
  표시한다.
- 다른 차시 과제를 복사할 때 원본 과제의 만점과 합격 기준을 보존한다.
  100점·회차 기본 기준으로 재설정하지 않는다.
- 과제 운영 설정은 `PATCH /homeworks/{id}/`에 `title`, `max_score`,
  `cutline_mode`, `cutline_value`, `round_unit_percent`와 기존 값을 보존한
  `meta.due_date`를 한 번에 보낸다. 성공하면 과제 상세, 차시 과제 목록,
  성적표 캐시를 모두 무효화해 새 제목·기한·분모·판정 기준을 즉시 다시 읽는다.
- 서버 검증 오류는 입력값을 남긴 채 메시지로 보여 주며 저장 성공으로
  가장하지 않는다.

## 성적표 표시와 입력

과제 상세의 **결과** 탭은 통과형을 O/X로 표시하고 미입력·미제출과 구분한다.
통과형에는 숫자 커트라인이나 점수 분포를 표시하지 않으며, 통과·미통과·클리닉
집계는 서버 판정을 유지한다. 점수형 분포는 0–20%, 20% 초과–40% 등 연속된
구간을 사용해 소수점 점수도 한 구간에 포함한다. 학생을 선택하면 PC에서는
표 오른쪽, 390px에서는 표 아래에 상세를 표시하며 표는 자체 가로 스크롤을 사용한다.
결과 탭의 통계는 실제 제출률을 추정하지 않고 성적에 기록된 미입력·미제출 처리·
채점/판정 입력 인원을 구분한다. 미입력은 제출 완료를 뜻하지 않으며 실제 파일 제출은
**제출관리**에서 확인한다. 점수 분포 라벨은 같은 높이의 두 줄로 경계를 표시한다.

성적표 수정 중에는 **실행 취소·다시 실행** 버튼과 기존 Ctrl/⌘+Z·Ctrl/⌘+Y
단축키를 함께 제공한다. 모바일에서도 시험·과제 입력 실수를 되돌릴 수 있다.
이미 자동 저장된 값도 역방향 변경으로 저장하고, 다시 실행하면 원래 변경을
저장한다. 이 화면에서 기록한 변경만 대상으로 하며 새로고침 이전의 전체 이력을
복원하는 기능은 아니다. 저장 실패·동시 수정 충돌은 기존 입력 복구 경로를 유지한다.

- 성적표의 **만점 표기** 모드는 각 과제 메타의 `max_score`로 `점수/만점`을
  표시한다. 예를 들어 43점 만점에 41점이면 `41/43`이다.
- 셀 입력은 0부터 해당 과제 만점까지만 허용한다.
- 시험·점수형 과제의 `%` 입력은 현재 만점에 대한 원점수로 변환하며 소수를
  정수로 반올림하지 않는다. 예를 들어 1.5점 만점의 `100%`는 1.5점,
  `50%`는 0.75점이고 3점 만점의 `50%`는 1.5점이다. 숫자 없이 `%`만 입력하면
  0점으로 해석하지 않고 잘못된 입력으로 처리해 기존 점수를 유지한다.
- 숫자 셀에서 `Escape`를 누르면 이번 포커스 이후 입력만 취소한다.
  표시값뿐 아니라 저장 대기값과 실행 취소·다시 실행 이력을 편집 시작 상태로
  돌린다. 이전에 입력한 다른 변경은 유지하고, 과제 0점과 공란은 구분한다.
  취소한 값은 자동 저장·명시적 저장·화면 이동 후 복구에 다시 반영하지 않는다.
- 숫자가 아니거나 만점을 초과하는 값으로 입력을 마쳐도 이번 입력을 같은
  방식으로 복원한다. `7`을 입력하다 `7x`로 끝냈다는 이유로 중간값 7점을
  저장하지 않는다. 오류를 수정하면 정상 저장할 수 있으며, 과제 공란·미제출·
  통과형 선택의 기존 의미는 유지한다.
- 자동 저장과 `Ctrl+S` 요청에는 화면이 읽은 과제 만점을 함께 보내지만,
  최종 정본과 초과 점수 검증은 서버가 소유한다.
- 미입력 `-`, 미제출, 미배정, 검수 대기 상태를 0점과 혼동하지 않는다.
- 점수 저장 실패 시 입력값과 복구 초안을 유지하고 사용자가 다시 시도할 수
  있게 한다. 저장 응답을 기다리며 새 숫자를 작성하면 그 입력은 확정 전까지
  저장하지 않는다. 이때 **저장하고 잠금**은 입력을 마친 뒤 재시도하도록
  안내하며 수정 모드와 초안을 유지한다.
- 완료형 컬럼은 숫자 입력 칸 대신 `미입력·미완료·완료` 선택기를 표시한다.
  선택은 기존 자동 저장·실행 취소·편집 lease 흐름에 포함되고, 서버가 반환한
  `passed`와 클리닉 판정을 다시 읽는다.

## 학생 상세에서 바로 수정

- 학생 상세 과제 탭은 점수가 생긴 과제만 나열하지 않고 이 학생에게 배정된
  운영 과제를 기준으로 표시한다. 따라서 검사 전 과제도 행이 유지된다. 서버의
  `meta_status=NOT_SUBMITTED`는 **미제출**, 점수·미제출 기록이 모두 없는 상태는
  **검사 전**으로 표시하며 둘을 `0점`이나 빈 목록으로 바꾸지 않는다.
- 각 행은 채점 방식을 `숫자 채점` 또는 `완료 체크`로 함께 보여 준다. 상단
  요약은 완료 수와 미제출 수를 분리하고, 완료형에 `0/1`을 노출하지 않는다.
- **학생 목록 → 학생 상세 → 과제**에서 각 과제의 `바로 수정`을 누르면 현재
  화면 안에 작은 편집 패널이 열린다. 차시 화면으로 이동하지 않는다.
- 완료형은 `미완료/완료` 두 버튼을 누르는 즉시 저장한다. 숫자형은 점수를
  직접 입력하거나 `전부 완료`로 과제 만점을 저장한다. 숫자형의 완료 여부는
  임의 토글이 아니라 저장 점수와 서버 합격 기준으로 다시 계산한다.
- 저장 중에는 중복 입력을 막고, 잠긴 결과 또는 다른 성적표 편집 lease가 있으면
  원인을 표시하며 기존 값을 유지한다. 성공 후 학생별 성적을 재조회해 배지와
  점수, 클리닉 판정을 함께 갱신한다.
- 편집 패널은 키보드로 조작할 수 있고 `Escape`로 패널만 닫는다. 사이드바나
  모바일 화면 때문에 과제 목록 컨테이너가 좁아지면 제목 아래에 점수·상태·
  `바로 수정` 동작을 온전히 배치하고, 편집기의 입력과 동작 버튼은 세로로
  배치해 가로 넘침이나 잘림을 만들지 않는다. 열림 전환은 짧은 이동·투명도
  피드백만 사용하고 `prefers-reduced-motion`에서 제거한다.
- 생성·설정 모달은 낮은 노트북 화면과 390px 모바일에서 본문만 스크롤되고,
  제목·닫기·주요 제출 동작은 계속 접근 가능해야 한다. 페이지 축소는 정상 사용
  방법으로 요구하지 않는다.

학생 상세 과제 탭은 기본적으로 **최근 차시순**으로 표시해 1차시가 목록 아래에
오도록 한다. `수업(정규·보강)`, `상태(확인 필요·완료)`, `정렬(최근 차시·
1차시부터·최근 수정)` 필터를 제공하며 결과 수를 함께 보여 준다. 같은 차시의
여러 과제는 과제 표시 순서를 유지한다. 필터는 조회 범위나 저장 권한을 넓히지
않고 현재 tenant·학생 응답 안에서만 작동한다.

## 워크북 원본과 문항 채점표

- 과제 **자산**의 **워크북 자료 올리기**는 문제+해설 한 파일, 문제 파일 하나,
  문제 PDF/이미지와 해설 HWP/HWPX 두 파일을 같은 모달에서 받는다.
- HWP/HWPX는 미주 번호를 짝짓기 기준으로 쓰며 선생님 필기 해설 원본 이미지를
  보존한다. 검수 화면에서는 문제 영역 높이와 번호·수록 여부를 교직원이 확정한다.
- 원본이 준비되면 과제 **결과**에 학생×문항 채점 장부가 열린다. 셀은 `—`, `O`,
  `X · 수록`, `O · 복습`이며 변경 즉시 서버 응답으로 장부를 다시 맞춘다.
- X는 오답노트에 포함한다. 다시 맞혔지만 계속 복습시킬 문항은 O·복습으로
  바꾸고, 완전히 제외할 때만 O로 바꾼다.
- 소유 구현은 `HomeworkAssetsPanel.tsx`, `HomeworkQuestionLedger.tsx`,
  `api/adminHomework.ts`다.

## 제출관리 파일별 검수

- **과제 → 제출관리**는 제출 행 건수를 평면 목록으로 보여 주지 않고 학생 제출
  묶음 안에 ordered 사진·동영상 파일을 펼친다. 상단에서 제출 학생, 활성 전체 파일,
  검수 가능, 업로드 오류 수를 분리해 선생님이 확인 우선순위를 바로 판단한다.
- 관리자 제출관리와 선생님 모바일 상세는 같은 조회 함수를 사용해 200건씩 마지막
  페이지까지 읽고 전체 결과가 확인된 뒤 표시한다. 조회 동안 로그인 세대와 학원
  범위를 고정한다. 중간 페이지 실패·개수 변경·중복·응답 누락은 오류로 표시하며
  재시도하면 첫 페이지부터 다시 조회한다. 일부 결과를 빈 목록이나 완료된 전체
  목록으로 바꾸지 않는다. 서버의 기존 배열 응답은 순차 배포 호환으로 지원한다.
- 각 파일은 순서, 사진/동영상 종류, 안전한 원본 표시명, 용량, `저장 중·검수 가능·
  업로드 실패·교체됨` 상태와 서버 오류를 독립적으로 표시한다. 실패·저장 중·교체된
  파일의 미리보기 버튼은 비활성화한다.
- `미리보기`는 bucket key를 브라우저에 전달하거나 공용 storage inventory에 다시
  제출하지 않는다. 파일 opaque id를 과제 media preview API에 보내고 같은 tenant·
  교직원 권한을 통과한 짧은 서명 URL만 image/video viewer에 사용한다. 조회 실패는
  닫기 가능한 모달 안에서 재시도하며 목록을 빈 상태로 바꾸지 않는다.
- 관리자 PC에서도 학생별 `확인 대기·확인 완료`와 전체 건수를 표시한다. 업로드된
  파일을 모두 실제로 연 뒤에만 `직접 확인 완료`를 누를 수 있다. 이미지·동영상은 로드
  완료 시 확인한 것으로 센다. 기존 제출에서 PDF MIME이 반환되면 짧은 서명 URL을
  새 창으로 열고 교직원이 `열람 확인`을 눌러 확인 대상으로 센다. 신규 PDF 업로드는
  현재 학생 과제 제출 형식에 포함되지 않는다.
  실패·저장 중·교체된 파일은 확인 대상으로 세지 않고 각각 상태와 오류를 보여 준다.
- 저장 전 최신 제출 파일과 차시 성적을 다시 읽는다. 파일 구성이나 판정 시각이
  바뀌었으면 재확인하게 하고, 0점을 포함해 이미 점수 시도가 있는 제출은 성적
  화면에서 관리한다. 정상 확인·취소는 직원 권한의
  `PATCH /results/admin/sessions/:sessionId/score-correction/`에 수강생·과제·
  `expected_updated_at`을 보내며 점수와 제출 원본을 바꾸지 않는다. 서버는 tenant,
  차시, 과제 배정, 동시 수정을 확인한다. 저장 후 제출·성적을 재조회하고 새로고침
  후에도 상태를 유지한다. 완료 상태는 학생의 파일 교체를 잠근다.
- 열람 기록과 미리보기 캐시는 제출 파일 묶음의 `media_set_fingerprint`에 묶는다.
  파일 구성이 바뀌면 같은 파일 ID라도 주소를 다시 조회하고 열람을 다시 확인한다.
  완료 요청은 `expected_media_set_fingerprint`도 보내므로 마지막 조회 이후 파일이
  바뀌어도 서버가 저장하지 않고 409로 돌려준다. 최신 목록을 다시 열어 확인한 뒤
  재시도하며, 취소와 종이 과제의 기존 성적 화면 판정 계약은 유지한다.
- 주소 발급 성공 뒤 이미지·동영상 로드가 실패해도 열람 성공으로 세지 않는다.
  미리보기 안에 오류와 주소 재발급·재시도를 제공하며, 실패한 옛 파일을 표시하지 않는다.
- 학생의 파일 선택·제출 내역, 관리자 PC, 선생님 모바일에서 HEIC/HEIF 사진은
  기존 `heic2any`를 필요할 때만 불러와 브라우저 안에서 JPEG 미리보기로 변환한다.
  MIME 또는 대소문자 구분 없는 확장자로 판별하며, 변환 중에는 준비 상태를 표시한다.
  원본 업로드·파일명·지문·권한 API는 그대로 유지하므로 이미 제출한 HEIC도 별도
  재제출이나 데이터 이전 없이 열린다. 서명 URL의 원본을 자격정보 없이 읽고,
  변환 결과는 서버나 외부 서비스에 전송하지 않는다.
  여러 사진은 순차 변환하며 화면을 닫거나 파일을 바꾸면 대기 작업을 취소하고
  생성한 임시 URL을 해제한다. 실제 이미지 로드가 끝나야 열람으로 센다.
  다운로드·변환·이미지/영상 디코딩 실패는 PC와 모바일 모두 오류와 재시도를
  제공한다. 원본과 성공한 제출은 보존하고, 실패를 검수 완료로 간주하지 않는다.
  합성 HEIC 파일의 선택→업로드→reload, 기존 제출 열기, 변환 실패→복구→검수
  저장→reload는 학생·관리자·선생님 과제 회귀 테스트에서 검증한다.
- 제출/성적 조회 실패, 파일 미리보기 실패, 409 동시 수정은 기존 상태를 성공처럼
  표시하지 않는다. 오류를 보여 주고 최신 상태 확인·파일 재열기·저장 재시도 경로를
  제공한다. 확인 전에는 명시적 확인 대화상자를 거치고 진행 중 중복 저장을 막는다.
- 학생별 카드와 파일 행은 데스크톱에서 빠르게 훑을 수 있는 밀도를 유지하고,
  390px에서는 학생 메타와 파일 동작을 줄바꿈해 문서 가로 스크롤을 만들지 않는다.
  학생 제출 대상도 모바일에서 상태·과제명·수업명을 별도 행에 표시하여 제출 후
  길어진 상태 표시가 과제명을 가리지 않으며, 같은 대상을 다시 열 수 있다.
- 소유 구현은 `HomeworkSubmissionsPanel.tsx`, `HomeworkMediaPreviewModal.tsx`,
  `adminHomeworkSubmissions.api.ts`다. 집중 회귀는
  `e2e/admin/homework-media-review.mock.spec.ts`가 파일별 상태·오류·권한 미리보기,
  확인·취소·새로고침, 0점 잠금, 409 복구와 데스크톱/390px 레이아웃을 검증한다.
  201번째 제출 파일의 조회·미리보기·새로고침도 PC/390px에서 검증하며,
  `e2e/teacher/homework-manual-review.mock.spec.ts`는 같은 제출의 확인 저장·재조회와
  두 번째 페이지 실패 후 전체 재시도를 확인한다. 서버 페이지·검수 지문 정책은
  [backend 과제 정본](https://github.com/guswls3028-art/academy-backend/blob/main/docs/domain/homework-grading.md)이 소유한다.
  동일 산출물의 격리 `student-parent-homework-realuse.spec.ts`는 실제 제출 이미지로
  PC 확인·reload·390px 취소와 학생 측 파일 잠금/해제를 확인하고, 오래된 파일 지문의
  저장 거절도 검증한다. 기존 모바일 검수·채점·학생/학부모 재접속 검증을 유지한다.

## 소유 구현과 검증

- 설정·생성: `src/app_admin/domains/homework/`
- 차시 과제 카드: `src/app_admin/domains/sessions/components/SessionAssessmentSidePanel.tsx`
- 성적표: `src/app_admin/domains/scores/components/ScoresTable.tsx`
- API 응답 정규화: `src/shared/api/contracts/assessments.ts`
- 학생 상세 목록: `src/app_admin/domains/students/overlays/StudentsDetailOverlay.tsx`,
  `src/shared/api/contracts/studentGrades.ts`
- 회귀 E2E: `e2e/admin/score-entry-autosave.spec.ts`
- 학생 상세 회귀 E2E: `e2e/admin/student-score-trend.spec.ts`
- 과제 제출 검수 E2E: `e2e/admin/homework-media-review.mock.spec.ts`
- 격리 개발 release의 `e2e/student/student-parent-homework-realuse.spec.ts`는 합성 조교를
  생성하고 `/core/me/`의 `tenantRole=staff`를 확인한다. 신규 계정 안내는 실제 확인 버튼으로
  완료하고 `/core/me/`의 안내 필요 상태가 해제됐는지 다시 확인한다. 본문이 안내 모달 뒤에서
  DOM-visible인 상태를 상호작용 가능 상태로 간주하지 않는다. 조교 모바일 상세를 먼저 연 뒤
  학생이 제출한 HEIC의 자동 발견·실제 미리보기·reload·PC/390px 표시를 검증하고,
  학부모의 PNG 추가 제출도 확인한다. HEIC의 저장소 읽기는 exact 개발 테넌트의
  등록된 서명 URL·MIME·실제 바이트·CORS만 허용하며 인증 헤더를 전달하지 않는다.
  이어서 실제 조교 로그인으로 차시 성적표를 열고390px에서91점, PC에서92점을 입력·저장한 뒤
  reload와 학생·학부모 성적 반영을 확인한다. 이 추가 경로는 공식 격리 실행과 cleanup0을
  통과한 release에서만 실사용 완료 증거가 된다. 소스 추가만으로 운영 검증을 대체하지 않는다.
  직원 삭제 뒤 남는 합성 User/token/audit는 exact `qa-*` tenant teardown의 cleanup0이 소유한다.
